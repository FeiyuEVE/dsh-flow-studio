# 设计任务书：DSH 流程编排工作室（Flow Studio）

> 这份文件是所有设计 agent 的唯一输入。读完再动手，不要臆测产品形态。

## 1. 这是什么

DeepSeek Harness（下称 DSH）的一个 Web 插件。它给「把一个研发任务交给一组 agent 去做」这件事提供**可视化编排 + 过程监督**：

- 把 需求分析 → 方案设计 → 结构设计 → 开发 → 测试 → 代码审查 画成一张图；
- 每个节点就是一个 agent 角色，可以配「它是什么人」「它负责什么」「挂哪些 skill」「用哪个模型」；
- 节点可以是**单个 agent**，也可以是**主管 agent + N 个子 agent**（主管拆活、汇总，子 agent 并行干活）；
- 节点之间除了正常流转，还有**打回**：方案被打回 → 回到需求分析；测试打回 → 回到开发。打回构成循环；
- 任务跑起来之后，要在图上看到「现在在哪、谁在干、卡在哪、被打回几次、花了多少 token、审查发现了多少缺陷、提的意见被采纳了多少」。

当前已经有一版功能骨架（能画、能存、能配角色），但**界面很简陋**，现在要重做设计。

## 2. 硬约束（设计必须落在这个框里）

| 约束 | 说明 |
|---|---|
| 技术栈 | 浏览器里跑 React（由宿主提供）。v0.5 起画布改用 **@xyflow/react（React Flow 12）** 并打进单文件；其余 UI 仍手写 CSS，不引入 tailwind / 图标字体。 |
| 主题 | 只能用宿主的 CSS 变量：`--dsw-alias-*`（bg-base / bg-layer-1..3 / border-l1..l4 / label-primary|secondary|tertiary / brand-primary / state-success|warn|error-primary / interactive-bg-hover）、`--dsw-radius-*`、`--dsw-font-family`、`--dsw-focus-ring-*`。**亮/暗主题由宿主切换，设计必须两边都成立。** |
| 语言 | 中文界面。术语要贴中文研发团队的说法，不要生硬翻译。 |
| 体量 | 客户端产物是单文件；v0.5 起构建上限 524288 字节（React Flow 12 打进产物，实测宿主可下发 >400 KB）。设计仍要经得起「不重造轮子」的复杂度。 |
| 宿主外壳 | 它占满中间主区域（不是弹窗、不是侧边抽屉）。上方是侧栏与会话列表，本面板是其中一页。没有 keep-alive，切走即卸载。 |
| 数据规模 | 典型流程 6–12 个节点；极端 30 个节点。要能一屏看清主干。 |

## 3. 要解决的设计问题（按难度排序）

1. **打回循环怎么画得不乱。** 六阶段主干向右，四处打回向左上方回绕。如果只是画一条回头线，很快就糊成一团。需要考虑：分道（打回线走下方专用航道）、弯曲半径、重叠避让、标签位置、多轮回退的视觉。
2. **「主管 + 子 agent」怎么在图上表达。** 一个节点内部有 1 个主管 + N 个子 agent。是默认折叠成一个卡片、点开变成一个子图？还是直接在卡片上列出成员？运行时要能看到哪个子 agent 在跑。
3. **运行态叠加在设计态之上。** 同一张图，设计时看结构，运行时看进度。不能让运行态把结构信息淹没，也不能为了运行态重画一套。
4. **指标看板放在哪。** token 消耗、skill 采纳率、审查缺陷数、意见采纳率、任务完成度——这些是「跑完之后要看」的，不适合常驻在画布上。但也不该藏进另一个二级页面。
5. **信息密度。** 一个节点卡片上要放：标题、执行方式、角色摘要、skill 数、打回数、运行状态、耗时、token。全放会糊，全不放就得点开才知道。需要明确的信息层级。
6. **编辑手感。** 拖拽、从端口拉线、框选、缩放平移、对齐吸附、自动整理（tidy up）、撤销。哪些该有，哪些是负担。

## 4. 必须给出的交付物

每个设计 agent 输出一份 Markdown，落到 `dsh-flow-studio/docs/design/<你的文件名>.md`，内容必须包含：

1. **设计结论**：3–8 条，每条一句话，写清「做什么 + 为什么」。
2. **布局与尺寸**：给具体数值（px）。栅格、栏宽、卡片尺寸、间距刻度、圆角、字号行高。
3. **组件规格**：节点卡片（各状态）、连线（各类型/状态）、检查器、工具栏、状态栏、指标块——每个给「结构 + 尺寸 + 各状态样式 + 交互」。
4. **状态与流转的可视化规则**：待执行 / 运行中 / 通过 / 被打回 / 失败 / 跳过，各自的视觉；打回轮次怎么显示。
5. **交互规则**：画布上的鼠标/键盘操作清单（触发条件 → 结果），包括空状态、错误态、悬停态。
6. **反例**：明确写出你不建议做的 3–5 件事，附理由。
7. **参考出处**：你看过的产品/文章，给 URL，并写清「抄了它的哪一点」。

不要写「建议使用 XX 库」，就写视觉与交互本身。

## 5. 参考资料（自己去查，别只信这份清单）

- **n8n**：节点画布、执行态描边、执行路径高亮、运行日志抽屉

- **ComfyUI**：端口类型着色、节点折叠
- **AutoGen Studio / Microsoft AutoGen**：一组 agent 用「团队卡片 + 成员列表」表达
- **DSH 自己的 Agent Teams**：lead agent + teammates、任务板
- **GitHub Actions / Argo / Kestra**：DAG 的调度视图（不要照抄，它们的节点是任务不是 agent）

也可以参考 Figma / tldraw / Excalidraw 的画布交互（吸附、框选、对齐、小地图）。

## 6. 已经定下的产品决策（不要推翻，可以质疑并说明理由）

- 单页面板，三栏：左侧流程模板列表、中间画布、右侧检查器（选中节点/连线时才出现内容）。
- 节点类型只有三种：开始、阶段、结束。阶段节点才有角色/任务/skill/主从配置。
- 连线只有两种：正常流转、打回。打回目标必须是上游。
- 一句话能说清的操作不做成菜单：双击空白新建节点、从右侧端口拖线、Delete 删除选中、滚轮缩放。
