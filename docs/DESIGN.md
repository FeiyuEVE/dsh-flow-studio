## 1. 一句话定位

**它不是工作流编辑器，是把「一次研发交付」摊开在桌面上的作战图。**

大多数编排工具（n8n / Dify / Langflow）的隐含前提是：图是自动化的，人只在出错时介入。
这个产品的前提相反 —— **每个节点是一个 agent 在替你干活，你既要能配它，也要能盯它，还要能在它跑偏时把它打回去。**

这个前提推到三个设计后果，整份方案都建立在它们上面：

1. **打回不是错误分支，是主流程的一部分。** 一个只会往前走的流水线是假的；真实交付里"方案被否 → 回到需求"是常态。所以打回必须在图上占一个**常设位置**（下方航道），而不是一条偶尔出现的红色虚线。
2. **主从关系是节点内部的事，不是图的拓扑。** 主管不是第 N 个节点 —— 它是那个"收口的人"。把它画成节点会逼出一圈星型委派线，看的人会误解成数据流。
3. **设计态与运行态是同一张图的两层。** 结构（位置/形状/连线）在执行期间冻结，状态（颜色/线型/角标/动效）叠上去。用户的空间记忆不能因为点了个"运行"就被清空。

## 2. 参考了什么，拒绝了什么

调研覆盖 11 个编排产品 + DSH 自己的 Agent Teams + 三个 DSH 社区插件（完整出处见各分册末节）。**只抄机制，不抄皮肤** —— 这个产品的配色与字体完全由宿主 token 决定，所以任何产品的视觉风格都搬不过来。

真正被采纳的八条：

| 抄的 | 从哪来 | 为什么 |
|---|---|---|
| 卡片三层信息 + 参数全部外置 | Dify（`NODE_WIDTH=240`）、Flowise | 卡片是"是什么 + 一行摘要 + 状态"，不是表单。表单进检查器 |
| 执行态三重编码：边框 + 角标 + 连线 | n8n（绿勾节点 + 绿色已执行线 + 未走分支变灰）、Coze（绿框） | 只靠颜色，缩到 50% 就全糊了 |
| 同类端口同色、非法连接当场拒绝并给原因 | ComfyUI / Langflow | 把类型错误从"运行时崩"提前到"连不上" |
| 循环用容器/跳回，而不是画布回边 | Dify Loop 容器、Flowise「Loop Back To」 | 回边一多必然穿节点；这是我们换成正交航道的直接依据 |
| 双击空白新建、裸滚轮以指针为锚缩放（Ctrl/Cmd+滚轮与 pinch 同义）、框选、吸附（Alt 绕过）、fit | Figma / tldraw / n8n | 画布类产品的用户肌肉记忆，不学就是反直觉；滚轮缩放是任务书 §6 已定的硬决策 |
| 主管信息铺成一条横带，不占卡片 | dsh-graph（顶部 Supervisor 横幅）、dsh-agent-team-gui（Run Center 运行头） | 主管是 run 的所有者与收口者，不是并行执行体 |
| 指标用「数字为主、细条为辅」 | Dify 变量检查器、Grafana stat panel | 空间小的时候，趋势条是装饰，数字才是信息 |
| WCAG 2.2 拖拽单指针替代 | `ui-ux-pro-max` 的 Dragging Movements 规则 | 拖动不能是唯一路径 —— 因此必须另有右键菜单与键盘微移 |

明确**拒绝**的三条：

- **不做内嵌子画布**（ComfyUI 的 subgraph 那种双击进入）。单文件 262KB 的体量养不起第二套画布上下文，而且同屏看得见主干比进得去子图更重要。主从关系改用「折叠卡 + 成员点行 + 检查器编辑」。
- **不做顶部 Tab 切「设计 / 运行 / 指标」**。切走就看不到图，而"运行时要在图上看进度"是本产品的核心诉求（见 §1 第 3 条）。指标走底部可折叠抽屉。
- **不做力导向自动布局**。分层布局（按最长路径分列）才是研发流水线该有的形状；力导向会让"开发在测试左边"这种语义消失。

## 3. 视觉方向

一句话：**用宿主的分层语言做一张安静的作战图，全部注意力预算花在「现在卡在哪」。**

- **零自设颜色，没有例外。** 每个语义都指向 `--dsw-alias-*`；需要中间色时只允许两种混法 —— 与 `label-primary` 混（主题自适应加深/提亮）或与 `transparent` 混（tint/光晕）。**禁止与白/黑混**，暗色下会直接失效。主从卡里区分不同子 agent **不靠色相**（宿主没有 categorical 色板）：用「形状 + 首字 + 同一蓝色系的深浅梯度」，见 [02 §4.4](design/02-visual-system.md)。
- **亮色主题有一个坑，必须记住**：`bg-layer-1` 与 `bg-base` 在亮色下**都是纯白**。所以节点卡不能靠填充色浮起来 —— 画布必须整体压暗一档（与 `label-primary` 混 3.5%），节点靠 1.5px 描边立住。这是全套设计里唯一需要主题分支的地方。
- **「品牌蓝」不是 `brand-primary`。** 宿主里 `brand-primary` 是中性色（亮 `#0f1115` 近黑 / 暗 `#f9fafb` 近白），服务于主按钮；真正的蓝是 `state-business-primary`。**选中用中性色（与宿主一致），运行用蓝色** —— 这条纪律贯穿全部界面。
- **状态色必须做双主题自适应混色，而且要分图形档与文字档。** 成功绿 `#22c55e` 对白底只有 2.28:1、警告琥珀 2.15:1，原色不达标。混 `label-primary` 后：**图形档 70%** → 3.94 / 4.14:1（过图形 3:1 门槛）；**文字档 62%** → 4.72 / 4.95:1（过文字 4.5:1 门槛）。同屏里线用 70%、12px 文字用 62%，两套主题都合法，不需要主题分支。
- **字号地板 12px，画布文字随缩放隐藏而不是缩小。** 低于 12px 的中文笔画会糊，且各浏览器渲染不一致；LOD 三档只认一套阈值：**≥60% 完整档**（内容全渲染）、**45%–60% 紧凑档**（标题 + 状态角标 + ↺n）、**<45% 精简档**（轮廓 + 状态形状 + 打回线正交/虚线形态 + 可聚焦的无障碍名称，颜色只作加速线索，色点不算双编码）。低缩放是"看结构"，不是"读字"。
- **层级预算写死**：同屏强强调（光晕/脉冲/≥2.5px 描边）≤2 处；画布字号 ≤4 档；投影 0 种。运行态再热闹也不能盖过结构。

## 4. 布局

```
┌──────────────────────────────────────────────────────────────┐
│ 顶栏 48  [流程名] [统计]        [⊕][↺][↻][整理][全览][校验●][运行] │
├──────────┬────────────────────────────────────┬──────────────┤
│ 左栏 240 │              画布                   │  检查器 320  │
│ 流程模板  │  ┌────┐   ┌────┐   ┌────┐         │  选中才有内容 │
│ · 列表    │  │需求│──▶│方案│──▶│结构│──▶      │              │
│ · 折叠44  │  └────┘   └────┘   └────┘         │  标题/角色    │
│          │      ↖──────┘ ↑                   │  执行方式     │
│          │   ┌──────────────────────────┐    │  任务/产物    │
│          │   │  打回航道（正交折线）      │    │  skill/模型   │
│          │   └──────────────────────────┘    │  打回上限     │
├──────────┴────────────────────────────────────┴──────────────┤
│ 状态栏 28   7 节点 · 11 连线 · 4 条打回      ✓ 结构完整  ⌃指标 │
└──────────────────────────────────────────────────────────────┘
```

三条硬规则：

1. **检查器常驻，不做浮层。** "选中即配置"是编辑期最高频的回路，浮层会让画布抖动。
2. **小屏（<1100px）左栏收成 44px 图标条，检查器变覆盖抽屉**（点画布空白或 Esc 收起，不铺遮罩）。
3. **「全览」是独立动作，不是「适配」的附属。** 1440×900 下三栏常驻时画布只有 880px，8 列主干（世界宽 2028 = 7×260+208）fit 后仅 **38.7%**（地图模式/精简档）；「全览」临时收起左右两栏把画布拉到 1396px、fit **64.1%**（完整档临界，标题实渲染 ≈9px）——要逐字读标题需再放大到 ≥70%，此时不再承诺全纳。Esc 恢复。

## 5. 三个核心语义

### 5.1 打回走下方航道

打回线**正交折线**，从节点底缘出、下降进入主干下方的专用航道（第一航道 = 主干底缘 +24，六条满配总净空 196 = 24 + 28×5 + 32）、再上升进目标节点底缘。它与正常流转的贝塞尔软线形成**软 / 硬**两种几何语言 —— 不靠颜色也能区分。

- 航道从主干底 +24 起、间距 28、最多 6 条；打回端口每节点每侧 **6 槽**（外侧 ±8/24/40/56/72/88，内侧镜像）。超过 6 条时**确定性降级**：并入最外航道、双线 1px、丢标签、末端 `+N` 汇总角标（03 §2.2）。
- 避让是确定性算法：按「目标列升序、同目标源列降序、同列并列按节点序→id 字序」从深到浅分配航道；只保证「同一输入同一输出、冲突可枚举」，**不承诺任意手排零碰撞**；确实交叉的地方用 12×6 的桥拱抬一下。
- 打回线**双态**：虚 = 潜在路径，实 = 这次真的触发了。轮次不靠多条线表示，靠节点角标 `↺n` + 线上刻度。
- 标签 ≤16 字常驻，完整触发条件去检查器看。

为什么要航道而不是弧线：现版直接把一条贝塞尔往左下兜，4 条打回就会穿过节点、标签打架。**正交航道的好处是它占的是一块稳定的空间**，而不是一条随内容变化的曲线。

### 5.2 主从不进拓扑

`mode === 'team'` 的节点仍是一个卡片，只是高 96 → 116，多出 20px 的成员点行：主管是 16×16 方 chip 写「主」，子 agent 是 Ø16 圆点内嵌首字，最多 5 个 + 「+n」。圆点之间不连线（并行是默认语义），左端一个 `⋈` 分叉符表示"从这里分发"。

编辑成员去检查器；双击卡片就地半展开成 26px 的成员泳道（不换视图、不新开画布）。

运行时要能分出三个阶段：**主管在拆任务 / 子 agent 在干 / 主管在汇总**。用三个通道同时表达 —— 左缘 3px 竖条、脉冲出现的位置（主 chip 还是成员点）、状态行文字。

**出厂模板**：六个阶段节点默认就是 `mode === 'team'` 的「主管 + 3 个子 agent」——
需求分析 = 业务拆解 / 验收条目 / 风险与边界，方案设计 = 架构与选型 / 接口契约 / 数据与存储，
结构设计 = 模块划分 / 依赖与构建 / 目录与命名，开发 = 后端实现 / 前端实现 / 自测与用例，
测试 = 用例设计 / 自动化执行 / 回归与缺陷，代码审查 = 规范与风格 / 安全与边界 / 可维护性。
**设计理由**：多角色并行、按视角分工是这个产品的产品主张 —— 真实研发链本来就由不同关注点的人各管一段，
把它画成一个「什么都干的 agent」会抹掉这套语义；**单 agent 仍然是一等选项**，在检查器里把执行方式改回
single 即可（代价更低，但一个节点只能有一个视角）。team 的成本见 README：每个节点起 1 个主管 + N 个成员会话，
整条链的 token 开销显著高于 single，别把它当成默认免费。

### 5.3 状态叠加，不换皮

| 通道 | 归属 |
|---|---|
| 位置、形状、连线几何 | **结构**（运行期间冻结） |
| 颜色、线宽、光晕、角标、动效、文字 | **运行** |

节点八态（待执行 / 运行中 / 返工中 / 通过 / 被打回 / 失败 / 跳过 / 超限待人工），每个状态至少用**两个非颜色通道**编码（角标图标 + 描边样式 / 线型 / 文字），保证色盲与缩小后仍可读。

## 6. 冲突裁决

四个模块并行设计，出现了 10 处数值冲突。裁决如下（理由见 [02 §0.3](design/02-visual-system.md)）；末尾追加一行是 2026-11-06 本轮复核（M07/M09/M10/M11 文档侧）的口径，代码侧由并行任务处理，验收状态见 [REVIEW 的「复核进展」](design/REVIEW.md)。

| 冲突 | 结果 |
|---|---|
| 卡片尺寸 180×80（01） / 208×96（03） / 220×96（04） | **208×96** —— 03 的航道坐标与成员行几何全建在它上面，改宽会连锁作废 |
| 字号 11/12/13/16（03） vs 12/13/14/16/20（01） | **12px 地板，五档封顶**；03 里所有 9/10/11px 一律上调 |
| 「运行中」的颜色 | **`state-business-primary`**（蓝）；**选中用 `brand-primary`**（中性黑/白）—— 两者必须可区分，否则运行期分不清「我选中了」和「它在跑」 |
| 卡片描边 1px `border-l2`（04） vs 1.5px `border-l3`（03） | **1.5px `border-l3`** —— 亮色下 l2 只有 10% 黑，208px 宽的卡边界立不住 |
| 状态是否换卡片填充层 | **不换**，恒 `bg-layer-1` + ≤8% tint —— 亮色下 layer-1/2 都是纯白，换层零收益 |
| 圆角 6px（01） | **8px = `--dsw-radius-sm`** —— 6px 不在宿主档位里 |
| 网格 20px 点阵（01） vs 4px（03） | **两层并存**：视觉点阵 20px，逻辑吸附 4px |
| 状态模型 八态（03） vs 六态（04） | **八态为准**，六态是它的投影 |
| 运行按钮在校验不过时 | **不灰置**，点击后跳到问题列表第一条并定位到节点（比灰按钮多给一步出口）；执行引擎已接入，点击直接走启动门禁（非法流程 400） |
| 状态色混色配比 | 图形 70%、文字 62%（原文档只给了 70% 并误用于小号文字，实测 3.94/4.14 < 文字门槛 4.5） |
| 主从卡高度 | **默认 96；有成员时 116**（多出 20px 放成员点行，向下长、中心线不变）；144 的「展开」变体**本版不做** |
| 成员计数语义 | 「主从 N」里的 N **只算子 agent，不含主管**；主管单独一个方 chip |
| 运行期展开 | **不移结构**：成员逐项状态只体现在成员点双环与检查器里，不展开行、不下移航道 |
| 成员身份识别 | **不用色相**（宿主无 categorical 色板，自设色违反 token 约束）；用「形状 + 首字 + 同色系深浅梯度」，见 02 §4.4 |
| 画布底 | 亮色 `color-mix(bg-base 96.5%, label-primary)`，暗色 `bg-base`；节点恒 `bg-layer-1` |
| 指标看板位置 | **画布底部可折叠抽屉**（40 / 200px），否决顶部 Tab |
| **本轮复核：输入协议 / LOD / 全览数学 / 航道槽位（M09、M11、M07、M10 文档侧）** | **统一为**：① 输入只有一张表（01 §5.1 #7/#8/#12）——裸滚轮=以指针为中心缩放、`Shift`+滚轮=横向平移、`Ctrl`/`Cmd`+滚轮与 pinch=缩放（阻止浏览器页面缩放）、中键/空格+拖=平移、`Alt`+拖=绕过 4px 吸附；② LOD ≥60% 完整 / 45–60% 紧凑 / <45% 精简，精简档保留状态形状 + 方向/连线形态 + 可聚焦无障碍名称；③ 世界边界由节点矩形求得（宽 208、高 96/116、列距 260），边距 48 **屏幕 px**，`fit = min((视口宽−96)/boundsW, (视口高−96)/boundsH)`，8 列主干宽 **2028**，缩放地板 **15%**；④ 打回槽位每节点每侧 **6** 个（外侧 ±8/24/40/56/72/88），>6 条确定性降级（并入最外航道、双线 1px、丢标签、末端 `+N`），同列 tie-break 按节点序→id 字序。**旧值（Ctrl 缩放 / 裸滚轮纵移 / Ctrl 绕过吸附、50–69% 紧凑与 <50% 全隐、1852 / 1940、4 槽、±10/±20 扇出）一律作废。** |
| **本轮复核：回退计数的归属（C11）** | 分三个**互不替代**的口径，各标在各处：**① 边触发数** = 这条打回边被触发的次数（`attemptId` 去重后累加）→ 标在**线上**（`×n` 小刻度）；**② 目标返工数** = 目标节点因被它自己收到/发出的打回而重跑的次数 → 标在**目标节点的 `↺n` 角标**；**③ 源发起数** = 源节点发起打回的总次数 → 只进检查器与底部抽屉，不标在节点卡上（避免和 ② 抢同一个位置）。三者都由 run 契约（04 §3.13）的 `attemptId` 派生，都不含「预置的潜在路径」。旧稿「目标累计返工 + 线上刻度」与「源头标数 + 不在线上标数字」的冲突按本条作废。 |
| **本轮复核：检查器常驻（C09）** | 检查器**常驻**（宽度固定 320，可拖到 240），空选中时显示流程级设置，**不是**滑入/隐藏——画布宽度不随选中变化，避免空间记忆漂移（02 §2.2 旧「无选中不显示」作废）。 |
| **本轮复核：运行中锁结构（C12）** | 运行/返工中**锁结构**：双击空白新建、拖节点、改边一律禁用（显示原因），只有「停止运行」后恢复；设计态 04 的「双击空白不受运行态影响」作废，覆盖全部编辑入口。 |
| **本轮复核：抽屉 40px 内容（C13）** | 收起条 40px 内**只放一行主摘要**（主值 = 验收条目通过率；左侧状态点、右侧结论 pill），其余五项在展开 200px 的明细里；04 的「40 只是把手 + 另 48 摘要」作废。 |
| **本轮复核：脉冲预算（C14）** | 同时脉冲的节点**最多 2 个**（按「返工中 > 运行中 > 子 agent 完成」优先级取前 2）；其余在跑节点用**静态双环**（不脉冲），并保留 `prefers-reduced-motion` 全关。多成员并行不再各自脉冲。 |
| **本轮复核：数字胶囊（C16）** | 数字胶囊高度统一 **18px**（02 §2.2 的 20 作废），字号 `--dsw-font-xxs-12`、`tabular-nums`。 |

## 7. 运行态与指标（形状；0.3.0 起逐步落地）

- 节点卡上**最多 2 个自由数字**（耗时 + 一个更紧急的：回环轮次或缺陷数）+ 1 个 skill 徽标 + 1 条 3px token 构成条。再多一律进检查器或抽屉。
- 底部抽屉收起 40px 是一行摘要条（完成度 / 返工 / 缺陷 / token / 耗时 / 结论），展开 200px 是分阶段明细。运行中自动展开，结束后停留 2 秒展示结论。
- 1Hz 节流刷新，数字用 `tabular-nums` 避免横向抖动；`prefers-reduced-motion` 关掉全部流动动画。
- 复盘先看三个数：**完成度 → P0 缺陷 + 意见采纳率 → 总 token 与耗时**；一句话结论由确定性规则生成（返工 ≤1 且 P0=0 且采纳率 ≥60% 且测试 100% → 优）。

### 8.1 v0.7 的三条对外变化

| 变化 | 用户可见结果 | 契约位置 |
|---|---|---|
| 节点可换外部 executor | 检查器里每个阶段节点可选 `dsh` / `codex` / `custom`；`codex` 起 `codex exec --json` 外部进程，`custom` 跑 `sh -c` 模板。外部 executor 只允许「单个 agent」，非法配置**能保存、不能开跑** | 07 §6 / 06 §17；`src/executor.js`、`src/engine.js` `_runExternalNode()` |
| 节点会话是顶层会话 | 每个节点的主管会话能在会话列表看到、点开接管；它不是子 agent 会话，`dispose()` 不删日志。判据看 session header，不看 `roots()` | 07 §3 / 06 §16.2.1；`src/engine.js` `_createNodeSession()` |
| 运行按工作区分组、并发不设上限 | run 记录按 `workspacePath` 分组；同一工作区可以同时跑多个 run，唯一冲突是同一个 `runId` 已在跑；`GET /runs?workspaceId=` 可过滤 | 07 §4 / §5；`src/runtime.js`、`src/client/flowlist.js` `groupRunsByWorkspace()` |

内建 supervision（`flow_start` 默认开启、HTTP 起的 run 默认关闭）是 v0.7 的第四条对外能力，
入口与字段见 07 §7 / 06 §18。

### 8.2 v0.8 的节点闹钟

每个节点主管会话在 `agents.create` 成功后自动登记一个自审闹钟（默认 600s / 10 分钟，可用 `FLOW_STUDIO_NODE_ALARM_MS` 覆盖）；到点按会话状态走
`inject` / `followup` / 冷会话 `resume`，要求节点用 `node/status` 回报
`state / progress / summary / members / blockers / verdict`。`state=done` + 合法 `verdict` 与
`whenIdle` 竞速、可提前完成（`node/end.extra.completedBy='self-check'`）；`blocked` 且进度不变由
`flow_watch` 在 `recommended` 里给建议。闹钟状态只在内存、进程重启不恢复；外部 executor
节点没有会话，不挂闹钟。Host 在 `run.json.nodeStatus` / `live.nodeStatus` / `GET /runs`
三处下发，客户端在运行详情「节点状态」区块只读展示（标题 / 状态 / 进度 / 成员 / 阻塞）。
契约见 07 §11 / 06 §19。

## 9. 验收口径

1. 亮暗两套主题下，画布底与节点底都能分出层次（亮色下这一条最容易翻车）。
2. 任意状态下，缩放到 60%（完整档下限）并在灰度截图里，仍能只靠「状态角标形状 + 打回线正交/虚线形态 + 箭头方向」认出「哪一步被打回了」；颜色只能加速识别，不能是唯一线索。
3. 出厂模板的 4 条打回线，交叉数 ≤1（03 的航道算法已验证）。
4. 全屏 1440×900 下，点一次「全览」能看到 8 列主干全部（fit 64.1%，完整档）；标题在 ≈9px 的临界档可辨，要逐字读标题需放大到 ≥70%（此时不再承诺全纳）。
5. 画布上不出现任何非 token 颜色、任何 <12px 文字。
6. 键盘可以完成「选中 → 移动 → 删除 → 连线」全流程；单指针不按住拖动也能完成「连接 → 移动」（WCAG 2.2 两条判据分别验收，不互相顶替）。
7. 30 节点串行链在 1396px 视口下 fit ≈16.8%（1300/7748），允许只显示结构；拟合结果低于 15% 地板时固定 15%，并显示「还有 N 列在视野外」与分段/平移导航，不得假装全纳。
