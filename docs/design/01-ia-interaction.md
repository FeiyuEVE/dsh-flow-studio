# 01 · 信息架构与画布交互

> **历史资料（0.14.0 起）**：本文描述旧运行域时代的设计与契约，保留原文不重写；当前实例事件 / 指标 / 证据分别以 [design/10](10-bpmn-instance-api.md)、[design/12](12-instance-metrics.md)、[design/13](13-instance-evidence.md) 为准。

> 模块归属：信息架构 + 画布交互（布局、操作手感、键盘、空态/异常态、设计/运行关系）。
> 节点卡片与连线的静态视觉（各状态配色、打回航道画法、标签版式）归节点/连线模块，本文只定**交互侧规格**并给出三条反推约束（标准卡 208×96 / 列距 260；打回第一航道偏移 24px，六条满配总净空 196px）。
> 所有颜色/圆角/字体一律引用宿主变量 `--dsw-*`，本文只写语义名，不写 hex。

## 1. 设计结论

1. **三栏常驻、宽度不对称**：左栏（流程列表）240px 可折叠到 44px，右栏（检查器）320px，画布吃满剩余。理由：左栏是低频导航（一次会话换 1–3 次流程），右栏承载高频表单回路（选中即配置）。
2. **检查器常驻（320px，可拖到 240px）**：空选中时显示流程级设置，**不做进出动画、不隐藏，画布宽度不随选中变化**（总案 §6 C09）；<1100px 也保持常驻，旧「退化为右侧覆盖抽屉」作废。理由：设计态「点节点→改配置」每分钟发生，浮层会遮挡画布并制造焦点管理成本；宽度随选中跳变会让空间记忆漂移。
3. **设计/运行是一个视图、两种状态**：设计态是底图，运行态是叠加层，运行中锁结构编辑、不锁平移缩放。理由：保住空间记忆（用户刚在哪编辑过，运行时同一位置能找到），也符合单文件产物（v0.5 起上限 512KB）的体量现实。
4. **首次路径压到 2 步**：空态卡预置「六阶段模板」为视觉第一动线，点「用模板创建」即得一张连线齐全的图，再点「运行」。2 步是底线，再压会剥夺用户「确认创建」的决策点。
5. **编辑手感走轻键盘路线**：双击空白建、右端口拉线连、Delete 删、方向键微移、Space/中键平移、**裸滚轮以指针为中心缩放**（`Shift`+滚轮横向平移；`Ctrl`/`Cmd`+滚轮与触控板 pinch 同义；`Alt`+拖动绕过吸附）；右键菜单只收编低频、需要文字标签确认的动作（复制/粘贴/吸附开关/连接到…/移到…）。单字母快捷键默认不用；唯一例外是画布上下文里的 `C`（打开「连接到…」目标列表，见 §5.4），它只在无文本输入焦点且已选中节点时响应。中文 IME 激活时单字母会被吃掉，所以不采用 `Ctrl+L`（浏览器会抢占该组合）。**修饰键口径只有一张表**（§5.1 #7/#8/#12），02、03 一律引用该表，不各自重写。
6. **自动整理用分层布局**（主干按阶段序分列向右、打回统一绕下方航道），不用力导。理由：本产品的拓扑是固定的「DAG 主干 + 反向打回边」，分层是它的自然语言，力导会把主干揉成球。
7. **撤销要做，粒度 = 一次有意义的操作**：一次拖放 = 一步、一个字段失焦提交 = 一步，栈深 50。不做「每个 mousemove 入栈」和「每字符一步」。
8. **校验错误三通道定位**：状态栏计数 → 点开问题列表 → 点单条即平移居中到出错节点并呼吸高亮。错误不许让用户自己找茬。

## 2. 布局与尺寸

### 2.1 总体框架

```
┌──────────────────────────────────────────────────────────────┐
│ 顶栏 48px  流程名+保存状态 │ 撤销 重做 | 整理 校验 ● │ ▶ 运行  │
├────────┬───────────────────────────────────────┬─────────────┤
│ 左栏    │                                       │ 右栏        │
│ 240px   │            画布（弹性）                │ 320px       │
│ (可折叠 │            网格 20px 点阵              │ 检查器      │
│  44px)  │                                       │ (常驻)      │
│         │                       [缩放HUD ↘右下角] │             │
├────────┴───────────────────────────────────────┴─────────────┤
│ 状态栏 28px  节点 8 · 连线 7 · 问题 2 │ 阶段 3/6 · 4m12s      │
└──────────────────────────────────────────────────────────────┘
```

面板总可用 900–1600 × 600–1000px；顶栏+状态栏共吃 76px，画布净高 524–924px。

### 2.2 响应式断点

| 视口宽 | 左栏 | 右栏（检查器） | 形态 | 为什么 |
|---|---|---|---|---|
| ≥1360px | 240px 常驻 | 320px 常驻 | 三栏 | 1600 时画布 ≈1020px：8 列主干（世界宽 2028）fit ≈46%（精简档）、6 列（1508）≈61%（紧凑档），结构可读 |
| 1100–1359px | 200px 常驻（隐藏列表第二行时间戳） | 320px 常驻 | 三栏紧凑 | 画布保住 ≥580px：100% 下约 2 列，fit 到 3 列（728 世界宽）≈66%（紧凑档） |
| <1100px | 44px 图标条（点图标展开为覆盖列） | 320px **常驻**（同上：可拖到 240，不随选中出现/隐藏） | 三栏（窄画布） | 900px 最小面板：900−44−320=536px 画布；检查器再拖到 240 可回到 616px。**宽度不随选中跳变**优先于多让出 320px 画布 |

检查器常驻规格（总案 §6 C09）：宽度固定 **320px、可拖到 240px**；空选中时显示**流程级设置**，不做进出动画、不隐藏，**画布宽度不随选中变化**（旧「<1100px 覆盖抽屉 / 选中时滑出」已废止）。层级用 bg-layer-1 + 左缘 1px border-l2 表达，**投影 0**（总案 §3；旧「向左投影」作废）。

### 2.3 顶栏（48px，bg-layer-1，底缘 1px border-l1）

| 区 | 内容 | 尺寸 |
|---|---|---|
| 左 | 流程名（点击变输入框就地改名，min 120 / max 320px 自适应）+ 保存状态徽标 | 名 14px/600 label-primary；徽标 12px label-tertiary |
| 右 | 撤销 ↺ / 重做 ↻（28×28 图标钮，禁用 40% 透明，间距 8px）‖ 自动整理（28×28）‖ 校验点（8px 圆：灰=未校验 / 绿 `state-success-primary`=通过 / 红 `state-error-primary`=有错）‖ 运行按钮 | 运行 88×32，brand-primary 填充（主操作/中性色，不是运行色），圆角 `--dsw-radius-sm`（8）；运行中替换为「停止」64×32 `state-error-primary` 描边 |

**归属原则**：作用对象是「整张流程」的动作放顶栏（运行/停止/整理/撤销重做/校验）；作用对象是「选中物」的放检查器与右键。**保存状态徽标**的四态文案：`已保存 · 16:32` / `保存中…` / `未保存改动`（state-warn）/ `保存失败`（state-error，点击展开横幅）；保存失败且已写入本地草稿时，徽标后附「草稿」小字（草稿键与恢复流程见 §5.5-④）。

### 2.4 状态栏（28px，bg-base，顶缘 1px border-l1）

放**持续变化的低优先级读数**（读数不配按钮位，顶栏才是动作区）：

| 侧 | 设计态显示 | 运行态显示 |
|---|---|---|
| 左 | `节点 8 · 连线 7 · 问题 2`（问题>0 时该项 state-error，可点击展开问题列表浮层） | 同左 |
| 右 | （空） | `阶段 3/6 · 测试 · 已运行 4m12s · 打回 1 次`（12px label-tertiary，每秒刷新） |

### 2.5 画布内 HUD（浮层）清单与归属判断

**原则：HUD 只放「与光标/当前手势强相关的瞬时反馈」；持续读数去状态栏；配置去检查器。** 用户在拖动时眼睛在光标处，反馈必须出现在光标附近，放工具栏等于没有反馈。

| HUD | 位置 | 规格 |
|---|---|---|
| 缩放控件 | 右下角，距边 12px | 横排四件：`−`、百分比（56px 宽，点击回 100%）、`+`、`适配`；整体 32px 高，bg-layer-2，1px border-l2，圆角 `--dsw-radius-sm`（8）；单件 hover interactive-bg-hover |
| 框选计数气泡 | 跟随框选矩形右下角 | 高 24px，圆角 `--dsw-radius-panel`（28；CSS 在 24 高上钳到 12，等效胶囊），bg-layer-3，12px 文本 `已框选 4 个`，不响应指针 |
| 拖线合法性提示 | 跟随光标 +16/+16 偏移 | 12px，bg-layer-3，160ms 内出现（见 §5.1-15/16） |
| 拖动位移读数 | 选区包围盒右上角 | `+80 / +40`（网格吸附后取整值）12px |
| 对齐参考线 | 贯穿画布对应轴 | 1px brand-primary 虚线（dash 4-2），吸附瞬间出现，松手 200ms 淡出 |
| 问题定位呼吸高亮 | 出错节点描边 | brand→error 交替，400ms/次 × 2 次 |

**不进 HUD 的**：token/缺陷数等指标（归指标模块的运行 HUD 与检查器运行 tab）、节点配置（检查器）、小地图（见 §6 反例）。

### 2.6 基础刻度

| 项 | 值 |
|---|---|
| 间距刻度 | 4 / 8 / 12 / 16 / 24 / 32px（密度 8 档对应 8–32 主刻度） |
| 字号 | 12（辅助，正文地板 = `--dsw-font-xxs-12`）/ 13（正文）/ 14（标题）/ 16（面板题）/ 20（空态主文案），行高一律 1.5 |
| 圆角 | 只用宿主档位：容器/卡片/按钮 `--dsw-radius-sm`（8）、气泡与端口 `--dsw-radius-panel`（28，小尺寸上钳成胶囊）、细件（选中框等）`--dsw-radius-xs`（4）；不写裸数值 |
| 画布网格 | 20px 点阵，点 1px（label-tertiary @20% 透明）；缩放 <40% 时点距自动换挡为 40px（抄 tldraw 的「网格密度随缩放换挡」，避免缩小时网格糊成底纹） |
| 动效时长 | hover/选中 120–180ms；浮层进出 200ms；适配视图 240ms；自动整理 300ms（+按列 stagger 20ms）；HUD 淡出 200ms。全部 ease-out，`prefers-reduced-motion` 时归零为瞬切 |

### 2.7 从「一屏看清主干」反推的三条硬约束

八列主干的世界宽是 **2028px = 7×260 + 208**（节点 208 + 列距 260）。在 1440px 三栏画布（≈880px）上 fit ≈38.7%，属**精简档**（只看结构）；点「全览」把画布拉到 1396px 时 fit = (1396−96)/2028 ≈64.1%，是**完整档**的临界值。因此给节点/连线模块三条约束（与 03 §2.0、[DESIGN §6](../DESIGN.md) 同源）：

- **标准节点卡片 208×96px**：208 宽 + 52 间隙 = 列距 260；宽高都落在 4px 逻辑格上（视觉点阵仍是 20px）。卡片内容密度取舍归节点模块，宽度不再变；
- **主管+子 agent 卡片固定 208×116px**：同一列宽，多出的 20px 是常驻成员行；运行态只换内容、不改矩形（03 §2.3）；
- **自动整理在主干下方留出打回净空带**，但「净空」是两件事：**第一条航道偏移 `LANE_OFFSET=24`**（主干底缘下 24px 即 T1），**六条满配总净空 196px**（24 + 28×5 + 32，T1–T6 加末端 32px 留白）。旧稿「主干下 80px 起」把总净空误写成第一航道偏移，作废；打回线的绕行走法归连线模块（03 §2.1–2.2）。

## 3. 组件规格（本模块负责的组件）

### 3.1 顶栏图标按钮（撤销/重做/整理/校验点）

- 结构：28×28px 方形图标钮，SVG 描边图标（stroke 1.5px，尺寸 16×16），无文字。
- 状态：normal（label-secondary）→ hover（interactive-bg-hover，120ms）→ active（bg-layer-2）→ focus-visible（`--dsw-focus-ring-*` 外环，2px 偏移）→ 禁用（40% 透明 + cursor default）。
- 交互：hover 300ms 后浮出 tooltip（13px，bg-layer-3，写明动作名+快捷键，如「撤销 (Ctrl+Z)」）。图标钮必须带 tooltip 与 aria-label——无文字的按钮不能靠猜。
- 为什么 28px：顶栏 48px 高中垂直居中留上下各 10px 呼吸位；28px 热区配合 focus ring 足够，44px 会把顶栏撑成两排。

### 3.2 运行/停止按钮

- **待运行态**（按钮文案「运行」）：88×32，brand-primary 填充（主操作的中性色，不是运行状态色）、label 反色，圆角 `--dsw-radius-sm`（8），文本 13px/600；hover 提亮 8%（brand-primary 上叠加 bg-layer-1 8%）；校验不过时**不禁用**但点击后走「校验不通过」流程（跳问题列表第一条并定位）——让用户知道为什么不能跑，比灰按钮的说服力强。
- 运行中：替换为「停止」64×32，state-error-primary 描边 1px、文本同色、透明底；点击二次确认免掉（停止是可恢复动作：重新运行即可）。
- 为什么：主操作只有这一个，给它唯一一块品牌色填充，其余顶栏元素全部让路。

### 3.3 缩放控件（HUD）

- 结构与尺寸见 §2.5。按钮件 28×28 热区，百分比件 56px 宽居中。
- 交互：`−`/`+` 按档步进（15/25/50/75/100/125/150/200 八档，下限 15% 与 02 §2.4 的缩放地板同源，越界端点禁用态）；百分比点击回 100%；`适配` 等价快捷键 1。
- 为什么放画布右下：操作对象是视口，距光标最近，与滚轮缩放的心智一致（n8n/Figma 均将缩放控件放画布角落）。

### 3.4 右键菜单

- 结构：宽 200px，项高 32px，文本 13px label-primary 左对齐，图标区 24px（可选），分隔线为上下 margin 8px 的 1px border-l2；容器 bg-layer-3 + 1px border-l2（**投影 0**，总案 §3；旧「菜单投影」作废——层级靠填充层差 + 1px 描边），圆角 `--dsw-radius-sm`（8）。
- 出现：80ms scale 0.96→1，变换原点在光标侧；菜单打开时其余快捷键冻结（防误触发）。
- 两个菜单的内容：

| 节点右键 | 空白右键 |
|---|---|
| 复制 / 剪切 / 删除（state-error 文本） | 粘贴（剪贴板为空时禁用） |
| 原位副本 (Ctrl+D) | 全选 (Ctrl+A) |
| 连接到… (C) | 适配视图 (1) |
| 移到…（列/行或 x、y 输入） | 自动整理 |
| 重命名 (F2) | 吸附：开/关（toggle，显示当前态） |
| 复制为模板（后续版本） | |

- 为什么**要**右键菜单：复制/粘贴/吸附开关是「不是一句话能说清」或需要文字标签确认的低频动作（任务书红线只挡高频手势入菜单）；且它是拖拽类操作的纯指针替代路径（WCAG 2.2 拖拽替代要求）。「连接到…」同时是键盘连线的入口（见 §5.4），「移到…」是拖动节点的单指针替代：弹出列/行或 x、y 输入，提交后按 4px 吸附落位，不需要按住拖动。

### 3.5 空态卡与提示（视觉细节见 §5.5）

### 3.6 选择矩形与对齐参考线

- 选择矩形：brand-primary 8% 填充 + 1px brand-primary 描边（中性选中色），圆角 `--dsw-radius-xs`（4）；拖动中实时重算；完全包含判选（见 §5.1-5）。
- 对齐参考线：1px brand-primary 虚线，贯穿画布整轴，仅拖动中出现；松手 200ms 淡出。同屏最多同时 2 条（横+竖各一），避免参考线本身变成噪音。

### 3.7 端口与拖影线（交互规格；端口视觉归节点模块）

- 端口视觉 12px 圆，**热区 20px**（热区大于视觉，指针容差；hover 端口时光标变 crosshair）。
- 拖影线（拖线过程中的临时线）：合法时 1.5px brand-primary 实线 + 目标端口 4px brand 外环；非法时 1.5px state-error-primary 虚线（dash 6-4）+ 目标节点 1.5px error 描边 + 光标旁原因标签。
- 为什么热区 20px：12px 视觉目标在 1080p 上的点击失误率明显偏高，8px 半径扩展是画布工具的通行容差。

### 3.8 运行日志抽屉：三档高度、节点运行详情与全文弹层

抽屉（`src/client/logdrawer.js`，Ctrl/Cmd+J 开合；数据契约见 05 §6）解决两件事：**详情要能放大看**，**agent 到底在干什么要看得见**。

**三档高度**（A1）：

| 档 | 高度 | 进入方式 | 场景 |
|---|---|---|---|
| 默认 | 200px | 抽屉打开即此档 | 扫一眼指标与事件流 |
| 拉高 | `70vh`（`DRAWER_TALL_VH`） | 点「放大」 | 追一条长事件流 / 读节点详情 |
| 全屏 | `position:fixed;inset:0`，遮住画布 | 点「全屏」 | 集中排障，事件 + 详情两栏都吃满 |

- 头行常驻「放大 / 全屏 / 还原」三个按钮：当前不可用的档位禁用而不是隐藏（可用性不靠猜）；`aria-expanded` 落在放大 / 全屏按钮上，`aria-keyshortcuts="Escape"` 落在还原上。
- **Esc 逐档还原**：全屏 → 拉高 → 默认；到默认档后 Esc 交还画布（退出全览等），抽屉不抢。焦点随档位走：进全屏时焦点落到「还原」，退回默认时还给「放大」——键盘用户不会丢位置。
- 拉高 / 全屏时头部与指标区固定，**只有事件列表与详情列各自滚动**；<720px 三栏退化为单列（run 列表 / 事件流 / 详情纵向排列，各自可滚）。

**区域独立展开**（A2）：指标区、事件流、详情列各有一个「收起 / 展开」按钮（`aria-expanded`、`aria-label` 写明区域名）。收起只隐藏该区内容，不改变其他区；长内容永远在事件列表 / 详情列内部滚动，不把整条抽屉撑破。

**节点运行详情**（B4–B7）：入口两处——事件行里的**节点名 chip**，或事件详情里的「查看节点运行详情」。面板字段与数据来源：

| 面板字段 | 来源 |
|---|---|
| 标题 / 执行方式（单 agent / 主管 + 成员）/ 角色 | `node/start.data` 的 `title` / `mode`，缺失回落 `detail.nodes` / summary / nodeId |
| 状态 / attempt / 返工 / 是否当前节点 | `progress.nodes` + 事件 + `live`（与画布同一套 `deriveNodeStates`） |
| 最近在做什么（1–5 条，带时间与发言者） | `summary.activity.nodes[nodeId]`；运行中 summary 未收口时回退 `agent/message` 事件 |
| 最近工具调用（名字 + 参数摘要 + 结果 + 耗时） | `tool/call`（`argumentsDigest` / `ok` / `durationMs`） |
| token 用量（四段） | `summary.tokens.byNode`；缺失时回退该节点 `model/call` 的 `usage` |
| 成员最近活动 | `member/start` / `member/end` 提供名字 / 角色 / 状态，`agent/message.memberId` 提供最近发言 |
| 已写产物（路径 + 字节数 + kind） | `artifact/write` |
| 失败原因 | `node/end.extra.reason`，其次 `run/end.data.reason` |

- 运行中带「正在运行」文本 + 圆点（**不做无限动画**；`prefers-reduced-motion` 已有全局兜底）；run 结束后同样保留「最后在做什么」与失败原因，不再只显示一个红点。
- 字段缺失一律显示「未记录 / — / 还没有…」的可读占位，不抛错、不拿 0 冒充。

**全文弹层**（A2）：agent 消息、错误 / reason 等长文本在面板里可折行显示（限高），旁边永远有「展开全文」；弹层内可滚动、可「复制全文」、Esc 关闭，Tab 焦点困在弹层内，关闭后焦点归还触发按钮。

样式只用 `--dsw-*` 语义 token（新增类无 hex），正文最小 12px；新按钮全部是原生 `<button>`，可 Tab、有 `aria-label`。

## 4. 状态与流转的可视化规则（交互侧）

节点/连线在「待执行/运行中/通过/被打回/失败/跳过」六态下的静态视觉归节点/连线模块。本段定义**交互上下文叠加其上的规则**，与六态正交：

| 交互上下文 | 视觉规则 | 为什么 |
|---|---|---|
| 节点 hover | 描边加深一档（border-l2→border-l3），120ms；端口同步淡入放大至 14px | hover 是「可交互」的预告，端口放大降低拉线瞄准成本 |
| 单选 | 2px brand-primary 描边 + 200ms 过渡；不改变卡片内部内容 | 描边是最不侵占内容的选中语言 |
| 多选 | 每个选中 1.5px brand 描边，**最后操作起点的主选中 2px**，选区包围盒显示 1px border-l3 虚线框 + 位移读数 | 主次区分让后续 Enter/检查器有明确目标 |
| 拖动中 | 被拖卡片：**投影保持 0**（不升阴影；改用描边提到 1.5px `border-l4` + 整体 90% 透明）+ 位移读数；其连线：降为 1px 虚线 | 拖动时连线是「随动信息」不是主角，降级让用户聚焦位置；总案 §3 投影 0 种，旧「阴影升级」作废 |
| 拖线合法 | 见 §3.7 | |
| 拖线非法 | 见 §3.7 + 光标标签 | 反馈要在尝试时就地出现（错误就近原则） |
| 打回自动判定宣告 | 落线瞬间线体 state-warn 色 + 线上「打回」标签 + 节点旁 inline toast `已按打回连线：方案 ← 开发`，2.5s 自动消失 | 系统替用户改了线的类型，必须显式宣告，否则用户不知道这条线为什么长这样（详见 §5.1-16） |
| 校验定位 | 呼吸高亮：描边 brand→error 交替 400ms/次 ×2 | 两次足够引起注意，三次以上变成骚扰 |
| 运行中 / 返工中（结构锁定） | **锁全部结构编辑**：双击空白新建（#11）、拖节点（#2/#6）、改边（#3/#4/#16）、自动整理（#13）与检查器结构字段一律禁用，悬停/点击时就地给原因 `运行中，结构不可编辑`（12px tooltip + 顶部提示条）；顶栏出现 `运行中` chip；平移/缩放/选中查看**不受限**。**无例外**——旧「双击空白新建不受运行态影响」已废止；只有点「停止」回到设计态后恢复（总案 §6 C12） | 锁结构不锁查看：监督时用户最常做的就是缩放看图、点节点看运行信息；运行中改结构会让执行器与图上拓扑错位 |

### 5.4 键盘快捷键全表

**设计原则：默认不用单字母快捷键；唯一例外是画布上下文里的 `C`（连线）。** 中文用户输入法激活时单字母会被 IME 吃掉产生歧义（n8n 的 D 停用/P 钉数据在本产品语境里不可复制）；功能键、数字、符号与 Ctrl 组合不受 IME 影响。**不采用 `Ctrl+L` 做连线**：Chrome / Firefox / Edge 都把 `Ctrl+L` 绑定到地址栏，页面拿不到该事件，写进规格等于承诺一个永远不会触发的快捷键。`C` 的生效条件见下表与 WCAG 2.1.4 说明。

| 键 | 生效场景 | 动作 | 备注 |
|---|---|---|---|
| Tab / Shift+Tab | 画布焦点态 | 在节点间按图序循环（开始→阶段1→…→结束），焦点即选中 | 纯键盘可达路径（WCAG） |
| ↑↓←→ | 有选中 | 微移 4px（1 格，逻辑吸附步长） | 微移同样吸附对齐规则 |
| Shift+方向 | 有选中 | 微移 20px（5 格） | 抄 tldraw「1 格/5 格」节奏，步长跟 4px 网格 |
| Ctrl+A | 画布 | 全选 | |
| Delete / Backspace | 画布有选中 | 删除选中节点与连线 | 输入框聚焦时失效（见冲突 1） |
| Ctrl+C / Ctrl+X / Ctrl+V | 画布 | 复制 / 剪切 / 粘贴（粘贴落点 +20/+20 偏移） | |
| Ctrl+D | 画布 | 原位副本（+20/+20 偏移，随即可拖） | 造平行阶段的最快路径 |
| `C` | 画布上下文：有选中节点、焦点不在 `input/textarea/contenteditable`、且不在 IME 组合中 | 打开「连接到…」目标列表（只列合法下游目标，按图序排列）；↑↓ 选择、Enter 建线、Esc 取消 | 键盘连线主路径；与右键「连接到…」是同一动作。**不采用 `Ctrl+L`**（浏览器抢占地址栏） |
| Enter | 单选节点 | 打开/聚焦检查器对应分区 | 输入框内 Enter=提交字段 |
| F2 | 单选节点 | 进入重命名 | 功能键，无 IME 冲突 |
| Esc | 分层退出 | 见下方冲突 2 | |
| Space（按住） | 画布 | 平移模式（grab 光标） | preventDefault 防止误触按钮 |
| `+` / `=` | 画布 | 放大一档 | |
| `-` | 画布 | 缩小一档 | |
| `0` | 画布 | 回 100% | |
| `1` | 画布 | 适配全图 | |
| `2` | 画布 | 适配到选中 | |
| Ctrl+Z | 全局 | 撤销 | |
| Ctrl+Shift+Z / Ctrl+Y | 全局 | 重做 | |
| Ctrl+S | 全局 | 保存 | |
| Ctrl+Enter | 全局 | 运行（运行中无效） | textarea 内也触发——textarea 惯例就是 Ctrl+Enter 提交，不视为冲突 |

**单字母键与 WCAG 2.1.4（字符键快捷键）**：2.1.4 针对的是「仅用字母/字符键实现的快捷键」，要求可关闭、可重映射，或**仅在对应组件获得焦点时生效**。本方案只保留一个字符键 `C`，生效条件是「画布上下文 + 已选中节点 + 焦点不在 `input/textarea/contenteditable` + 不在 IME 组合中」——打字路径上不存在会被劫持的字符输入，等价于 2.1.4 的「仅在组件获得焦点时生效」豁免，因此不需要额外提供关闭开关。若以后新增字符键，必须按同一判据复核；`C` 只作为画布上下文快捷键，不与浏览器/输入法组合冲突。

**键盘连线与单指针连线（M08 补齐，两条路径分别验收）**：

| 路径 | 操作链 | 适用 | 验收时要证明的事 |
|---|---|---|---|
| 键盘 | `Tab`/`Shift+Tab` 选中源节点 → `C` 打开目标列表（只列合法目标，非法目标不出现）→ `↑↓` 选择 → `Enter` 建线 → 建线后焦点落在新线上，`Esc` 退出 | 纯键盘用户、无精确指针设备 | 不依赖指针移动即可完成「选源 → 选目标 → 建线」，且非法目标不给出可选项；`C` 只在画布上下文生效 |
| 单指针（点击-点击） | 单击源节点右端口（进入连线态，端口常亮 + 光标旁提示「选择目标端口」）→ 单击目标左端口落线；点空白或 `Esc` 取消 | 触屏、手部不便、拖动不稳 | 全程不需要按住拖动，判定与拖拽路径完全一致（同一 `validateConnection`） |
| 单指针（移动） | 右键节点 →「移到…」→ 输入列/行或 x、y → 提交按 4px 吸附落位；或检查器「位置」两个数值字段直接改 | 替代拖动定位 | 不按住拖动也能把节点移到任意位置，且落位与拖动吸附同规则 |

为什么拆成两条路径：WCAG 2.2 的拖拽替代（2.5.7）要求「不按住拖动也能完成同一操作」，而键盘可达（2.1.1）要求「不依赖指针也能完成」。两者是两条独立判据——不能拿「有方向键微移」冒充拖拽替代（微移一次 20px，把 208px 宽的卡移过一列要按十几次），也不能拿「键盘能连」冒充单指针可达。**方向键微移保留，但它不是替代路径。**

**冲突说明（必须实现，不是备注）：**

1. **Delete vs 输入框**：任何 `input / textarea / contenteditable` 聚焦时，Delete/Backspace/方向键/Ctrl+Z/Ctrl+C 全部归输入框，画布快捷键全部休眠（判定条件：事件 target 命中可编辑元素）。为什么：重命名到一半按 Delete 想删节点、结果只删了字符，是可恢复的小挫折；反过来（输入时误删节点）是灾难。防误删优先。
2. **Esc 的退出栈**（每次只退一层，按进入的逆序）：拖线进行中 → 取消拖线；节点拖动中 → 弹回原位；重命名中 → 恢复原名退出；右键菜单/问题列表浮层开 → 关闭浮层；检查器拖宽进行中 → 复位到 320；多选 → 退为单选；单选 → 清空选中。为什么：Esc 的语义是「退出当前模式」，模式是栈式的，一层一层退才不会一步把用户五个动作的上下文全抹掉。
3. **Ctrl+Z vs 输入框**：输入框内撤销是文本级撤销，**不冒泡**为结构撤销；想撤销结构先 Esc/点画布失焦。界限清晰比「智能冒泡」可靠。
4. **Space vs 按钮激活**：Space 进入平移模式时对画布容器 preventDefault，防止此刻恰好聚焦的顶栏按钮被 Space 触发。
5. **数字键 1/2/0 vs 重命名**：重命名是输入框场景，规则同冲突 1，自动覆盖。

### 5.5 空状态与异常态

#### ① 第一次打开（还没有流程）

| 元素 | 规格 |
|---|---|
| 左栏 | 模板列表（内置「六阶段研发流」卡片）+「+ 新建流程」按钮 32px 高全宽 |
| 画布 | 中央空态卡：64px SVG 线稿图示（三个小节点连成链的简笔图形，label-tertiary 描边）；主文案 20px/600 label-primary **「还没有流程」**；副文案 13px label-secondary **「从六阶段模板开始，两步就能看到第一张能跑的图」**；按钮组：`用模板创建` 120×36 brand 填充（视觉第一）+ `新建空白流程` 120×36 描边 ghost（视觉第二） |
| 顶/状态栏 | 运行按钮禁用（tooltip `还没有流程`）；状态栏 `节点 0 · 连线 0` |

为什么：首次用户的目标是「30 秒看到能跑的东西」而不是白手起家，所以模板路径按钮拿唯一的品牌色填充、文案直接承诺步数（「两步」是真实承诺）。

#### ② 流程为空（0 个节点，刚建了空白流程）

- 画布中央**轻提示**（非全屏卡）：30% 透明的虚线轮廓卡片（208×96）+ 一行 13px label-tertiary：**「双击画布任意位置，添加第一个节点」**。
- 网格照常显示；顶栏运行按钮禁用，tooltip **「缺少开始节点」**；状态栏 `节点 0 · 连线 0`。
- 为什么轻量：用户已在任务中，提示只指路不挡道；空态是画布的一层薄纱而不是另一块屏幕。

#### ③ 校验不通过（错误定位到节点）

三通道，缺一不可：

1. **状态栏**：`问题 2` 显示为 state-error，点击浮出问题列表浮层（宽 280px，每条 = 节点名 13px/600 + 问题句 13px + `定位` 文字钮）。
2. **画布**：出错节点右上角 8px state-error 圆点；hover 圆点显示同款问题句 tooltip。
3. **定位**：点问题条目或 `定位` → 画布 300ms 平移居中该节点 → 呼吸高亮 2 次（§4）。

文案格式统一为「对象——问题」，短、说人话、不出现错误码：

| 场景 | 文案 |
|---|---|
| 缺起点 | **缺开始节点——流程没有起点** |
| 打回指向下游 | **测试的打回指向了下游，打回只能往回连** |
| 孤立节点 | **代码审查没有连线，跑不到它** |
| 缺终点 | **没有结束节点，流程收不了尾** |
| 循环无出口 | **这条循环里没有能通过的出口** |

为什么：校验错误必须「一键到现场」；只给列表不给定位，是让用户自己找茬。文案不带「错误码 E-xxx」——码是给日志的，不是给人解决问题的。

#### ④ Host 连不上 / 保存失败

| 态 | 视觉 | 文案 |
|---|---|---|
| 连不上宿主 | 顶栏下横幅 36px，bg-layer-2 + 左缘 3px state-warn | **「连不上宿主服务。改动已写入本地草稿（`flow-studio:draft:<flowId>`），恢复后点「重存」才会写回流程」** + `重试` `重存`；画布继续可编辑 |
| 保存失败（请求明确失败） | 同位置，左缘 3px state-error | **「保存失败。改动已存为本地草稿，没有丢失」** + `重试` `丢弃草稿` |
| 重新打开 / 切回该流程时发现草稿 | 同位置，左缘 3px state-warn | **「发现上次未保存的本地草稿（16:32），要恢复吗？」** + `恢复` `丢弃`；恢复 = 把草稿内容装回画布并标「未保存改动」，丢弃 = 删除该草稿键 |
| 保存成功 | 同位置，左缘 3px state-success，2.5s 后自动收起 | **「已保存」**；同时清除该流程的草稿键 `flow-studio:draft:<flowId>` |
| 切流程（有未保存改动或未处理草稿） | 切换到新流程前弹确认（≤360px，非全屏模态） | **「当前流程还有未保存的改动，切换后可从本地草稿恢复」** + `仍要切换` `留在此页`；草稿键保留，不静默丢弃，切回来可恢复 |
| 顶栏徽标联动 | 见 §2.3 四态；保存失败时徽标附「草稿」小字 | — |

草稿机制的实现口径（文案以它为前提，未实现前不得上线这套承诺）：

- 键名 `flow-studio:draft:<flowId>`，值是「流程内容 + 保存发起时间 + 内容版本号」；只存本地 `localStorage`，不上传。
- 只有在**保存请求明确失败或宿主连不上**时才落草稿；保存成功必须清键，避免下次误报「有草稿」。
- 「恢复」不自动提交：恢复后画布标「未保存改动」，由用户再点保存；「丢弃」是显式动作，不做静默清理。
- 切流程前若仍有未保存改动/未处理草稿，必须先确认；确认后草稿仍保留在本地，回来时可恢复。

为什么：断连不是用户的错误，文案仍要一次回答三问——**丢没丢**（没丢，已写本地草稿）、**现在能干嘛**（继续编辑、随时重试）、**之后会怎样**（恢复后需手动重存，或显式丢弃）。**不写「自动同步」**：本版没有后台同步/离线队列，文案不得承诺没有实现机制的能力（M06）。同时如实说明草稿只在本地浏览器——换设备、清缓存会丢，这一点写在恢复横幅的 tooltip 里。

### 5.6 信息架构判断

#### 设计 / 运行：一个视图、两种状态（叠加态）

**判断：不做两套视图。** 理由：

1. **空间记忆**：用户刚在「测试」节点旁改过打回目标，运行时要能在同一位置找到它。切视图 = 丢掉「哪里有什么」的全部记忆，监督成本暴涨。
2. **任务书 §3.3 已把它定性为「叠加」问题**，不是重画问题。
3. **体量现实**：单文件产物做不起两套画布渲染（v0.5 起 512KB，仍需克制）。
4. **先例**：LangGraph Studio 的 Graph mode 在同一张图上叠加节点遍历与中间状态，而不是为运行重画一张。

机制：运行开始 → 结构编辑锁定（§4 末行）→ 叠加层渲染执行态（当前节点动效描边、已完成路径高亮、执行 HUD——视觉归运行态模块）→ 平移/缩放/选中查看全程可用 → 结束或停止 → 回设计态，图上的位置一个都没动。**退出运行回到设计态时，视口位置也原样保留**（监督时放大到哪里，回去还在哪里）。

#### 从「新建流程」到「第一张能跑的图」：步数

| 路径 | 步骤 | 明细 |
|---|---|---|
| **模板路径（推荐动线）** | **2 步** | 点 `用模板创建`（空态卡第一按钮）→ 6 节点、5 条流转、典型打回全部预置 + 自动适配 → 点 `运行` |
| 空白路径 | ≈20+ 次操作 | 新建 → 双击建 6 个节点（每个顺带起名）→ 拉线 5–9 条 → 逐节点打开检查器配角色 → 运行 |

能不能更少：**2 步是底线。** 再压（比如打开面板就自动建好模板图）会剥夺「我确认要创建」的决策点——未经确认生成的图，用户不会当自己的东西对待（见 §6 反例 6）。真正该做的是压空白路径的**单步摩擦**：双击新建后自动进重命名（已定）、新建节点后左侧端口短暂高亮 1.5s 提示可拉线、检查器分区按使用频率排列（角色→任务→skill→模型）。步数压不掉，摩擦可以压到底。

## 6. 反例（明确不做的事）

1. **不做两套设计/运行视图。** 理由见 §5.6：空间记忆断裂 + 体量双倍。
2. **不用力导布局做自动整理。** 本产品拓扑固定（六阶段主干 + 指向上游的打回），力导会把「开始…结束」揉成毛线球；分层布局与领域语义一一对应。也不用纯网格对齐——网格不表达连线关系，整理完线还是乱的。
3. **不做命令面板（Ctrl+K）。** n8n 有，但它服务于上百个动作的全局搜索；本面板动作 ≤20 且每个都有直接手势。单文件预算应花在画布手感上（v0.5 起 512KB）。
4. **不做小地图。** 典型 6–12 节点、极端 30 节点，快捷键 1 一击全览、快捷键 2 聚焦选中段；小地图是常驻 UI + 双份同步渲染的体量大户，在这个规模收益为负。（有条件放弃：若 30+ 节点成为常态再评估。）
5. **不做「松手才校验」的连线。** 连不上必须在拖动过程中实时可见（§5.1-15），松手报错等于让用户完成一个注定失败的动作。
6. **不做「打开面板自动建图」。** 创建要留给用户一次显式确认（点 `用模板创建`），未经确认的产出不被信任；首次空态卡把模板路径做成视觉第一动线，2 步已经够短。
