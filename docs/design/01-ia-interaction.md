# 01 · 信息架构与画布交互

> 模块归属：信息架构 + 画布交互（布局、操作手感、键盘、空态/异常态、设计/运行关系）。
> 节点卡片与连线的静态视觉（各状态配色、打回航道画法、标签版式）归节点/连线模块，本文只定**交互侧规格**并给出两个反推约束（卡片 180×80、下航道净空 80px）。
> 所有颜色/圆角/字体一律引用宿主变量 `--dsw-*`，本文只写语义名，不写 hex。

---

## 1. 设计结论

1. **三栏常驻、宽度不对称**：左栏（流程列表）240px 可折叠到 44px，右栏（检查器）320px，画布吃满剩余。理由：左栏是低频导航（一次会话换 1–3 次流程），右栏承载高频表单回路（选中即配置）。
2. **检查器常驻、<1100px 退化为右侧覆盖抽屉**。理由：设计态「点节点→改配置」每分钟发生，浮层会遮挡画布并制造焦点管理成本；小屏时空间不够才让位。
3. **设计/运行是一个视图、两种状态**：设计态是底图，运行态是叠加层，运行中锁结构编辑、不锁平移缩放。理由：保住空间记忆（用户刚在哪编辑过，运行时同一位置能找到），也符合单文件 256KB 的体量现实。
4. **首次路径压到 2 步**：空态卡预置「六阶段模板」为视觉第一动线，点「用模板创建」即得一张连线齐全的图，再点「运行」。2 步是底线，再压会剥夺用户「确认创建」的决策点。
5. **编辑手感走轻键盘路线**：双击空白建、右端口拉线连、Delete 删、方向键微移、Space/中键平移、Ctrl+滚轮缩放；右键菜单只收编低频、需要文字标签确认的动作（复制/粘贴/吸附开关）。单字母快捷键一律不用（中文 IME 会吃掉）。
6. **自动整理用分层布局**（主干按阶段序分列向右、打回统一绕下方航道），不用力导。理由：本产品的拓扑是固定的「DAG 主干 + 反向打回边」，分层是它的自然语言，力导会把主干揉成球。
7. **撤销要做，粒度 = 一次有意义的操作**：一次拖放 = 一步、一个字段失焦提交 = 一步，栈深 50。不做「每个 mousemove 入栈」和「每字符一步」。
8. **校验错误三通道定位**：状态栏计数 → 点开问题列表 → 点单条即平移居中到出错节点并呼吸高亮。错误不许让用户自己找茬。

## 2. 布局与尺寸

### 2.1 总体框架

```
┌──────────────────────────────────────────────────────────────┐
│ 顶栏 48px  流程名+保存状态 │ 撤销 重做 | 整理 校验 ● │ ▶ 运行  │
├────────┬───────────────────────────────────────┬─────────────┤
│ 左栏    │                                       │ 右栏        │
│ 240px   │            画布（弹性）                │ 320px       │
│ (可折叠 │            网格 20px 点阵              │ 检查器      │
│  44px)  │                                       │ (常驻)      │
│         │                       [缩放HUD ↘右下角] │             │
├────────┴───────────────────────────────────────┴─────────────┤
│ 状态栏 28px  节点 8 · 连线 7 · 问题 2 │ 阶段 3/6 · 4m12s      │
└──────────────────────────────────────────────────────────────┘
```

面板总可用 900–1600 × 600–1000px；顶栏+状态栏共吃 76px，画布净高 524–924px。

### 2.2 响应式断点

| 视口宽 | 左栏 | 右栏（检查器） | 形态 | 为什么 |
|---|---|---|---|---|
| ≥1360px | 240px 常驻 | 320px 常驻 | 三栏 | 1600 时画布 ≈1020px，80% 缩放下 6 列主干全览 |
| 1100–1359px | 200px 常驻（隐藏列表第二行时间戳） | 320px 常驻 | 三栏紧凑 | 画布保住 ≥580px，仍能看 3–4 列 |
| <1100px | 44px 图标条（点图标展开为覆盖列） | 320px **覆盖抽屉**（选中时滑出，点画布空白/Esc 收起） | 单栏画布 | 900px 最小面板：900−44=856px 画布，不能再被两栏挤压 |

覆盖抽屉规格：从右滑入 200ms ease-out，bg-layer-1 + 左缘 1px border-l2 + 向左 8px 投影，不铺遮罩（画布平移缩放仍可用，只有点空白/Esc 才收）。

### 2.3 顶栏（48px，bg-layer-1，底缘 1px border-l1）

| 区 | 内容 | 尺寸 |
|---|---|---|
| 左 | 流程名（点击变输入框就地改名，min 120 / max 320px 自适应）+ 保存状态徽标 | 名 14px/600 label-primary；徽标 12px label-tertiary |
| 右 | 撤销 ↺ / 重做 ↻（28×28 图标钮，禁用 40% 透明，间距 8px）‖ 自动整理（28×28）‖ 校验点（8px 圆：灰=未校验 / 绿 state-success=通过 / 红 state-error=有错）‖ 运行按钮 | 运行 88×32，brand-primary 填充，radius 6；运行中替换为「停止」64×32 state-error 描边 |

**归属原则**：作用对象是「整张流程」的动作放顶栏（运行/停止/整理/撤销重做/校验）；作用对象是「选中物」的放检查器与右键。**保存状态徽标**的四态文案：`已保存 · 16:32` / `保存中…` / `未保存改动`（state-warn）/ `保存失败`（state-error，点击展开横幅）。

### 2.4 状态栏（28px，bg-base，顶缘 1px border-l1）

放**持续变化的低优先级读数**（读数不配按钮位，顶栏才是动作区）：

| 侧 | 设计态显示 | 运行态显示 |
|---|---|---|
| 左 | `节点 8 · 连线 7 · 问题 2`（问题>0 时该项 state-error，可点击展开问题列表浮层） | 同左 |
| 右 | （空） | `阶段 3/6 · 测试 · 已运行 4m12s · 打回 1 次`（12px label-tertiary，每秒刷新） |

### 2.5 画布内 HUD（浮层）清单与归属判断

**原则：HUD 只放「与光标/当前手势强相关的瞬时反馈」；持续读数去状态栏；配置去检查器。** 用户在拖动时眼睛在光标处，反馈必须出现在光标附近，放工具栏等于没有反馈。

| HUD | 位置 | 规格 |
|---|---|---|
| 缩放控件 | 右下角，距边 12px | 横排四件：`−`、百分比（56px 宽，点击回 100%）、`+`、`适配`；整体 32px 高，bg-layer-2，1px border-l2，radius 8；单件 hover interactive-bg-hover |
| 框选计数气泡 | 跟随框选矩形右下角 | 高 24px，radius 999，bg-layer-3，12px 文本 `已框选 4 个`，不响应指针 |
| 拖线合法性提示 | 跟随光标 +16/+16 偏移 | 12px，bg-layer-3，160ms 内出现（见 §5.1-15/16） |
| 拖动位移读数 | 选区包围盒右上角 | `+80 / +40`（网格吸附后取整值）12px |
| 对齐参考线 | 贯穿画布对应轴 | 1px brand-primary 虚线（dash 4-2），吸附瞬间出现，松手 200ms 淡出 |
| 问题定位呼吸高亮 | 出错节点描边 | brand→error 交替，400ms/次 × 2 次 |

**不进 HUD 的**：token/缺陷数等指标（归指标模块的运行 HUD 与检查器运行 tab）、节点配置（检查器）、小地图（见 §6 反例）。

### 2.6 基础刻度

| 项 | 值 |
|---|---|
| 间距刻度 | 4 / 8 / 12 / 16 / 24 / 32px（密度 8 档对应 8–32 主刻度） |
| 字号 | 12（辅助）/ 13（正文）/ 14（标题）/ 16（面板题）/ 20（空态主文案），行高一律 1.5 |
| 圆角 | 容器 8px、卡片与按钮 6px、气泡与端口 999px，全部走 `--dsw-radius-*` 对应档 |
| 画布网格 | 20px 点阵，点 1px（label-tertiary @20% 透明）；缩放 <40% 时点距自动换挡为 40px（抄 tldraw 的「网格密度随缩放换挡」，避免缩小时网格糊成底纹） |
| 动效时长 | hover/选中 120–180ms；面板滑入 200ms；适配视图 240ms；自动整理 300ms（+按列 stagger 20ms）；HUD 淡出 200ms。全部 ease-out，`prefers-reduced-motion` 时归零为瞬切 |

### 2.7 从「一屏看清主干」反推的两个硬约束

典型 6 阶段主干要在一屏 80% 缩放下全览：6 列 × (卡片 180px + 列距 60px) − 60 = 1380px 世界宽 → 在 1100px 画布上适配 ≈ 80%，此时 13px 字号仍有 10.4px，可读。因此本文给节点/连线模块两个约束：

- **节点卡片建议 180×80px**（180=9 格、80=4 格，全部落在 20px 网格整格上；卡片内容密度取舍归节点模块，超过 200px 宽就挤占适配能力）；
- **自动整理在主干下方留 80px 打回航道净空带**（打回线的绕行走法归连线模块，但布局必须给它让出这条带）。

## 3. 组件规格（本模块负责的组件）

### 3.1 顶栏图标按钮（撤销/重做/整理/校验点）

- 结构：28×28px 方形图标钮，SVG 描边图标（stroke 1.5px，尺寸 16×16），无文字。
- 状态：normal（label-secondary）→ hover（interactive-bg-hover，120ms）→ active（bg-layer-2）→ focus-visible（`--dsw-focus-ring-*` 外环，2px 偏移）→ 禁用（40% 透明 + cursor default）。
- 交互：hover 300ms 后浮出 tooltip（13px，bg-layer-3，写明动作名+快捷键，如「撤销 (Ctrl+Z)」）。图标钮必须带 tooltip 与 aria-label——无文字的按钮不能靠猜。
- 为什么 28px：顶栏 48px 高中垂直居中留上下各 10px 呼吸位；28px 热区配合 focus ring 足够，44px 会把顶栏撑成两排。

### 3.2 运行/停止按钮

- 运行态：88×32，brand-primary 填充、label 反色，radius 6，文本 13px/600；hover 提亮 8%（brand-primary 上叠加 bg-layer-1 8%）；校验不过时**不禁用**但点击后走「校验不通过」流程（跳问题列表第一条并定位）——让用户知道为什么不能跑，比灰按钮的说服力强。
- 运行中：替换为「停止」64×32，state-error-primary 描边 1px、文本同色、透明底；点击二次确认免掉（停止是可恢复动作：重新运行即可）。
- 为什么：主操作只有这一个，给它唯一一块品牌色填充，其余顶栏元素全部让路。

### 3.3 缩放控件（HUD）

- 结构与尺寸见 §2.5。按钮件 28×28 热区，百分比件 56px 宽居中。
- 交互：`−`/`+` 按档步进（25/50/75/100/125/150/200 七档，越界端点禁用态）；百分比点击回 100%；`适配` 等价快捷键 1。
- 为什么放画布右下：操作对象是视口，距光标最近，与滚轮缩放的心智一致（n8n/Figma 均将缩放控件放画布角落）。

### 3.4 右键菜单

- 结构：宽 200px，项高 32px，文本 13px label-primary 左对齐，图标区 24px（可选），分隔线为上下 margin 8px 的 1px border-l2；容器 bg-layer-3 + 1px border-l2 + 8px 模糊阴影，radius 8。
- 出现：80ms scale 0.96→1，变换原点在光标侧；菜单打开时其余快捷键冻结（防误触发）。
- 两个菜单的内容：

| 节点右键 | 空白右键 |
|---|---|
| 复制 / 剪切 / 删除（state-error 文本） | 粘贴（剪贴板为空时禁用） |
| 原位副本 (Ctrl+D) | 全选 (Ctrl+A) |
| 重命名 (F2) | 适配视图 (1) |
| 复制为模板（后续版本） | 自动整理 |
| | 吸附：开/关（toggle，显示当前态） |

- 为什么**要**右键菜单：复制/粘贴/吸附开关是「不是一句话能说清」或需要文字标签确认的低频动作（任务书红线只挡高频手势入菜单）；且它是拖拽类操作的纯指针替代路径（WCAG 2.2 拖拽替代要求）。

### 3.5 空态卡与提示（视觉细节见 §5.5）

### 3.6 选择矩形与对齐参考线

- 选择矩形：brand-primary 8% 填充 + 1px brand-primary 描边，radius 2；拖动中实时重算；完全包含判选（见 §5.1-5）。
- 对齐参考线：1px brand-primary 虚线，贯穿画布整轴，仅拖动中出现；松手 200ms 淡出。同屏最多同时 2 条（横+竖各一），避免参考线本身变成噪音。

### 3.7 端口与拖影线（交互规格；端口视觉归节点模块）

- 端口视觉 12px 圆，**热区 20px**（热区大于视觉，指针容差；hover 端口时光标变 crosshair）。
- 拖影线（拖线过程中的临时线）：合法时 2px brand-primary 实线 + 目标端口 4px brand 外环；非法时 2px state-error-primary 虚线（dash 6-4）+ 目标节点 1.5px error 描边 + 光标旁原因标签。
- 为什么热区 20px：12px 视觉目标在 1080p 上的点击失误率明显偏高，8px 半径扩展是画布工具的通行容差。

## 4. 状态与流转的可视化规则（交互侧）

节点/连线在「待执行/运行中/通过/被打回/失败/跳过」六态下的静态视觉归节点/连线模块。本段定义**交互上下文叠加其上的规则**，与六态正交：

| 交互上下文 | 视觉规则 | 为什么 |
|---|---|---|
| 节点 hover | 描边加深一档（border-l2→border-l3），120ms；端口同步淡入放大至 14px | hover 是「可交互」的预告，端口放大降低拉线瞄准成本 |
| 单选 | 2px brand-primary 描边 + 200ms 过渡；不改变卡片内部内容 | 描边是最不侵占内容的选中语言 |
| 多选 | 每个选中 1.5px brand 描边，**最后操作起点的主选中 2px**，选区包围盒显示 1px border-l3 虚线框 + 位移读数 | 主次区分让后续 Enter/检查器有明确目标 |
| 拖动中 | 被拖卡片：阴影提升一档 + 整体 90% 透明 + 位移读数；其连线：降为 1px 虚线 | 拖动时连线是「随动信息」不是主角，降级让用户聚焦位置 |
| 拖线合法 | 见 §3.7 | |
| 拖线非法 | 见 §3.7 + 光标标签 | 反馈要在尝试时就地出现（错误就近原则） |
| 打回自动判定宣告 | 落线瞬间线体 state-warn 色 + 线上「打回」标签 + 节点旁 inline toast `已按打回连线：方案 ← 开发`，2.5s 自动消失 | 系统替用户改了线的类型，必须显式宣告，否则用户不知道这条线为什么长这样（详见 §5.1-16） |
| 校验定位 | 呼吸高亮：描边 brand→error 交替 400ms/次 ×2 | 两次足够引起注意，三次以上变成骚扰 |
| 运行中（结构锁定） | 检查器全部输入禁用 + 顶部 12px 提示条 `运行中，结构不可编辑`；顶栏出现 `运行中` chip；平移/缩放/选中查看**不受限** | 锁编辑不锁查看：监督时用户最常做的就是缩放看图、点节点看运行信息 |

## 5. 交互规则

### 5.1 画布操作全表

| # | 操作 | 触发方式 | 结果 | 视觉反馈 | 为什么这样 |
|---|---|---|---|---|---|
| 1 | 选中节点 | 单击卡片 | 选中，检查器切换为该节点配置 | 2px brand 描边，200ms 过渡；反馈须在 100ms 内出现 | 100ms 内的响应被感知为「即时」；选中是所有后续操作的地基，不能有迟疑感 |
| 2 | 拖动节点 | 按住卡片移动，位移 >4px 才进入拖动 | 节点跟手移动，连线实时重算 | 拖动态视觉见 §4；释放时落位吸附（无动画，直接咔哒到位） | 4px 是区分「点击/拖动」的通行阈值（Figma/tldraw 同款），避免手抖误拖；吸附落位不做动画是因为吸附的价值就在「突然变正」的确定感 |
| 3 | 从端口拉线 | 从卡片右侧端口按下拖动 | 拖到目标左侧端口释放即建线 | 拖影线/目标高亮见 §3.7 | 从右侧拉向左侧与主干方向一致，符合「向下游流」的阅读方向 |
| 4 | 删连线 | hover 连线 → 线加粗至 3px + 中点浮出 × 删除点（24px 热区）；点击 ×，或选中线后 Delete | 删除连线 | 线 200ms 淡出 | hover 加粗让细线变得可瞄准；中点 × 比拖断手势可发现、可撤销、可点按（拖断对新手是隐藏手势） |
| 5 | 框选多个 | 空白处按下拖动（位移 >4px） | 释放后**完全被矩形包含**的节点进入多选 | 选择矩形 + 计数气泡 `已框选 N 个` | 用「完全包含」而非「相交」：6–30 节点规模下相交选区会顺带勾住远处的连线，包含判选更准；计数气泡让用户不用逐个确认选中了几个 |
| 6 | 框选后整体拖动 | 拖动任一选中节点 | 全组保持相对位置移动 | 整组拖动态 + 位移读数 `+80 / +40` | 组内相对位置不变是「整体移动」的心智模型；显示吸附后的整数位移让网格吸附可感知 |
| 7 | 平移 | ① Space 按住+拖 ② 中键拖 ③ 触控板双指 | 画布平移 | 光标 grab→grabbing（Space 路径），无动画 | Space+拖与中键是 Figma/n8n 共用约定；**不用 Ctrl+拖**（n8n 也支持），因为 Ctrl 留给「绕过吸附」（tldraw 惯例）——修饰键一义一用 |
| 8 | 缩放 | ① Ctrl+滚轮（以光标为锚）② `+`/`-` 按档 ③ 裸滚轮=纵向平移、Shift+滚轮=横向平移 | 视口缩放/平移，档位 25–200% | 缩放控件百分比实时刷新 | 光标锚定缩放认知负荷最小（光标处内容不动）；裸滚轮给平移不给缩放——6 列主干常超出视口，纵向平移是高频刚需，误缩放比误平移恼人得多 |
| 9 | 适配视图 | 快捷键 1 / HUD「适配」 | 全图包围盒 + 80px 边距，缩放平移动画 240ms 到位 | 240ms ease-out | 打开文件默认 zoom to fit 是 Figma 的做法，新建/切换流程后也自动适配一次；80px 边距避免节点贴边 |
| 10 | 适配到选中 | 快捷键 2 | 选中包围盒 + 80px 边距 | 同上 | 30 节点极端规模下「只看选中的一段」是找回上下感的快捷方式 |
| 11 | 双击空白新建 | 双击画布空白 | 就地新建阶段节点，位置 round 到 20px 网格，自动进入重命名态 | 节点 160ms 淡入 + 描边呼吸一次 + 名称字段全选待输入 | 任务书已定。就地创建免去从面板拖出的距离；直接进重命名省一次双击——新建后的第一件事 90% 是起名 |
| 12 | 对齐吸附 | 拖动中自动；阈值 **6px**（屏幕像素） | 双轨：对齐参考线（与既有节点边缘/中线对齐）优先，其次 20px 网格；按住 Ctrl 临时全绕过 | 参考线 1px brand 虚线，同屏最多 2 条 | 6px 在 96dpi 屏 ≈0.5cm 视角：低于 4px 感知不到、高于 8px 会「抢光标」；参考线优先于网格是因为「与既有节点对齐」的意图强于「落在格子上」（tldraw 同序） |
| 13 | 自动整理 | 顶栏「整理」/ 空白右键「自动整理」 | **分层布局**：① 主干按开始→结束的最长路径排成向右的列 ② 同列垂直居中 ③ 列距 160px、行距 40px ④ 主干下方留 80px 打回航道净空 ⑤ 结束后自动适配（参数速查见 §5.2） | 节点 300ms ease-out 移动到位，按列 stagger 20ms；整理算一步撤销 | 本产品拓扑固定（DAG 主干+反向打回），分层是它的自然语言；**不用力导**（会把固定主干揉成球）、**不用纯网格**（不表达连线语义）。列距 160px：给连线标签与端口热区留横向余量 |
| 14 | 撤销/重做 | Ctrl+Z / Ctrl+Shift+Z（Ctrl+Y 兼容） | 按粒度表回退/重做（见 §5.3） | 被撤销对象 200ms 淡出/淡入；顶栏按钮禁用态同步 | 拖拽类操作必须有后悔药，否则画布编辑的容错为零 |
| 15 | 拖线非法提示 | 拖影线悬停在不能连的节点上（如连向开始节点入口、目标已有同源线） | 释放不生效；继续拖仍可换目标 | 目标节点 1.5px state-error 描边 + 拖影线变虚线 + 光标旁 12px 标签写**具体原因**（如 `不能连：开始节点没有入口`），160ms 出现 | 校验必须发生在尝试中而不是松手后；文案给具体原因而非「无效」（抄 n8n connect_nodes 校验语义：validation.error 要带 reason） |
| 16 | 连上游自动判打回 | 拖线释放在拓扑上游节点 | 线自动判为「打回」类型 | 落线瞬间 state-warn 色线体 + 「打回」标签 + inline toast `已按打回连线：方案 ← 开发` 2.5s；可 Ctrl+Z | 系统替用户做了类型决定，必须显式宣告。toast 写出方向（谁 ← 谁）让用户能一眼核对意图是否被理解对 |

### 5.3 撤销/重做粒度表（栈深 50，跨流程不共享，新操作清空重做栈）

| 操作 | 一步的内容 | 为什么 |
|---|---|---|
| 增/删单个节点或连线 | 1 个对象 | 与用户心智里的「一个动作」对齐 |
| 一次节点拖放 | 按下→释放全程 1 步（含吸附落位） | mousemove 入栈会一次拖动吃掉几十步，撤销就废了 |
| 框选后整体拖动 | 整组 1 步 | 一起动的要一起回来 |
| 批量删除（多选 Delete） | 整批 1 步 | 同上 |
| 重命名 / 检查器字段编辑 | 单字段**失焦提交** 1 步 | 每字符一步会把结构操作淹没在文本噪音里 |
| 自动整理 | 1 步 | 整理是单次显式动作 |

### 5.4 键盘快捷键全表

**设计原则：不用任何单字母快捷键。** 中文用户输入法激活时单字母会被 IME 吃掉产生歧义（n8n 的 D 停用/P 钉数据在本产品语境里不可复制）；功能键、数字、符号与 Ctrl 组合不受 IME 影响。

| 键 | 生效场景 | 动作 | 备注 |
|---|---|---|---|
| Tab / Shift+Tab | 画布焦点态 | 在节点间按图序循环（开始→阶段1→…→结束），焦点即选中 | 纯键盘可达路径（WCAG） |
| ↑↓←→ | 有选中 | 微移 20px（1 格） | 微移同样吸附对齐规则 |
| Shift+方向 | 有选中 | 微移 100px（5 格） | 抄 tldraw「1 格/5 格」节奏 |
| Ctrl+A | 画布 | 全选 | |
| Delete / Backspace | 画布有选中 | 删除选中节点与连线 | 输入框聚焦时失效（见冲突 1） |
| Ctrl+C / Ctrl+X / Ctrl+V | 画布 | 复制 / 剪切 / 粘贴（粘贴落点 +20/+20 偏移） | |
| Ctrl+D | 画布 | 原位副本（+20/+20 偏移，随即可拖） | 造平行阶段的最快路径 |
| Enter | 单选节点 | 打开/聚焦检查器对应分区 | 输入框内 Enter=提交字段 |
| F2 | 单选节点 | 进入重命名 | 功能键，无 IME 冲突 |
| Esc | 分层退出 | 见下方冲突 2 | |
| Space（按住） | 画布 | 平移模式（grab 光标） | preventDefault 防止误触按钮 |
| `+` / `=` | 画布 | 放大一档 | |
| `-` | 画布 | 缩小一档 | |
| `0` | 画布 | 回 100% | |
| `1` | 画布 | 适配全图 | |
| `2` | 画布 | 适配到选中 | |
| Ctrl+Z | 全局 | 撤销 | |
| Ctrl+Shift+Z / Ctrl+Y | 全局 | 重做 | |
| Ctrl+S | 全局 | 保存 | |
| Ctrl+Enter | 全局 | 运行（运行中无效） | textarea 内也触发——textarea 惯例就是 Ctrl+Enter 提交，不视为冲突 |

**冲突说明（必须实现，不是备注）：**

1. **Delete vs 输入框**：任何 `input / textarea / contenteditable` 聚焦时，Delete/Backspace/方向键/Ctrl+Z/Ctrl+C 全部归输入框，画布快捷键全部休眠（判定条件：事件 target 命中可编辑元素）。为什么：重命名到一半按 Delete 想删节点、结果只删了字符，是可恢复的小挫折；反过来（输入时误删节点）是灾难。防误删优先。
2. **Esc 的退出栈**（每次只退一层，按进入的逆序）：拖线进行中 → 取消拖线；节点拖动中 → 弹回原位；重命名中 → 恢复原名退出；右键菜单/问题列表浮层开 → 关闭浮层；<1100px 抽屉开 → 收抽屉；多选 → 退为单选；单选 → 清空选中。为什么：Esc 的语义是「退出当前模式」，模式是栈式的，一层一层退才不会一步把用户五个动作的上下文全抹掉。
3. **Ctrl+Z vs 输入框**：输入框内撤销是文本级撤销，**不冒泡**为结构撤销；想撤销结构先 Esc/点画布失焦。界限清晰比「智能冒泡」可靠。
4. **Space vs 按钮激活**：Space 进入平移模式时对画布容器 preventDefault，防止此刻恰好聚焦的顶栏按钮被 Space 触发。
5. **数字键 1/2/0 vs 重命名**：重命名是输入框场景，规则同冲突 1，自动覆盖。

### 5.5 空状态与异常态

#### ① 第一次打开（还没有流程）

| 元素 | 规格 |
|---|---|
| 左栏 | 模板列表（内置「六阶段研发流」卡片）+「+ 新建流程」按钮 32px 高全宽 |
| 画布 | 中央空态卡：64px SVG 线稿图示（三个小节点连成链的简笔图形，label-tertiary 描边）；主文案 20px/600 label-primary **「还没有流程」**；副文案 13px label-secondary **「从六阶段模板开始，两步就能看到第一张能跑的图」**；按钮组：`用模板创建` 120×36 brand 填充（视觉第一）+ `新建空白流程` 120×36 描边 ghost（视觉第二） |
| 顶/状态栏 | 运行按钮禁用（tooltip `还没有流程`）；状态栏 `节点 0 · 连线 0` |

为什么：首次用户的目标是「30 秒看到能跑的东西」而不是白手起家，所以模板路径按钮拿唯一的品牌色填充、文案直接承诺步数（「两步」是真实承诺）。

#### ② 流程为空（0 个节点，刚建了空白流程）

- 画布中央**轻提示**（非全屏卡）：30% 透明的虚线轮廓卡片（180×80）+ 一行 13px label-tertiary：**「双击画布任意位置，添加第一个节点」**。
- 网格照常显示；顶栏运行按钮禁用，tooltip **「缺少开始节点」**；状态栏 `节点 0 · 连线 0`。
- 为什么轻量：用户已在任务中，提示只指路不挡道；空态是画布的一层薄纱而不是另一块屏幕。

#### ③ 校验不通过（错误定位到节点）

三通道，缺一不可：

1. **状态栏**：`问题 2` 显示为 state-error，点击浮出问题列表浮层（宽 280px，每条 = 节点名 13px/600 + 问题句 13px + `定位` 文字钮）。
2. **画布**：出错节点右上角 8px state-error 圆点；hover 圆点显示同款问题句 tooltip。
3. **定位**：点问题条目或 `定位` → 画布 300ms 平移居中该节点 → 呼吸高亮 2 次（§4）。

文案格式统一为「对象——问题」，短、说人话、不出现错误码：

| 场景 | 文案 |
|---|---|
| 缺起点 | **缺开始节点——流程没有起点** |
| 打回指向下游 | **测试的打回指向了下游，打回只能往回连** |
| 孤立节点 | **代码审查没有连线，跑不到它** |
| 缺终点 | **没有结束节点，流程收不了尾** |
| 循环无出口 | **这条循环里没有能通过的出口** |

为什么：校验错误必须「一键到现场」；只给列表不给定位，是让用户自己找茬。文案不带「错误码 E-xxx」——码是给日志的，不是给人解决问题的。

#### ④ Host 连不上 / 保存失败

| 态 | 视觉 | 文案 |
|---|---|---|
| 连不上宿主 | 顶栏下横幅 36px，bg-layer-2 + 左缘 3px state-warn | **「连不上宿主服务。改动先存在本地，恢复后自动同步」** + `重试` 按钮；画布继续可编辑 |
| 保存失败（请求明确失败） | 同位置，左缘 3px state-error | **「保存失败。你的改动还在，已存本地副本」** + `重试` |
| 恢复成功 | 同位置，左缘 3px state-success | **「已恢复同步」**，2.5s 后自动收起 |
| 顶栏徽标联动 | 见 §2.3 四态 | — |

为什么：断连不是用户的错误，文案必须一次回答用户心里三问——**丢没丢**（没丢，在本地）、**现在能干嘛**（继续编辑）、**之后会怎样**（自动同步）。绝不写「网络异常请检查」这种把责任推给用户的话。

### 5.6 信息架构判断

#### 设计 / 运行：一个视图、两种状态（叠加态）

**判断：不做两套视图。** 理由：

1. **空间记忆**：用户刚在「测试」节点旁改过打回目标，运行时要能在同一位置找到它。切视图 = 丢掉「哪里有什么」的全部记忆，监督成本暴涨。
2. **任务书 §3.3 已把它定性为「叠加」问题**，不是重画问题。
3. **体量现实**：单文件 256KB 做不起两套画布渲染。
4. **先例**：LangGraph Studio 的 Graph mode 在同一张图上叠加节点遍历与中间状态，而不是为运行重画一张。

机制：运行开始 → 结构编辑锁定（§4 末行）→ 叠加层渲染执行态（当前节点动效描边、已完成路径高亮、执行 HUD——视觉归运行态模块）→ 平移/缩放/选中查看全程可用 → 结束或停止 → 回设计态，图上的位置一个都没动。**退出运行回到设计态时，视口位置也原样保留**（监督时放大到哪里，回去还在哪里）。

#### 从「新建流程」到「第一张能跑的图」：步数

| 路径 | 步骤 | 明细 |
|---|---|---|
| **模板路径（推荐动线）** | **2 步** | 点 `用模板创建`（空态卡第一按钮）→ 6 节点、5 条流转、典型打回全部预置 + 自动适配 → 点 `运行` |
| 空白路径 | ≈20+ 次操作 | 新建 → 双击建 6 个节点（每个顺带起名）→ 拉线 5–9 条 → 逐节点打开检查器配角色 → 运行 |

能不能更少：**2 步是底线。** 再压（比如打开面板就自动建好模板图）会剥夺「我确认要创建」的决策点——未经确认生成的图，用户不会当自己的东西对待（见 §6 反例 6）。真正该做的是压空白路径的**单步摩擦**：双击新建后自动进重命名（已定）、新建节点后左侧端口短暂高亮 1.5s 提示可拉线、检查器分区按使用频率排列（角色→任务→skill→模型）。步数压不掉，摩擦可以压到底。

## 6. 反例（明确不做的事）

1. **不做两套设计/运行视图。** 理由见 §5.6：空间记忆断裂 + 体量双倍。
2. **不用力导布局做自动整理。** 本产品拓扑固定（六阶段主干 + 指向上游的打回），力导会把「开始…结束」揉成毛线球；分层布局与领域语义一一对应。也不用纯网格对齐——网格不表达连线关系，整理完线还是乱的。
3. **不做命令面板（Ctrl+K）。** n8n 有，但它服务于上百个动作的全局搜索；本面板动作 ≤20 且每个都有直接手势。单文件 256KB 的预算应花在画布手感上。
4. **不做小地图。** 典型 6–12 节点、极端 30 节点，快捷键 1 一击全览、快捷键 2 聚焦选中段；小地图是常驻 UI + 双份同步渲染的体量大户，在这个规模收益为负。（有条件放弃：若 30+ 节点成为常态再评估。）
5. **不做「松手才校验」的连线。** 连不上必须在拖动过程中实时可见（§5.1-15），松手报错等于让用户完成一个注定失败的动作。
6. **不做「打开面板自动建图」。** 创建要留给用户一次显式确认（点 `用模板创建`），未经确认的产出不被信任；首次空态卡把模板路径做成视觉第一动线，2 步已经够短。
