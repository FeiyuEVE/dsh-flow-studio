## 1. 设计结论

1. **打回线与主干分道**：正常流转走上平面（贝塞尔软曲线），打回线一律走「主干下方专用航道」——
   正交折线（下降 → 水平 → 上升）、转角 r=10。软/硬两种线型本身就是类型区分，颜色只是辅助。
   航道按固定规则分配（§2.2），出厂模板 4 条打回可做到**仅 1 处可预期交叉**，交叉点用桥拱明示。
2. **打回线双态，一图两用**：虚线 = 结构（潜在的回退路径）；本次运行真实触发时转实线并叠加轮次刻度。
   设计态/运行态不画两张图，用同一条线的「线型 + 透明度 + 刻度」切换承载。
3. **返工计数三个口径、各标各处**（总案 §6 C11，定义与去重见 04 §4.2）：**边触发数**标在线上（`×n` 小刻度）、**目标返工数**标在目标节点的 `↺n` 角标、**源发起数**只进检查器与底部抽屉（不上节点卡）。
   三者不是同一个数的冗余编码，各有独立定义与去重规则；单看任一处只回答它自己那个问题，不能互相替代。
4. **主从节点是一张固定矩形卡（208×116）+ 常驻成员圆点行，成员编辑收进右侧检查器**。
   成员行默认可见；运行态**不重排几何**（只换行内内容：双环 / ✓ / ✕ 与状态文字，矩形和航道位置都不动）。不做内嵌子画布（ComfyUI 式），理由见 §6 反例 3；本版也不做半展开泳道与 144 展开变体。
5. **主管三阶段（拆任务 / 子在干 / 汇总）用三个通道区分**：脉冲位置（「主」chip vs 成员点）＋
   卡片左缘 3px 竖条颜色段 ＋ 状态行文字。颜色永不单独承担语义。
6. **通道分配一刀切**：位置 / 形状 / 连线几何归结构（运行时冻结），颜色 / 描边宽度 / 光晕 / 角标 / 动效归运行
   （结构不动，状态叠加）。唯一共享通道是「线型实/虚」，且语义自洽：虚=潜在，实=发生。
7. **身份与状态分家，但身份不用色相**：宿主没有 categorical 色板，成员识别用「形状（主=方 / 子=圆）+ 顺序 + 圆点内嵌首字 + 同一 business 色相的深浅梯度」（02 §4.4 的 B02 更正，原六色板已作废）；状态色只归运行态（唯一例外是打回线常态的 warn 类型色，见 §4.1）。色盲安全由形状 + 首字 + 文字兜底。

- **世界宽 2028**：8 列主干 = 7×260 + 208；6 列中间段 = 5×260 + 208 = 1508（用于 01 §2.2 的断点估算）。
- **间距刻度**：全模块只用 4 的倍数（4 / 8 / 12 / 16 / 24 / 28 / 32 / 52 / 56）。
- **列距 260**：节点 208 + 间隙 52。间隙 52 是正常流转贝塞尔与打回端口的共用呼吸区，不可压缩。
- **打回净空分两件事写**：① **第一条航道偏移 `LANE_OFFSET = 24`**（主干底缘 y=316 → T1 y=340）；② **六条满配总净空 196px**（T1 y=340 到航道区底 y=512 = 24 + 28×5 + 32）。旧口径「主干下 80px 起」把总净空误写成第一航道偏移，作废。
- 字号刻度（沿用宿主的模块化刻度）：**12（正文地板 = `--dsw-font-xxs-12`）/ 13 / 14 / 16 / 20**，行高 1.5；唯一例外是**非正文徽标**可用 11px（`--dsw-font-xxxs-11`，§2.4 已逐个标注），正文一律 ≥12px。

### 2.1 打回线的走线（单条线详图）

打回 = **三段正交折线**：源节点底缘出端口垂直下降 → 水平航道 → 垂直上升进目标底缘槽位。折线转角 r=10 是 SVG 路径的几何圆角，不是组件圆角，不受 `--dsw-radius-*` 档位约束；组件圆角一律用宿主 token。
放弃现版「一条大贝塞尔下兜」的走法（`rejectPath`：dip = max(56, 0.18·|dx|)，跨度越大弧越深，
四条弧互相套叠——任务书 §3.1 点名的「糊成一团」就是这么来的）。

```
        目标节点（上游，靠左）                                    源节点（下游，靠右）
      ┌──────────────────┐                                  ┌──────────────────┐
      │      开发         │                                  │      代码审查     │
      └─┬──┬──┬──┬──┬──┬─┘                                  └─┬──┬──┬──┬──┬──┬─┘
        ▲  ▲  ▲  ▲  ▲  ▲  入槽区（底缘左半，6 槽）          │  │  │  │  │  │  出端口区（底缘右半，6 口）
       s1 s2 s3 s4 s5 s6                                  p1 p2 p3 p4 p5 p6
      -88 -72 -56 -40 -24 -8                              +8 +24 +40 +56 +72 +88   （相对节点中心 x）
         ▲                                                     │
         │                                                     │ 垂直下降（先走 24px 到 T1，
         │r=10                                                 │  每深一条航道多走 28px）
         └────── 水平航道 Tk ──────────────────────────────────┘r=10
           ▲          ▲                          ▲
           │          │                          └─ 轮次刻度位：竖短棒 4×1.5px，间距 6，
           │          │                              一轮一根，最多 5 根，超出画「5+」
           │          └─ 标签 chip：中心位于「源下降点向目标方向 24%」处（靠源一侧，
           │              用户视线从刚被打回的源节点跟过来第一眼就碰到）
           └─ 箭头：画在上升段末端、入槽之前，7×8，方向朝上
```

**端口/槽位规则**（消除同节点多线的挤压）：

- 出端口区：底缘右半 **6** 个口位，x = 中心 +8 / +24 / +40 / +56 / +72 / +88（16px 步进）。
  **同一源节点有多条打回时，目标越靠左（回得越远）占越靠右的口位**（最远目标 → +88，依次 −16px 向内）。
- 入槽区：底缘左半 **6** 个槽位，x = 中心 −88 / −72 / −56 / −40 / −24 / −8（与出口镜像）。
  **同一目标节点有多条打回进入时，源列越靠右占越靠左的槽**（最远源 → −88，依次 −16px 向内）。
- 出/入严格分居左右两半，永不在同一 x 区间混用——这是「同一节点底部又出又进」时不糊的关键。
- 每侧只有 6 个槽：第 7 条起不新增槽位，按 §2.2 的确定性降级处理（并入最外航道），**不承诺任意手排位置下靠槽位消解全部重叠**。

### 2.2 多条打回线的航道分配（避让排序规则）

**分配规则（确定性算法，手排与 tidy up 都按它）：**

1. 把所有打回线按**全序排序键**排定：**①目标列升序 → ②同目标时源列降序 → ③同列并列按节点在流程图中的顺序（数组序，y 小者先）→ ④再按节点 id 字典序**。四层键保证同一张图每次得到同一结果，没有「并列未定义」。
2. 排第 1 的拿最深航道 T_max，依次向浅排：回得越远（目标越靠左）的线走得越深。
3. 同源多出口、同目标多入槽按 §2.1 的 6 槽规则排开；槽位顺序用同一 tie-break（③④），槽用完走 §2.2 末尾的降级。
4. 排序后仍存在的交叉（只剩「同列出入」与乱序模板两类）：在交叉点画**桥拱**——
   竖线连续、水平线断开留出 r=6 的半圆拱（电路图惯例，读作「跨越，不相交」）。

**适用范围（不承诺零碰撞）**：以上只能保证「同一输入 → 同一输出」与「四边单行出厂模板的交叉可枚举」；**不承诺任意手排位置下自动零碰撞**。用户把节点拖成同列多行、非列对齐时，交叉可以出现且未必能靠桥拱完全消解——此时以「桥拱 + 线型降级」兜底，并在状态栏提示「N 条打回线存在交叉」。不做全图自动避让（M10）。

**出厂模板验证**（4 条打回：方案↢需求、结构↢方案、测试↢开发、审查↢开发）：


**跨 4 个节点以上的长线怎么不糊**（如「审查↢需求」跨 5 列）：

1. 航道保证它与所有其他打回线**全程平行、间距恒 28px**——平行线是最好分离的图案；
2. 线宽恒 1.5px，**不用粗细表达跨度**（粗长线是视觉流氓）；
3. 跨度 ≥3 列时，水平段**中点**加一枚小号「↢ 需求分析」目标 chip（12px，`--dsw-font-xxs-12`，规格见 §2.4），
   视线走到半路也能接住「这条线回哪儿」；
4. 标签 chip 与目标 chip 都带不透明底色，盖断虚线，字不压线；
5. hover 任意打回线时，其余打回线透明度降到 0.25（聚焦规则，见 §5）；
6. 触发过的线上有轮次刻度，长线自带节奏，不是一根单调的灰线。

**打回线很多时**（>6 条 / 30 节点极端图）：

- 航道最多 6 条（T1–T6）：`24 + 28×5 + 32 = 196px`（T1 y=340 起、T6 y=480、航道区底 y=512），已到单行主干可接受的极限。
- 第 7 条起**确定性降级**（不新增航道、不新增槽位）：并入最外航道 T6，与已在该航道的线**并排双线**——两条 1px 线、间距 2px（替代 1.5px 单线）；**丢标签**（不画 chip，触发条件只在检查器里看）；在该航道水平段末端（靠目标一侧）画 `+N` 汇总角标（N = 并入该航道的超额线数），hover 角标列出「源 → 目标 · 轮次」清单。
- 降级顺序按 §2.2 的排序键：排在前面的线占 T1–T6 的整航道，排在后面的依次并入 T6；同一航道的双线按排序先后决定内外次序。
- 画布工具栏仍提供「打回线：全部 / 仅选中相关 / 收起」三态开关（>6 条或 30 节点时救命）：默认「全部」，降级线也在「全部」里按上述规则可见，不再需要 hover 单条才出现。

### 2.3 主从节点的固定尺寸（208×116）

```

        高 116 = 12 + 22 + 4 + 20 + 6 + 18 + 6 + 18 + 10

```

- **成员行默认可见**：不做「折叠 / 展开」两态，也不做本版的 144 展开变体（[DESIGN §6](../DESIGN.md) 已裁决）。旧稿的「折叠态 / 双击展开泳道 / 按成员数增高的卡高公式 / 整行重排、航道区下移」全部作废。
- **运行态不重排几何**：只替换成员行内容——在跑的成员点加 `state-business-primary` **双环**（静态；是否脉冲由 §3.5 的脉冲预算决定），完成的加右下 8px ✓，失败的换 `state-error-primary` 描边；矩形仍是 208×116，主干行高与航道区 y 坐标不变。成员逐项状态与耗时在检查器里看（§3.6）。
- **布局按矩形算**：世界边界里主从卡占 208×116（标准卡 208×96），列距仍 260、行距仍 40；同一行混排时按各自外接矩形（96 / 116）计入行高，不因状态变化重算。
- 成员上限：1 主管 + 最多 6 子 agent（检查器限制）。7 个活物一屏已经盯不住，超出就该拆成两个节点，这是设计立场不是技术限制。

## 3. 组件规格

### 3.1 打回连线（reject edge）

**结构**：出端口（底缘右半口位）→ 垂直下降 → r=10 转角 → 水平航道 → r=10 → 垂直上升 → 箭头（7×8，朝上）→ 入槽（底缘左半槽位）。
命中热区：路径两侧各 5px（总宽 10px 透明热区），保证 1.5px 细线可点。

| 状态 | 线型 / 线宽 | 颜色（token） | 透明度 | 附加 |
|---|---|---|---|---|
| 设计态常态 | 虚线 6·4 / 1.5px | `state-warn-primary` | 1 | 标签 chip 常驻 |
| 运行态·未触发 | 虚线 6·4 / 1.5px | `border-l3`（降级为中性灰） | 0.35 | 标签 chip 同步淡出 |
| 运行态·已触发 | 虚线 6·4 / 1.5px | `state-warn-primary` | 1 | 水平段画轮次刻度（§3.3） |
| 运行态·正在回退 | **实线** / 2px | `state-warn-primary` | 1 | dashoffset 流动 12px/s；箭头放大 1.25×；持续 0.5–2s 后回落「已触发」 |
| hover | 同前 / 2.5px | 同前 | 1 | 其余打回线透明度→0.25；两端端口/槽位出 4px 圆点 |
| 选中 | 同前 / 2.5px | `brand-primary` | 1 | 检查器打开打回配置；桥拱点同步高亮 |

正在回退的动效遵守 `prefers-reduced-motion`：降级为「实线 2px 静态，不流动」。

### 3.2 连线标签 chip（打回说明）

- 内容：检查器里「打回说明」字段。**建议 ≤8 字，硬上限 16 字**；chip 最大宽 120px，超出省略号，
  完整文案（连同 ≤64 字的触发条件详情）hover 时在 chip 下方展开第二行，两行总高 ≤40px（2×18 + 4）。
- 样式：12px = `--dsw-font-xxs-12`（12/18），`label-primary` 字；底 `bg-layer-2`（不透明，盖断虚线）；描边 1px `state-warn-primary` 40%（color-mix）；
  圆角 `--dsw-radius-xs`（4）；高 22（18 + 上下 padding 2），padding 2 8。
- 位置：水平航道段、距源下降点 24% 处；不与任何竖线段重叠（算法放置时避让端口 x ±24px）。
- **触发条件写不写？——写，但分两层**：短签常驻（「方案不满足验收标准」缩为「方案打回」由用户自写），
  全文进 hover 第二行与检查器。理由：条件是打回线的语义核心，完全不写就退化成纯几何装饰；
  但 64 字全文常驻 = 4 条长线 4 段文字，必糊。

### 3.3 轮次刻度（rail ticks）

```
标签 chip 左侧 8px 起，一轮一根竖短棒：

   ┌────────────┐
   │↢ 测试打回   │  |||        ← 3 根 = 已触发 3 轮
   └────────────┘
   棒：4×1.5px，间距 6；warn 色；最多 5 根，超出画「5+」（12px 字，`--dsw-font-xxs-12`）
```

- 刻度表达**边触发数**：「这条打回边本次运行累计触发了几次」（`×n`，标签 chip 左侧）；它**不等于**目标节点的 `↺n`（目标返工数）——一条边触发 3 次、目标只重跑 2 次是合法组合（如第 3 次被超限阻断）。源发起数只在检查器/底部抽屉。三者定义与去重见 04 §4.2。
- 新增一轮时最新一根刻度从 0 高度长到 4px（200ms，reduced-motion 下直接出现）。

### 3.4 节点卡片（标准 208×96 / 主从 208×116，本模块只定与语义相关的部分）

三类节点外形（结构通道，运行时不变）：

- **开始 / 完成**：胶囊形（stadium），宽 120，高 48，圆角 `--dsw-radius-panel`（28；CSS 在 48 高上钳到 24，等效胶囊），无端口区，不参与打回。
- **阶段节点**：圆角矩形（`--dsw-radius-sm` = 8），208×96；主从卡同宽、高 116（§2.3）。底部带打回端口/槽位区（视觉上是底缘两排 2×2px 小点，
  hover 时放大为可拖端口 Ø8）。

卡片内容层级（信息密度模块的总规矩，这里只列与语义有关的行）：
标题行（主 chip / 标题 / 执行方式徽标）→ 摘要行 → tag 行（skill×n、↺n、模型）→ 成员行（仅主从）。

**主从卡片的成员行**：见 §2.3。成员视觉区分：

| 维度 | 规则 |
|---|---|
| 形状 | 主管 = 16×16 方 chip（写「主」）；子 agent = Ø16 圆点（第一通道） |
| 文字 | 圆点内嵌成员名首字 12px = `--dsw-font-xxs-12`（第二通道，与检查器同字） |
| 顺序 | 固定按配置顺序（第三通道） |
| 颜色 | **不做色相区分**（同一 business 色相，只变深浅）：第 i 个成员底 = `color-mix(in srgb, var(--dsw-alias-state-business-primary) (10 + i×5)%, var(--dsw-alias-bg-layer-2))`，上限 35%；前景 `label-primary`，深底（≥20%）改 `label-primary-foreground` 并复验 ≥4.5:1（见 §4.4、02 §4.4） |
| 并/串行 | 本产品主从语义 = 主管拆活 → 子 agent **并行** → 主管汇总。成员行圆点**等距不连线**即并行；行左端画 12px「⋈」分叉符。未来若支持串行，圆点间画 6px 小箭头（本版不实现） |

### 3.5 主管三阶段的卡片表达（运行时）

| 阶段 | 「主」chip | 成员点 | 卡片左缘 3px 竖条 | 状态行文字 |
|---|---|---|---|---|
| 拆任务中 | `state-business-primary` 脉冲（透明度 1↔0.45，2s） | 全部灰 ○（`state-idle-primary`） | `state-business-primary` | 「主管：拆任务中」 |
| 子在干 | 静态 `state-business-primary` 描边（不脉冲） | 在跑=同色相梯度底 + `state-business-primary` 双环（**静态**；只有进入脉冲预算前 2 的节点才脉冲）；完成=梯度底 + 右下 8px ✓；失败=`state-error-primary` 描边 | `state-business-primary` 60% | 「子 agent：2/4 完成」 |
| 汇总中 | `state-business-primary` 脉冲（同拆任务） | 全部 ✓（静态） | `state-business-primary` | 「主管：汇总中」 |

> 三阶段刻意让「脉冲」在同一元素（主 chip）上复现：用户学会一次「主 chip 脉冲 = 主管在干活」即可。
> 竖条与文字是双兜底——脉冲被 reduced-motion 关掉后，竖条仍在。
>
> **脉冲预算（总案 §6 C14）**：同屏**同时脉冲的节点 ≤2 个**，按 **返工中 > 运行中 > 子 agent 完成** 的优先级取前 2；其余在跑节点（含其余成员点）一律**静态双环**，不脉冲；`prefers-reduced-motion` 时全部关闭。多成员并行不再各自脉冲——「子在干」不保证每个成员点都在脉冲。

### 3.6 与检查器 / 状态栏 / 指标块的接口（非本模块，只留接口约定）

- 选中打回线 → 检查器显示「打回说明（≤16 字）+ 触发条件（≤64 字）+ 目标节点 + 航道预览（选中线高亮）」。
- 选中主从节点 → 检查器成员列表：每成员一行（名 / 角色 / 任务 / 模型覆盖），与卡片成员行顺序一致、同一首字与深浅梯度。
- 状态栏（底栏）汇总**边触发数**：「本次运行打回 5 次（边触发）：测试↢开发 ×3，审查↢开发 ×2」——与航道刻度同源。
- 指标看板（模块 04）消费同源 `attemptId`，但按三个口径分开展示（边触发数 / 目标返工数 / 源发起数，04 §4.2）；**源发起数只进检查器与底部抽屉**，不在画布节点卡上重复展示汇总数字。

## 4. 状态与流转的可视化规则

### 4.1 通道分配表（本模块的宪法）

| 视觉通道 | 分配给 | 结构层用法 | 运行层用法 |
|---|---|---|---|
| 位置（x/y/列位/航道 y） | **结构**（冻结） | 列位 = 阶段顺序；航道 = 打回拓扑 | 🚫 运行态永不移动任何元素 |
| 形状（胶囊/圆角矩形/方圆点） | **结构** | 开始结束 = 胶囊；阶段 = 矩形；主 = 方、子 = 圆 | 🚫 |
| 连线几何（贝塞尔/正交折线/桥拱） | **结构** | 软曲线 = 正常流转；硬折线 = 打回 | 🚫 |
| 线型（实线/虚线） | 共享 | 虚线 = 打回（潜在路径） | 激活的打回线转实线（潜在→发生），语义自洽 |
| 颜色（色相） | **运行**优先 | 结构只用中性色（`border-l3/l4`、`label-secondary`）；唯一例外：打回线常态用 warn 色——它同时是「类型色」与「警示色」，属有意为之 | 状态色全部归运行层：`state-business-primary`=在跑、`state-success-primary`=通过、`state-warn-primary`=打回/警示、`state-error-primary`=失败；**选中**另用中性的 `brand-primary`（近黑/近白），与运行蓝必须可区分 |
| 线宽 | **运行** | 恒 1.5px（>6 条降级时最外航道用 1px 双线，见 §2.2） | hover 2.5 / 正在回退 2 |
| 描边光晕 | **运行** | 无 | 运行中节点专属：外扩 6px，`state-business-primary` 25%（color-mix） |
| 角标 | 共享 | 执行方式徽标「单/主从N」（结构信息） | 状态图标角标 + ↺n 轮次徽标 |
| 填充 | 结构为主 | `bg-layer-1` | 仅允许弱染色：完成 = success 8%、失败 = error 8%（tint，不大块换色） |
| 动效 | **运行**（瞬时） | 🚫 结构零动画 | 全产品只允许 3 处：运行中脉冲（2s 循环）/ 打回线流动（0.5–2s）/ 角标弹跳（300ms）；脉冲同屏 ≤2 并按「返工中 > 运行中 > 子 agent 完成」取前 2，其余静态双环；全部遵守 reduced-motion |
| 文字 | 双兜底 | 标题/摘要/tag | 状态行、耗时、轮次（任何颜色表达的信息必须同时有文字版） |

一句话：**运行时结构冻结，状态只做叠加**。用户不需要在「设计视图」和「运行视图」之间做任何脑内对齐。

### 4.2 阶段节点八状态编码表

| 状态 | 描边 | 填充 | 光晕 | 角标（右上 Ø18） | 动画 | 状态行文字（tag 行） |
|---|---|---|---|---|---|---|
| 待执行 pending | `border-l3` 1.5px | `bg-layer-1` | 无 | 无 | 无 | 「待执行」 |
| 运行中 running | `state-business-primary` 2.5px | `bg-layer-1` | 6px `state-business-primary` 25% | ● 蓝（预算内脉冲，其余静态） | 描边透明度 1↔0.6，2s 循环（仅脉冲预算前 2） | 「运行中 12:34」（计时每秒走） |
| 返工中 reworking（= 被打回目标的再次运行，running 变体） | `state-business-primary` 2.5px | `bg-layer-1` | 6px `state-business-primary` 25% | ↺ warn 色 | 同上 | 「第 2 轮返工 · 00:47」 |
| 通过 passed | `state-success-primary` 1.5px | success 8% tint | 无 | ✓ 绿底白字 | 无 | 「完成 · 用时 8:12」 |
| 被打回 rejected（产物被拒，即将回退的源节点） | `state-warn-primary` 2px | `bg-layer-1` | 无 | ↺ warn 底 | 无 | 「已打回 → 需求分析」 |
| 失败 failed | `state-error-primary` 2px | error 8% tint | 无 | ✕ 红底白字 | 无 | 「失败 · 查看日志」 |
| 跳过 skipped | `border-l3` 1.5px 虚线描边（dash 4·3） | `bg-layer-1` 60% 透明 | 无 | ⊘ 灰 | 无 | 「已跳过」 |
| 打回超限待人工 blocked | `state-error-primary` 2px 虚线描边 | error 8% tint | 无 | ⏸ 红 | 无 | 「打回 2/2 · 待人工裁决」 |

规则：**每个状态至少两个非颜色通道**（描边宽度/线型/角标形状/文字），任何状态下截图转灰度仍可分辨。
开始/完成节点只有三态：待 → 在 → 完，编码从简（无角标，仅描边 + 文字）。

**选中不是第九态**：选中用中性 `brand-primary` 2px 描边（01 §4），运行/返工用 `state-business-primary`；两者在亮暗两套主题下都必须一眼分开，否则「我选中了它」和「它在跑」会混。

### 4.3 一次打回的完整视觉时序（运行态）

```
T0  源节点 running（蓝描边脉冲）
T1  判定打回：源节点 → rejected（黄描边 + ↺角标）；打回线从「未触发 0.35 灰」→「正在回退」
    （实线 2px + 流动 + 箭头 1.25×）
T2  0.5–2s 后：打回线回落「已触发」（虚线 + 线上刻度 +1 = 边触发数，最新刻度 200ms 长出）；
    目标节点 ↺n 角标 +1（目标返工数）并弹跳（scale 1→1.25→1，300ms）；中间节点 → passed（绿 + ✓）
T3  目标节点 → reworking（蓝描边 + ↺角标 + 状态行「第 2 轮返工」）
T4  若已达该节点打回上限：源节点 → blocked（红虚线描边 + ⏸ +「待人工裁决」），
    打回线不再激活，整图运行暂停在该节点
```

读法检验：暂停截图，「开发累计返工 2 次」看开发卡 `↺2`（目标返工数）；「测试↢开发这条边触发 3 次」看该线刻度 `×3`（边触发数）；「开发发起了几次打回」去检查器/抽屉（源发起数）。三者**不要求相等**，各自回答各自的问题（04 §4.2）。

### 4.4 色盲与暗色模式

- **状态色全部用宿主 token**：运行/返工 `state-business-primary`、通过 `state-success-primary`、打回/警示 `state-warn-primary`、失败 `state-error-primary`；**选中不是状态**，用中性的 `brand-primary`（近黑/近白）。亮暗切换与对比度由宿主保证，本模块不自设任何 hex。
- **成员身份不用色相**（B02 更正，02 §4.4 已作废原六色板）：宿主没有 categorical 色板，自设 12 个 hex 违反 token 硬约束。改为三条通道叠加：

| 通道 | 做法 |
|---|---|
| 形状 | 主管 = 16×16 方 chip「主」；子 agent = Ø16 圆点 |
| 首字 | 圆点内嵌成员名首字，12px = `--dsw-font-xxs-12`；检查器成员卡用同一首字 |
| 同色相梯度 | 第 i 个成员底 = `color-mix(in srgb, var(--dsw-alias-state-business-primary) (10 + i×5)%, var(--dsw-alias-bg-layer-2))`，上限 35%；前景 `label-primary`，深底（≥20%）改 `label-primary-foreground` 并复验 ≥4.5:1 |

  验收口径：梯度底与 `bg-layer-1` 的边界对比 ≥3:1（图形件）；同一卡片内相邻成员的混合比例差 ≥5 个百分点，且首字/顺序可独立识别。**不承诺**靠颜色一眼认出「谁是谁」——成员通常 2–4 个，位置 + 首字比色相记忆更稳。
- **双编码硬规则**（来自 ux 规则库 color-not-decorative-only / Color Only）：颜色表达的一切必须同时有
  图标 / 形状 / 线型 / 文字之一。红绿色盲用户靠「✓ vs ✕ 角标 + 文字」零损失读图。
- **暗色模式**：光晕用 `color-mix(in srgb, var(--dsw-alias-state-business-primary) 25%, transparent)` 自动适配；
  成员梯度混的是 `bg-layer-2`，底色随主题自动反相，无需另设暗色组；若验收脚本发现对比跌破 3:1，按 02 §4.5 的主题分支兜底处理。
- **reduced-motion**：三处动效全关——脉冲→静态光晕；流动→静态实线；弹跳→直接 +1。

| 触发 | 结果 |
|---|---|
| hover 打回线（10px 热区） | 该线 2.5px 高亮；其余打回线透明度 0.25；两端口位出 Ø4 圆点；标签 chip 展开完整触发条件第二行 |
| 点击打回线 | 选中（中性 `brand-primary` 描边；不是运行蓝）；检查器打开打回配置；再次点击空白处取消 |

| 双击主从卡成员行 | 打开检查器「成员」分区；不展开卡、不改矩形（§2.3） |
| 单击成员圆点 | 检查器定位到该成员配置（不改变卡片矩形） |
| 双击空白处 / 从端口拖线 / Delete | 沿用现版（新建节点 / 连线自动判方向 / 删除选中），打回线与正常线一致可删可撤销。**仅设计态**：运行/返工中全部禁用并提示原因（01 §4 结构锁定，总案 §6 C12） |
| 主从卡成员行 | 常驻可见，无展开/收起开关；运行态只换行内内容（脉冲 / ✓ / ✕ / 文字） |
| 工具栏「打回线：全部/仅相关/收起」 | >6 条打回或 30 节点时手动收；「仅相关」= 仅显示选中节点出入的打回线 |
| `prefers-reduced-motion` | 关闭脉冲/流动/弹跳，静态替代（§4.4） |
| 空状态：无任何打回线 | 航道区不占位（高 0），画布下方不留死空间 |
| 空状态：单 agent 节点 | 成员行整行不渲染（不是渲染一行空点） |
| 错误态：打回目标不在上游 | 连线立即回弹不成立；底栏校验 error 条目可点击定位（现版已有，保留） |
| 错误态：打回超上限 | 源节点 blocked（§4.2），状态行「待人工裁决」，检查器给「忽略并继续 / 终止」两个动作 |

## 6. 反例（明确不建议做的 5 件事）

1. **不要把打回线画成与主干同平面的自由弧线/大贝塞尔**（含现版 `rejectPath` 的下兜弧线方案）。
   弧线深度随跨度增长，四条弧互相套叠、交点不可预期、标签只能放弧中点互相打架——这正是任务书 §3.1
   点名的现状。打回必须与主干**分道**（下航道 + 正交折线），让交叉从「不可控」变成「可枚举、可桥接」。
2. **不要用常驻动画表达状态或进度**（常转圈、常流动的线、呼吸的一整排节点）。
   4 条打回线同时流动 = 画布无法阅读；「动得多快」无法量化进度。动效只做瞬时反馈
   （本方案全产品只留 3 处，且 reduced-motion 全关）；进度靠文字（12:34）、轮次刻度、状态色。
3. **不要为「主管+子 agent」做节点内嵌子画布**（双击进入一张可缩放连线的小图，ComfyUI subgraph 式）。
   单文件 262KB、零 UI 库的约束下，第二套画布上下文（缩放/连线/命中/撤销）不可维护；
   且展开会撑破主干行布局，「一屏看清主干」立即失效。固定 208×116 卡 + 常驻成员行（§2.3）用 5% 的复杂度拿到
   「看得见谁在跑」这 80% 的价值；成员编辑本来就该在检查器（任务书已定三栏结构）。
4. **不要给成员分配状态色系当身份色**（老大绿、老二黄、老三红）。
   运行时身份与状态必然撞色：绿点到底是「老二」还是「已完成」？本方案**身份完全不用色相**（§4.4），
   只靠形状 + 顺序 + 首字 + 同一 business 色相的深浅梯度。
5. **不要用颜色单独表达任何状态**（只把描边变红就算失败、只把线变灰就算未触发）。
   红绿色盲 + 暗色模式 + 截图转发三个场景都会丢信息。每个状态至少两个非颜色通道（§4.2 表已强制执行：
   描边宽度 / 线型 / 角标形状 / 状态行文字）。

### 附：一句话决策卡（贴墙版）

- 打回 = 下航道正交折线，虚线；排序：目标列升序、同目标源列降序；同列出入留桥拱。
- 打回触发 = 虚转实 + 线上刻度 +1（边触发数）+ 目标 ↺n 弹跳（目标返工数）；超上限 = 红虚线 + ⏸ + 待人工。
- 主从 = 固定 208×116 卡（▣主 + Ø16 首字圆点 ≤5 +「+n」），成员行常驻；编辑去检查器，运行态不改矩形。
- 运行态只许动：颜色 / 线宽 / 光晕 / 角标 / 三处瞬时动效 / 文字；位置形状几何冻结。
- 身份不用色相，身份 ≠ 状态；任何状态都有非颜色通道。
