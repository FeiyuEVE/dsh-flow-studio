## 一、设计结论

1. **节点卡片运行时最多显示 2 个「自由数字」（耗时 + 一个状态数字）+ 1 个固定格式徽标（skill x/y）+ 1 条 3px 构成条（token 三段）**。再多一律进 hover 或右侧检查器——因为人在 200ms 内扫一眼能可靠读出的独立数字就是 2 个左右，第 3 个开始需要逐一看，扫描成本陡增。
2. **单节点指标走右侧检查器，整次 run 的聚合走底部抽屉**，hover 卡片只是检查器内容的「只读预览」。不用在画布上堆数字，也不为单节点开二级页。
3. **指标看板放在画布底部的可折叠抽屉（40px 收起 / 200px 展开）**，运行中和运行结束时自动展开。四个候选里只有它不遮画布、不动三栏结构、又让「图和指标同屏」。
4. **不做「设计 / 运行 / 指标」顶部 Tab**。Tab 把聚合数字和画布拆到两个视图，直接违反「运行时要在图上看到现在在哪、卡在哪」这条核心需求。
5. **所有指标统一 tabular-nums（等宽数字）+ 1Hz 更新节流 + 200ms 克制过渡**，数字变而不抖、跳而不刺眼；长跑任务的「活着感」主要靠节点描边上的流动虚线，不是靠数字狂跳。
6. **审查缺陷这类带列表的数据，在小空间用「堆叠分布条 + 总数 + P0 数」表达**，完整列表只在右侧检查器展开，绝不在抽屉里逐行铺开。
7. **一句话结论用一张确定的判定表生成**，颜色映射到语义态（优=success / 良=success / 可=warn / 需返工=warn / 失败=error），不靠模型自由发挥。

## 二、布局与尺寸

### 2.1 总体布局

宿主外壳占满中间主区，本面板是三栏。指标看板是「第四块」——贴在**中间画布列的底部**，不压左侧流程模板列表、也不压右侧检查器。

```
┌──────────┬────────────────────────────────┬────────────┐
│ 流程模板 │        画布（可缩放平移）          │  检查器      │
│ 列表    │                                  │ (选中节点/  │
│ 220px   │                                  │  连线才有)   │
│         │                                  │  280px     │
├──────────┼────────────────────────────────┼────────────┤
│          │  ▔▔▔▔ 底部指标抽屉 ▔▔▔▔▔         │            │
│          │  40px 收起 / 200px 展开          │            │
└──────────┴────────────────────────────────┴────────────┘
```

- 抽屉只属于「画布」这一栏：展开时压缩画布垂直空间，但不影响左、右两栏的滚动与内容。
- 中间主区典型高约 900px；抽屉展开 200px 后画布仍剩约 700px，6–12 节点主干完整可见，30 节点靠缩放/平移仍可操作。

### 2.2 尺寸刻度

| 项目 | 数值 |
|---|---|
| 阶段节点卡片（缩放 1.0） | 220 × 96px |
| 开始 / 结束节点 | 120 × 48px（胶囊） |
| 卡片圆角 | 8px（`--dsw-radius-*`） |
| 卡片内 padding | 12px |
| 卡片描边（设计态） | 1px `border-l2` |
| 卡片描边（运行态） | 1.5px 语义色 |
| 节点角标（耗时/回环） | 高 20px，胶囊 |
| token 构成条 | 卡片底部，高 3px，段间 1px 缝 |
| 抽屉·收起态 | 高 40px（把手条） |
| 抽屉·展开态 | 高 200px（40 把手 + 160 内容） |

| 运行摘要条 | 高 48px，一行 |
| 迷你 stat 单元 | 最小宽 72px，stat 间距 16px |
| 缺陷分布条 | 高 12px，全宽 |

### 2.3 字号与行高

| 用途 | 字号/行高 | 变量 |
|---|---|---|
| 摘要条主数值 | 18px / 20px | `label-primary` |
| 摘要条副标签 | 11px / 14px | `label-tertiary` |
| 节点角标数字 | 11px / 20px，tabular-nums | `label-secondary` |
| 节点标题 | 13px / 20px | `label-primary` |
| 节点角色摘要 | 11px / 16px | `label-tertiary` |
| 检查器指标主值 | 20px / 24px | `label-primary` |
| 检查器指标单位/副文本 | 12px / 16px | `label-secondary` |

> 所有会变的数字（耗时、token、计数、比例）一律 `font-variant-numeric: tabular-nums`，保证数字跳动时**只变数值、不左右挪位**。

### 2.4 运行摘要条：48px 里塞 6 个数字怎么不挤

48px 高的一行，横向放 6 个迷你 stat，每个是「2px 语义色竖条 + 副标签 + 主数值」两行结构：

```
┌───┬──────────┬──────────┬──────────┬──────────┬──────────┬──────────┐
│   │ ▎42.3s    │ ▎12.3k    │ ▎5/6      │ ▎0        │ ▎78%      │ ▎7/9      │
│   │ 总耗时    │ 总 token  │ 完成度    │ P0 缺陷   │ 意见采纳  │ skill 采纳 │
└───┴──────────┴──────────┴──────────┴──────────┴──────────┴──────────┘
    ↑ 2px 竖条   ↑ 18px 主数值        ↑ 11px 副标签（可 ellipsis）
```

不挤的三条硬规则：

1. **副标签 11px 不换行**，超出 `ellipsis`；主数值 18px 是上限，不再往上加。
2. **每个 stat 用左边 2px 语义色竖条做类别锚点**（token=brand / 耗时=中性 / 缺陷=error / 质量=success），色条不占横向宽度，却能让人不用读标签就定位到「缺陷」那一列。
3. **6 个 stat 的最小总宽 512px**（6×72 + 5×16），在约 1200px 宽的画布列里绰绰有余；画布列窄于 640px 时，摘要条自动缩到只显示前 4 个（总耗时 / 总 token / 完成度 / P0），其余收进「…」展开。

## 三、组件规格

### 3.1 通用指标块结构

每个指标块（迷你 stat、检查器指标行）都用同一套结构：

```
┌──────────────────────────────┐
│▎ 副标签（11px, tertiary）      │   ← 2px 语义色竖条做类别锚点
│  42.3 s  ↑                   │   ← 18px 主数值 + 单位；↑↓ 是变化指示
└──────────────────────────────┘
```

**内容规格字段**（每个指标块必须回答的六件事）：

| 字段 | 定义 |
|---|---|
| 标题 | 副标签文案，中文，≤6 字 |
| 主数值 | 最显眼的那个数，tabular-nums |
| 副文本 | 主数值下方的补充说明（如缓存命中率、常态参考） |
| 单位 | s / 个 / 次 / % / k token |
| 变化指示 | 相对上次刷新或上次运行的 ↑ / ↓，累计单调量（token、耗时）默认隐藏，仅异常跳变（单次刷新 +5%）才亮 |
| 空数据态 | 未运行时显示「—」占位，不显示 0（0 是有意义的数字，别和空混淆） |
| 异常态 | 超过阈值时主数值换语义色 + 图标，见各指标具体规则 |

**状态规格表**（沿用 design-system 的 Property / Default / Hover / Active / Disabled 四列）：

| Property | Default | Hover | Active | Disabled |
|---|---|---|---|---|
| 背景 | 透明 / `bg-layer-1` | `interactive-bg-hover` | 同 Hover | `bg-layer-1`，opacity 0.5 |
| 主数值 | `label-primary` | 不变 | 不变 | `label-tertiary` |
| 副标签 | `label-tertiary` | `label-secondary` | 不变 | `label-tertiary` |
| 语义竖条 | 2px 类别色 | 不变 | 不变 | `border-l2` |
| 描边 | 无 | 无 | 无 | 无 |

### 3.2 运行摘要条（整次 run 的 6 个数字）

| 标题 | 主数值 | 副文本 | 单位 | 变化指示 | 空数据态 | 异常态 |
|---|---|---|---|---|---|---|
| 总耗时 | 42.3 | 运行时走秒，结束定格 | s / m | 运行中走秒（最强「活着」信号） | 「—」 | 超预期 P90×1.5 变 error + ⚠ |
| 总 token | 12.3 | 缓存命中率 51% | k | 默认隐藏 | 「—」 | 单节点超常态见 3.6 |
| 完成度 | 5/6 | 通过阶段数 / 总阶段数 | — | 相对上次 run ↑↓ | 「—」 | 有失败时变 error |
| P0 缺陷 | 0 | 后接 P1/P2 数 | 个 | 默认隐藏 | 「—」 | >0 变 error |
| 意见采纳 | 78% | 采纳意见数 / 总意见数 | % | 相对上次 run ↑↓ | 「—」 | <40% 变 warn |
| skill 采纳 | 7/9 | 实际加载 / 声明总数 | — | 默认隐藏 | 「—」 | 有节点 0 加载变 warn |

> 摘要条只放「整次 run 的聚合」，不逐节点；单节点数字在图上角标和右侧检查器里。

### 3.3 节点卡片：图上最小化表达

节点卡片运行时在**设计态基础上叠加**，不重画结构（任务书 §3.3）：

```
┌──────────────────────────────────────┐
│ ↻2                            ▎ 42s  │  ← 左上回环角标 / 右上耗时角标
│  方案设计                             │
│  资深架构师 · 产出设计文档            │
│  🧩 2/3 skills                       │  ← skill 采纳徽标（3 声明，2 实际）
│                                      │
│▎▎▎▎▎▎▎▎▎▎▎▎▎▎▎▎▎▎▎▎▎▎▎▎▎▎▎▎▎▎▎  │  ← 3px token 构成条
└──────────────────────────────────────┘
  ↑ 左侧 2px 竖条：缺陷语义色（缺陷>0 时 error，否则不显示）
```

**卡片上最多显示的东西（硬约束）**：

| 类型 | 内容 | 规则 |
|---|---|---|
| 自由数字 ×2 | ① 耗时（右上角，永远有）；② 状态数字（回环轮次 或 缺陷数，取更紧急的那个） | 第 3 个自由数字一律禁止 |
| 比例徽标 ×1 | skill 采纳「x/y」（实际加载 / 声明） | 固定格式、固定位置，不算自由数字 |
| 构成条 ×1 | token 输入 / 输出 / 缓存命中三段 | 只给比例感，不标具体数 |

**为什么是 2 个自由数字**：① 人在 200ms 扫视里可靠读出的独立数字约 2 个，第 3 个开始需要逐个盯，扫描从「瞥一眼」退化成「读一遍」；② 极端 30 节点时卡片缩小、角标字号压到 11px 以下，2 个以上会互相挤压换行，破坏卡片高度对齐；③ 状态色（描边/竖条）是 pre-attentive 的，不占「数字槽」，2 个数字 + 状态色已经能回答「这个节点现在怎么样」的 90%。

**角标状态规格**：

| Property | Default | Hover | Active | Disabled（跳过） |
|---|---|---|---|---|
| 背景 | `bg-layer-2` | `interactive-bg-hover` | 同 Hover | 透明 + 虚线描边 |
| 文字 | `label-secondary` | `label-primary` | 不变 | `label-tertiary` |
| 耗时角标内容 | 运行中走秒（42s），结束定格（3:12） | 无额外 | 无 | 「—」 |
| 回环角标内容 | 「↻ n」，仅 n>0 显示 | tooltip「打回 n 次」 | 无 | 不显示 |

**token 构成条**（3px 高，三段，段间 1px 缝）：

| 段 | 颜色 | 语义 | 色盲补救 |
|---|---|---|---|
| 输入 | `brand-primary` | 输入 token | 位置固定在最左 + hover tooltip |
| 输出 | `state-success` | 输出 token | 位置固定中间 |
| 缓存命中 | `label-tertiary` | 缓存命中（复用，无成本） | 位置固定最右 + 中性灰 |

> 构成条不标具体数字，hover 时 tooltip 报「输入 4.2k · 输出 1.8k · 缓存命中 6.0k」。它借的是 Grafana stat 面板 sparkline 的思路——**数字是主角，条只是给比例感的背景**——但这里条表达的是「构成」而非「趋势」。

**缺陷竖条**（卡片左侧 2px）：

| Property | 无缺陷 | 有缺陷 |
|---|---|---|
| 显示 | 不显示（干净） | 2px `state-error-primary` |
| 数字 | — | 缺陷总数并入「状态数字」槽（与回环轮次二选一，取更紧急的） |

### 3.4 审查缺陷：带列表的数据在小空间怎么表达

小空间（摘要条 / hover）**只给分布条 + 总数 + P0**，不给列表：

```
缺陷 12        P0 0 · P1 3 · P2 9
███████████████████████████████░░░░
└─ P0(error)──┘└─P1(warn)─┘└─P2(中性)─┘
        12px 高堆叠条，段宽按数量比例
```

| 段 | 颜色 | 说明 |
|---|---|---|
| P0 | `state-error-primary` | 发布阻塞项，>0 直接进异常态 |
| P1 | `state-warn` | 需关注 |
| P2 | `label-secondary` | 建议级 |

- **色盲补救**：段间 1px 缝 + 固定左→右 P0→P1→P2 顺序 + hover 逐段 tooltip「P1 · 3 个」，不靠颜色单独传义。
- **完整列表只在右侧检查器**的「审查」区展开：每条缺陷一行（严重级徽标 + 标题 + 所在节点 + 是否被采纳），采纳的给 success 勾、未采纳给中性点。抽屉里永不逐行铺缺陷列表——那会把 160px 内容区撑爆。

### 3.5 抽屉把手条（收起态 40px）

```
┌──────────────────────────────────────────────────┐
│  ◔ 指标   上次运行：42s · 12.3k token · 通过      ⌄ │
└──────────────────────────────────────────────────┘
  ↑ 16px 图标    ↑ 12px 摘要    ↑ 12px 箭头（⌄展开/⌃收起）
```

| Property | Default | Hover | Active | Disabled |
|---|---|---|---|---|
| 背景 | `bg-layer-2` | `interactive-bg-hover` | 同 Hover | `bg-layer-2` |
| 上边框 | 1px `border-l2` | `border-l3` | 不变 | 不变 |
| 摘要文字 | `label-secondary` | `label-primary` | 不变 | `label-tertiary` |
| 箭头 | `label-tertiary` | `label-primary` | 旋转 180°（展开时） | 不显示 |
| 高度 | 40px | 40px | 40px | 40px |

- **把手条永远可见**（哪怕收起），所以「上次运行结果」这个最关键的回看信息始终有一行可扫。
- 未运行时空数据态：把手条显示「尚未运行」，不显示占位数字。

### 3.6 右侧检查器·运行态区

选中一个节点时，检查器从「配置」切到「运行态」分页（用检查器顶部的分段控件「配置 / 运行」切换，默认落在「运行」当任务在跑）：

| 区块 | 内容 | 形态 |
|---|---|---|
| 状态头 | 节点名 + 状态徽标 + 耗时 + 打回轮次 | 一行 |
| token | 输入 / 输出 / 缓存命中三个指标块 + 合计 | 三个迷你 stat 竖排 |
| skill 采纳 | 逐行列出每个声明 skill：实际加载几次 / 声明几次 | 列表，行高 32px |
| 审查缺陷 | 缺陷分布条 + 逐条缺陷列表（标题/位置/是否采纳） | 分布条 + 列表 |
| 质量 | 编码规范符合 / 测试通过率两个指标块 | 两个迷你 stat |

> 检查器指标主值 20px，是「要看全」的地方；画布角标是「扫一眼」的地方；两者信息同源，不打架。

## 四、状态与流转的可视化规则

### 4.1 节点六态

| 状态 | 描边 | 填充 | 角标 | 补充 |
|---|---|---|---|---|
| 待执行 | 1px `border-l2` | `bg-layer-1` | 无 | 标题 `label-tertiary`，弱化 |
| 运行中 | 1.5px `brand-primary` + 流动虚线 | `bg-layer-2` | 耗时走秒 | 虚线沿轮廓流动，方向=数据流 |
| 通过 | 1.5px `state-success` | `bg-layer-1` | 定格耗时 | 左上角一个对勾微标 |
| 被打回 | 1.5px `state-warn` | `bg-layer-2` | 回环「↻ n」 | 打回线同时高亮 |
| 失败 | 1.5px `state-error-primary` | `bg-layer-2` | 定格耗时 + ⚠ | 节点标题变 error |
| 跳过 | 1px `border-l2` 虚线 | 透明 | 「—」 | 整卡 opacity 0.5，标题划线 |

### 4.2 打回轮次怎么显示

- 卡片左上角「↻ n」，n = 该节点被打回的累计轮次；n=0 不显示。
- 打回连线用 `state-warn`，线粗 1.5px，回环方向从下游节点下方走「专用打回航道」（这是另一模块 §3.1 的活，本模块只负责**数字**：轮次标在被打回的源头节点上，不在线上标数字）。

### 4.3 完成后的复盘视图

run 结束，抽屉自动展开到 200px，摘要条定格、节点描边定格。用户最想先看的 3 个数字（按序）：

| 序 | 数字 | 理由 |
|---|---|---|
| 1 | 完成度（通过 x/y 或 失败） | 唯一能立即回答「做完了吗、要不要行动」的数字 |
| 2 | P0 缺陷数 + 意见采纳率 | 「质量行不行」的代理；P0 是发布阻塞，采纳率说明审查是否真起了作用，最可能触发返工 |
| 3 | 总 token / 总耗时 | 成本与效率；前两项没问题时它才有意义 |

**「这次 run 好不好」一句话结论自动生成规则**（按序判定，命中即返回，颜色映射语义态）：

| 判定条件（自上而下，第一个满足的生效） | 结论文案 | 颜色 |
|---|---|---|
| 任一阶段失败 | 「失败：{阶段名} 未通过」 | `state-error-primary` |
| 完成度 < 100% | 「未完成：通过 {x}/{y} 阶段，{z} 个阶段被打回」 | `state-warn` |
| P0 缺陷 > 0 | 「需返工：审查发现 {n} 个 P0 缺陷」 | `state-warn` |
| 完成度 100% 且 返工 ≤1 且 P0=0 且 采纳率 ≥60% 且 测试通过率=100% | 「优：一次通过，质量达标」 | `state-success` |
| 完成度 100% 且 P0=0 且 返工 ≤2 | 「良：通过，返工 {n} 轮」 | `state-success` |
| 其余（通过但返工多 / 采纳率低 / P1P2 堆积） | 「可：通过，但返工 {n} 轮、遗留 {m} 个缺陷，建议复盘」 | `state-warn` |

> 规则是确定性的：阈值（返工 1/2 轮、采纳率 60%、P0=0、测试 100%）写死在判定表里，不交给模型自由措辞，保证同一 run 每次给同一结论。

## 五、交互规则

### 5.1 画布上的悬停 / 点击

| 触发 | 结果 |
|---|---|
| 悬停节点 150ms | 浮现 hover 卡片（只读），显示该节点 5 个运行时数字：耗时、token 输入/输出/缓存、skill x/y、缺陷数、打回轮次；移开即消失 |
| 点击节点 | 右侧检查器选中，落「运行」分页（任务在跑时） |
| 悬停 token 构成条 | tooltip「输入 4.2k · 输出 1.8k · 缓存命中 6.0k」 |
| 悬停缺陷分布条某段 | tooltip「P1 · 3 个」 |
| 悬停回环角标「↻ n」 | tooltip「打回 n 次，最近原因：{一句话}」 |
| 双击空白 | 新建节点（设计态行为，不受运行态影响） |

### 5.2 抽屉的展开 / 收起 / 拖拽

| 触发 | 结果 |
|---|---|
| 点把手条（文字或箭头） | 收起态 ↔ 展开态 toggle |
| 拖拽把手条上边缘 | 高度 120–360px 连续调节，松开吸附到 200 / 320px |
| 键盘 `Ctrl/Cmd + \` | toggle 抽屉 |
| 开始运行 | 自动展开到 200px |
| 运行结束（成功或失败） | 自动展开到 200px，停留 2s 展示一句话结论；之后不自动收起 |
| 用户手动收起 | 收起，直到下次运行再自动展开 |

### 5.3 实时性（任务书 D）

- **刷新频率 1Hz**：运行中的数字 1 秒更新一次（后端 SSE 推送优先，前端兜底 1s 轮询）。理由：一个阶段跑几十秒到几分钟，1Hz 足够感知「还在动」；更高频数字会抖、浏览器重绘成本高、30 节点会卡。
- **数字不刺眼**：① tabular-nums 固定宽度，只变值不移位；② 数值变化做 200ms 淡入淡出 + 上下 2px 位移，不是瞬间替换；③ 只有变化的数字动，静止数字不动；④ 变化合并到同一次 `requestAnimationFrame` 重绘；⑤ `prefers-reduced-motion` 时关掉过渡动画、直接替换。
- **长跑（>10 分钟）体现「还在动」**：① 耗时角标持续 +1s 本身就是最强的活着信号；② 运行中节点的描边是沿轮廓流动的虚线（流动方向=数据流），比数字更能一眼看出「在跑」；③ 摘要条「完成度」旁的当前阶段文案随推进变化（如「开发 · 3/5 子任务」）；④ 卡住判定：节点耗时超过该阶段历史 P90×1.5 时，描边从流动绿变呼吸橙 + tooltip「可能卡住」。

### 5.4 空状态 / 错误态 / 悬停态汇总

| 状态 | 触发 | 表现 |
|---|---|---|
| 空数据态（未运行） | 从未运行 | 抽屉收起，把手条显示「尚未运行」；展开内容区显示「尚未运行，点「运行」开始」，不显示占位数字（0 是有意义数字，不与空混淆） |
| 错误态（指标获取失败） | 后端指标源断了 | 摘要条数字位置显示「—」+ 右上角一个 error 小图标 + tooltip「指标获取中断，重试中」 |
| 异常态（token 异常高） | 单节点 token 超历史 P90×1.5 | 该节点卡片 token 构成条右端加 error 色警示段 + 检查器 token 主值变 error + ⚠ |
| 悬停态 | 见 5.1 | 150ms 延迟浮现，避免扫过即弹 |

## 六、反例（不建议做的事）

1. **在画布上画 token 热力图（节点卡片背景随 token 量变深/变色）**：卡片背景已被「运行状态色」占用（运行中绿 / 失败红 / 打回橙），再叠 token 热度会双重编码打架；30 节点时整张图糊成一团红绿。token 是事后看的指标，放抽屉即可。
2. **把 6 个指标全塞进节点卡片角标**：违反「最多 2 个自由数字」的约束，30 节点时挤爆卡片高度、角标换行破坏对齐，扫描从瞥一眼退化成读一遍。
3. **用弹窗展示运行日志或指标**：任务书 §2 明说本面板不是弹窗；弹窗遮挡画布，而过程监督需要「边看图上卡在哪、边看指标」，弹窗把它拆成模态，逼用户在两者间来回开关。
4. **为指标单独做一整个「指标 Tab」把画布切走**：让「图和指标不能同时看」，直接违反「运行时要在图上看到进度」的核心需求，也违反任务书 §3.3「同一张图，设计时看结构、运行时看进度」。
5. **数字变化用滚动式数字或大幅动画**：滚动数字/闪烁刺眼，30 节点同时动会引发注意力与性能双灾难；正确的「动」是 1Hz + 200ms 克制过渡 + tabular-nums。
