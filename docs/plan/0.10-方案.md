**两个必须写进验收的时序事实**（方案据此排布）：

1. `node/start` 早于 `agents.create` → R6 只能新增事件；R1 的失败（503）发生时 `node/start` 已落盘，但 `agents.create` 调用次数为 0。
2. 冷会话 resume 时宿主优先级是「会话已记录的 selection > 上次请求 > `agentOptions`」（`@deepseek-ai/dsh-agent/lib/types/runtime-types.d.ts:49-54`）。所以 `agentOptions` 是**兜底**：本插件创建的会话已记录我们传入的对，resume 再传同一对是加固；**旧会话**（0.9.2 之前只记了宿主默认）无法靠 `agentOptions` 改绑，只能 `warn` + 在下次 `create` 时修正。文档与 UI 不得声称「resume 一定能换模型」。

## 2. 横切设计

### 2.1 模型路由：一个函数、三种来源、两条路径

**落点**：`src/engine.js`。把现有 `_resolveCreateAgentOptions`（`:2057-2094`）的规则抽成可导出的纯函数 `resolveModelRoute(input)`，create 与 resume 都调它。它不读 ctx、不读 fs、不抛异常，只返回 `{ok:true,...}` / `{ok:false,code,message}`，便于单测与红→绿。

**输入**：

```
input = {
  node:   { id?, title?, provider?, model?, reasoningEffort? },   // 节点 agentOptions；空串=未配置
  host:   { provider, model, reasoningEffort? } | null,            // agentDefaultModel.currentSelection()
  session:{ provider, model, reasoningEffort? } | null,           // sessions.json 里记录的对（仅 resume 有）
  origin: 'create' | 'resume',
}
```

**规则表（同源成对，硬判据）**：

| node provider | node model | session 有合法对 | host 有合法对 | 结果 |
|---|---|---|---|---|
| 有 | 有 | 任意 | 任意 | `{provider:node, model:node, source:'node'}`；`reasoningEffort` **只取 node 自己的** |
| 有 | 无 | 任意 | 任意 | `MODEL_ROUTE_CONFLICT`（禁止「节点 provider + 别处 model」） |
| 无 | 有 | 任意 | 任意 | `MODEL_ROUTE_CONFLICT`（同上，反向） |
| 无 | 无 | 有 | 任意 | `{provider:session, model:session, source:'session'}`（resume 优先复用创建时的一对） |
| 无 | 无 | 无 | 有 | `{provider:host, model:host, source:'host'}`；**不带** host `reasoningEffort`（沿用现状，不同模型档位不可移植） |
| 无 | 无 | 无 | 无 | `MODEL_ROUTE_UNAVAILABLE`（文案含「宿主未提供 agentDefaultModel」） |

补充规则：

- `host.currentSelection()` 抛错 / 形状坏（只有一半）→ `MODEL_ROUTE_UNAVAILABLE` + `warn`，**不**把它当成「宿主没配」。
- node 只给了 `reasoningEffort`（provider/model 都空）→ 不算半对：按 session/host 解析后把 node effort 带上。
- `session` 里的对必须同时满足：provider/model 都是非空字符串且 ≤128、effort 缺省或 ≤64；不合法整条忽略（旧 run / 手改坏的文件不炸）。
- 返回的 `reasoningEffort` 永不来自 host；来自 session 的 effort 也不存在（创建时只存我们实际传的对，而实际传的对里 host 档位从未写入）。

**错误码与 HTTP**：

| code | HTTP | run/end.reason 要点（中文，可诊断） |
|---|---|---|
| `MODEL_ROUTE_CONFLICT` | 503 | 「节点「X」只配置了 provider=…（或 model=…），不允许与宿主默认/会话记录拼成一对；请同时补全 provider 与 model，或都留空」 |
| `MODEL_ROUTE_UNAVAILABLE` | 503 | 「节点「X」无法确定模型路由：宿主未提供 agentDefaultModel，且节点/会话都没有成对的 provider/model」 |
| `MODEL_ROUTE_PARTIAL_HOST` | 503 | 「宿主 agentDefaultModel 只返回了 provider/model 的一半：…」 |

（需求里 A1.4 允许「503 或解析为同一 provider 的模型」；本方案选 503 —— 不做隐式 provider 内模型猜测，理由：猜错比报错更贵，且无法在事件里证明「同源」。）

**create 路径**：`_createNodeSession` 在 `agents.create` 之前调 `resolveModelRoute({node, host, origin:'create'})`；失败直接 `EngineError(503, message)`。此时主循环已写 `node/start`（`:4427`），因此可观测性为：`agents.create` 0 次、`node/start` 1 条、`run/end.status='failed'`、`reason` 含上表文案（现有 `test/engine.test.mjs:2380-2404` 正是这个形状）。

**resume 路径**：`_followupNodeSession`（`:2624-2666`）在 `agents.resume` 之前调同一函数，输入多一个 `session`；解析成功后：

```
resumeOptions = {
  resumeSessionId,
  agentOptions: { provider, model, ...(effort?{reasoningEffort}:{}) },
  setup: composition.setup,   // 保持 0.9.2 的 preset 挂载
}
```

`agents.resume` 的类型确实接受 `agentOptions`（`@deepseek-ai/dsh-agent/lib/types/index.d.ts:109-136`，注释写明「Route fallback and output controls」），所以不需要改宿主。resume 成功后读一次 `agent.model.current()`（`dsh-agent/lib/types/runtime-types.d.ts:49-56`：已记录选择 > 上次请求 > 实时 options）核对实际值；与本次请求不同（只会发生在旧会话上），`warn`：「会话已记录 X，本次请求 Y；宿主优先已记录值，节点模型只在新建会话时生效」——不失败、不静默。

**复用创建时的一对：存哪里**。`sessions.json` 现有条目是 `{sessionId, createdAt, lastUsedAt}`（`src/runstore.js:2656-2708`）。方案扩展为：

```
{ "n_dev": { "sessionId": "s-1", "createdAt": "...", "lastUsedAt": "...",
             "agentOptions": { "provider": "openai", "model": "gpt-5" } } }
```

- 读：`readNodeSessions` 校验后带上该字段；坏形状（数组/数字/半对/超长/空串）整条丢弃，不抛错。
- 写：`writeNodeSessions` / `upsertNodeSession` 同口径归一化；未提供就不写该键（旧文件读回再写不会凭空多出字段）。
- run.json 的 `sessions`（`{nodeId→sessionId}` 字符串映射，`src/runstore.js:868-884/513`）**不变**，那是给客户端/审计看的；两个文件职责不混。
- `runtime.restart` 已经把旧 `sessions.json` 原样复制进新 run（`src/runtime.js:1321-1339`），扩展字段自然继承，不需要改 restart。
- 体积：≤60 节点 × ~100B ≈ 6KB，远低于 512KB 上限（`src/runstore.js:2703`）。

**为什么不用「每次 attempt 重新解析、不落盘」**：两个 attempt 之间宿主默认模型可能被换掉（用户/别的 run 改了默认），只重解析会让同一节点的打回重跑/续跑换了模型，结果不可比（RISK-2 的原意）。落盘后，**节点显式对 > 会话已记录对 > 宿主默认**，既尊重用户改节点，又保证「没改就没漂移」。

### 2.2 会话快照：新事件 `node/tools`

**落点**：`src/runlog.js`（契约）+ `src/engine.js`（采集）+ `src/client/logdrawer.js`（展示）。

**为什么必须是新事件**：`node/start` 在主循环里先写（`:4427`、`:4882`），会话在 `_executeNode → activate → _createNodeSession` 才建（`:3498`）；工具面要等 `agents.create/resume` + `_syncNodeRejectTool` + 预热轮之后才稳定。任何「塞进 node/start」的方案都要么改写事件顺序（伤旧读端与既有断言），要么先写空值再补写（自欺）。

**事件形状**（kind 用新扩展白名单，不污染冻结的 17 种 `EVENT_KINDS`，模式照 `INBOX_EVENT_KINDS`/`MACHINE_EVENT_KINDS`，`src/runlog.js:44-77`）：

```json
{
  "kind": "node/tools",
  "nodeId": "n_dev", "attemptId": 1, "traceId": "…",
  "data": {
    "tools": ["bash", "flow_node_reject", "glob", "grep", "read", "subagent", "write"],
    "toolsSource": "session",
    "count": 7
  }
}
```

- `tools`：去重 + 字典序排序 + 每项 ≤64 字符 + 最多 64 项；只存名字，不存 schema/描述。
- `toolsSource`：`'session'`（拿到注册表视图）/ `'unavailable'`（宿主没有 `agent.ctx.tools`、`definitions` 抛错、或返回非数组）。
- `truncated: true`：仅在超过 64 项或防御性字节裁剪发生时出现。
- 字节：64×64 最坏约 4.3KB，加字段头 < 8KB（`MAX_EVENT_BYTES`，`src/runlog.js:80/885`）；采集端仍用 `Buffer.byteLength(JSON.stringify(event))` 再兜一层，超限截尾并置 `truncated`。
- `runlog.js` 的 `validateData` 增加 `case 'node/tools'`（数组/枚举/布尔有界校验）；`eventDigest` 增加一句人话摘要（否则事件表显示空行）。
- `logdrawer.js` 的 `EVENT_KINDS` 与 `WATCH_EVENT_KINDS` 增加 `node/tools`：前者让筛选表认识它，后者让运行中的增量窗口能收到它。

**采集时序（硬要求）**：

```
node/start(已落盘) → agents.create | agents.resume
  → _syncNodeRejectTool(当前流程结构)        // :3537 / :2676
  → (仅新建) 预热轮 _warmUpNodeSession       // :3540，冷会话复用不预热
  → _promptNodeSession 入口 → **采集点**：收集 tools → append node/tools
  → 正式任务 followup（同一函数内，紧随采集之后）
```

推荐把采集放在 `_promptNodeSession` 的**最开头**（`src/engine.js:2471`，跟进 `followup` 之前）：它只有两个调用点（`:2679` 复用、`:3543` 新建），天然满足「预热之后、正式 prompt 之前」；`nodeTools.has(sessionId)` 就能判断本轮 `flow_node_reject` 是否已注册，不需要再传 `flow`。

- 采集调用 `agent.ctx.tools.definitions(agent)`（宿主 `dsh-tools/lib/index.js:576-580`；`scope` 传 agent）。
- 若本次 `_syncNodeRejectTool` 返回 `true`（注册成功），**合并** `flow_node_reject` 进名单：不依赖宿主 `definitions` 是否立刻可见，保证 A6.2 的确定性。
- 采集/落盘失败**不阻断节点**：`try/catch` + `warn`，最坏是少一条观测事件（与预热失败不阻断同口径，`src/engine.js:3688-3692`）。这是刻意的：排查工具面的功能不能反过来把节点跑挂。
- 每次 attempt 采集一次（重试同 attemptId 会多一条 `node/start` + 一条 `node/tools`，时间线可读）。

**口径说明**（必须写进 UI 文案与文档）：清单是「会话注册表可见的工具」，不是「某一轮实际被准入的工具」。首轮精简（`minimal-first-turn`）是 step 级准入，不影响注册表视图；因此清单回答的是「这个会话有没有 bash/subagent/打回工具」，不回答「上一轮实际给了哪些」。这与需求 Q6 的主口径一致，也避免把 `tool/call` 历史冒充「可用」。

### 2.3 客户端数据归一化：先补字段，再写 UI

RISK-13 的顺序不能反：`normalizeRun` 是显式映射（`src/client/logdrawer.js:522-556`），现在会丢 `sessions`/`agentPreset`/`supervision`/`restart`；`mergeRunDetail` 虽然 `{...base, ...detail}`（`:716-729`），但只要经过 `normalizeRun` 就再丢一次。方案先把这四个字段进模型并单测，再写展示。

| 字段 | 来源 | 归一化规则 | 缺失时 |
|---|---|---|---|
| `sessions` | `run.json.sessions`（`runstore.js:513`） | 只收 `{string→非空 string}`，其余键值跳过；整对象非 plain object → `null` | `null`，UI 不显示入口 |
| `agentPreset` | `run.json.agentPreset`（`runstore.js:506`） | `{value: string≤64, source: string≤32}`，value 空 → `null` | `null`，显示 `—` |
| `supervision` | `run.json.supervision`（`runstore.js:504`） | 只取 `wakerSessionId`（≤128 字符串），其余忽略 | `null` |
| `restart` | `run.json.restart`（`runstore.js:942-972`） | `{fromRunId, attempt, startNodeId?, skippedNodeIds?, note?}`，fromRunId 非法 → `null` | `null`，不显示世系 |

派生的纯函数（都可直接在 `test/logdrawer.test.mjs` 断言，不需要 DOM）：

- `sessionTargetOf(run, nodeId, events)` → `{sessionId, source:'run.sessions'|'event.ref'|'none', canOpen}`。
- `presetInfoOf(events, run, nodeId)` → `{value, source, sourceText}`；节点最近一条 `node/start.data.agentPreset` 优先，run 级兜底，最后 `—`。

### 2.4 宿主导航：懒取 + props 注入 + 复制降级

**现状**：插件只 `inject:['slots']`（`src/client/plugin.js:29`）；宿主 `uiWorkspace` 是客户端核心服务，签名 `openSession(target: SessionTarget): void`（同步、返回 void、失败由宿主 notice 显示；`dsh-client-ui-workspace/lib/types/client/navigation.d.ts:20-23`），`SessionTarget = SessionId | SubagentAddress`（`dsh-api-session-controller/lib/types/client/contract/sessions.d.ts:20`）。

**方案**：

```js
// plugin.js
apply(ctx) {
  const openSession = target => {
    const ws = typeof ctx.get === 'function' ? ctx.get('uiWorkspace') : undefined
    if (!ws || typeof ws.openSession !== 'function') return false
    try { ws.openSession(target); return true } catch { return false }
  }
  ctx.slots.register({
    name: 'main', key: PANEL_ID,
    inject: () => ({ openSession }),
  }, FlowStudioPage)
  ...
}
```

为什么不用 `inject:['slots','uiWorkspace']`：cordis 的必需注入在服务缺失时让 fiber 停在 PENDING（`@deepseek-ai/cordis/lib/types/fiber.d.ts:188` 与 registry 语义），结果是**整个「流程编排」面板消失**——为了一个跳转入口赔掉主功能，代价不成比例。`ctx.get(name)` 明确支持「不声明 inject 也读服务」（`cordis/lib/types/reflect.d.ts:7/123`），宿主侧栏也这么用（`dsh-client-ui-sidebar/lib/client.js:677` 同时 inject 与 get）。这不是绕过契约，是把**可选能力**按可选方式读取。

**降级链**：

1. `openSession` 可用 + 有 sessionId → 按钮「打开节点会话」/「打开发起会话」，点击调用一次（不 await，不重试）。
2. `openSession` 不可用 → 同位置显示「复制会话 id」，点击复制 + `已复制` 反馈（复用抽屉现有 copy 反馈样式）。
3. 没有 sessionId（外部 executor / 未跑到 / 已删）→ 按钮 `disabled`，`title` 写明原因（「外部执行器没有节点会话」「该节点还没开始运行」）。

**页面透传**：`FlowStudioPage` 增加可选 prop `openSession`；再经 `FsLogDrawer` 的 `openSession` prop 落到节点详情与事件 ref 行。SSR/测试不传时为 `undefined`，正好覆盖降级分支。

### 2.5 保存 → 重启的时序（R8 的核心）

```
点击「修复后重启」
  ├─ 前置：canRestartInPlace(run, currentFlowId)
  │    run.status ∈ {failed, aborted} ∧ run.flowId === 当前流程 ∧ !restarting
  ├─ ① 防重入：restarting=true，按钮 disabled
  ├─ ② await flushBeforeLeave()            // page.js:913-921；内部走 saveNow → createSaveQueue
  │    ├─ 无改动 → ''（可继续）
  │    ├─ 有改动且保存成功 → ''（磁盘已是新结构）
  │    └─ 保存失败 → 返回可读 warning：中止重启，不改旧 run，草稿保留
  ├─ ③ POST /runs/<old>/restart {note?}    // api.restartRun
  ├─ ④ 202 → 用响应里的 run.id 聚焦新 run（focusRun + nonce）、syncToken++、announce
  └─ ⑤ 失败 → restartFailureText 显示在动作条；不自动重试（接口非幂等）
```

**为什么必须 await flush**：`saveNow` 是整份替换 + 乐观锁，保存队列保证「出队时才取 version」（`src/client/page.js:331-352`）；如果先 restart，Host 读的是磁盘旧结构（R9 的加边不会生效，A8.3 会假绿）。`flushBeforeLeave` 在 `editVersion > savedVersion` 时触发保存，正好覆盖「去抖窗内」与「在途保存」两种情况。

**为什么限制同流程**：抽屉的 run 列表是全局的（`logdrawer.js:2147` 注释「仅用于说明；列表是全局的」），而 `flushBeforeLeave` 只保存当前打开的流程。允许跨流程重启会「保存 A 流程、重启 B 流程的 run」，两端都不对。跨流程时按钮 disabled，提示「先打开该流程再重启」。

**重启继承边界**（服务端既有语义，`src/runtime.js:1296-1412`，0.10 不改）：

| 继承 | 不继承 |
|---|---|
| `flowId/flowName/engine`、`workspace`、worktree 路径（以 `startOptions{worktree:'off'}` 钉住）、`supervision.wakerSessionId` | 旧事件流、attempt 计数、run 状态、limits、input/inbox |
| 旧 `sessions.json` 里仍存在于当前流程的阶段节点会话（同 nodeId **同 sessionId**） | 已从流程删除的节点会话 |
| `restart.{fromRunId,attempt,oldStatus,oldReason,startNodeId,skippedNodeIds,inheritedNodeIds,at,note?}` | 旧 `run.json.sessions` 的字符串表会被引擎按新 run 重新 patch |

`skippedNodeIds` = 旧 run 中 `node/end passed` 且仍在起点 `next` 路径上的阶段节点（`src/restart.js:168-237`）。新 run 从 `startNodeId` 起跑，`resumePlan.skipped` 把已完成节点作为上下文注入、不重跑。

**sessionId 复用**：新引擎 `_loadNodeSessions` 读新 run 的 `sessions.json`（`src/engine.js:1852-1871`）→ 起点节点命中 `nodeSessions` → `_followupNodeSession` → 活会话 `followup`、冷会话 `agents.resume({resumeSessionId, agentOptions, setup})`。失败节点因此「在原会话里继续」。

**工具重挂**：`_followupNodeSession` 在 prompt 前调 `_syncNodeRejectTool`（`:2676`），判据用**当前流程**（`flow` 参数来自本次 run 启动时读到的结构）——加边补挂、删边撤掉、旧注册先 dispose。重启续跑与同 run 打回重跑走同一条，不需要额外的「结构指纹」。

### 2.6 打回门控与旁路

**判据（唯一、结构性）**：`node.kind === 'stage'` 且 `flow.edges` 存在 `from === node.id && kind === 'reject'`（`src/node-tools.js:47-63`）。开始/结束节点、无出向 reject 边的阶段节点一律不注册。工具名固定 `flow_node_reject`。

**时序**：

| 时点 | 动作 |
|---|---|
| 新建会话 | `_syncNodeRejectTool`（`:3537`）在 `agents.create` 之后、followup 之前；先 dispose 旧注册，再按当前结构决定注册 |
| 复用冷/活会话 | `_followupNodeSession` 里 `_syncNodeRejectTool`（`:2676`），attempt 变了就换闭包 |
| restart 续跑 | 新 run 的 `_loadNodeSessions` 加载继承会话 → 走上面的复用路径，用**当前磁盘结构**重算 |
| run 收尾 / stop | `_disposeAllNodeRejectTools` 全部 dispose，不泄漏（`:2755-2762`） |
| 无 tools 服务 / register 抛错 / disposer 缺失 | `warn` + 不挂工具，节点照跑（`:2716-2745`）；不静默 |

**等价性**：工具只登记「本轮待生效打回」，收口时并入结构化结论（`verdict='reject'`，`:2817-2836`），随后完全复用 `node/end rejected → selectRejectTarget → reject/trigger → 目标 attempt+1`，不新增事件 kind。边界：登记与当前 `node/attempt` 不匹配会被忽略（`:2820`）——工具不会打回「上一轮」。

**旁路（D9）**：无出向 reject 边但模型仍输出 `verdict=reject` 时，现状写 `node/end rejected` 后抛「没有任何 reject 边」→ run failed（`:4521-4526`）。0.10 **保留失败**，改两点：

1. `reason` 追加行动指引：「补一条从该节点出发的打回边后，用「修复后重启」在原会话续跑；或把结论改为 pass」。
2. `node/end.extra` 增加 `{ rejectBypass: 'no-edge' }`，便于审计/筛选。

不降级 pass 的理由：把审查否定静默改成通过，会污染验收/质量统计，也会让「配置错误」在界面上消失；保留失败 + 明确指引 + R8 续跑，才是可修复的闭环。

## 4. 接口契约（调用方不用猜）

### 4.1 模型路由

**函数签名**（`src/engine.js` 导出，供测试直接调用）：

```js
resolveModelRoute({ node, host, session, origin }) => RouteResult

RouteResult =
  | { ok: true, provider: string, model: string, reasoningEffort?: string,
      source: 'node' | 'session' | 'host' }
  | { ok: false, code: 'MODEL_ROUTE_CONFLICT'|'MODEL_ROUTE_UNAVAILABLE'|'MODEL_ROUTE_PARTIAL_HOST',
      message: string }
```

- 长度上限：provider ≤64、model ≤128、effort ≤64（与 `node.model` 的 128 对齐，`runlog.js:481`）。
- 不抛错；失败由调用方转 `EngineError(503, message)`。
- 切来源时必须**整对**切换，禁止字段级合并。

**正常示例**：

```js
// 节点显式对（openai/gpt-5），宿主是 deepseek
resolveModelRoute({
  node: { id: 'n_dev', provider: 'openai', model: 'gpt-5' },
  host: { provider: 'deepseek', model: 'deepseek-chat' },
  origin: 'create',
})
// → { ok: true, provider: 'openai', model: 'gpt-5', source: 'node' }
// agents.create 收到 agentOptions={provider:'openai',model:'gpt-5'}，不带宿主 effort
```

**失败示例**：

```js
resolveModelRoute({
```

### 4.4 `POST /runs/<id>/restart`

请求：`{ "note"?: string }`（≤500，超长 400）。响应 202：

```json
{
  "ok": true,
  "run": { "id": "r-def-2", "status": "running", "flowId": "f-1" },
  "restart": { "fromRunId": "r-abc-1", "attempt": 1, "oldStatus": "failed",
               "oldReason": "节点执行失败…", "startNodeId": "n_b",
               "skippedNodeIds": ["n_a"], "inheritedNodeIds": ["n_a","n_b"],
               "at": "2026-11-07T09:10:00.000Z" },
  "plan": { "startNodeId": "n_b", "skipped": ["n_a"], "inherited": ["n_a","n_b"] },
  "hint": "已新建续跑 run r-def-2；旧 run r-abc-1 的终态与事件不会被改写。"
}
```

错误（客户端展示 Host 原文 + 人话前缀）：

| HTTP | 条件 | 客户端文案 |
|---|---|---|
| 400 | runId 非法 / pending\|running / done / 结构不合法 / 起点不在 next 路径 / note 超长 | 「重启失败：<Host 原因>」；running 提示先停止；done 提示复制流程 |
| 404 | run 不存在 / 流程不存在 | 「重启失败：run 或流程已不存在，刷新后重试」 |
| 500 | engine 未初始化/不支持 restart | 「重启失败：执行引擎未启用或版本不匹配」 |
| 503 | 有可继承会话但 agents 无 get/resume | 「重启失败：宿主 agents 不可用，无法在原会话续跑」 |

**幂等性**：非幂等。同一 failed run 连点两次会建两个新 run；UI 用 in-flight disabled + 不自动重试。超时语义：服务端无独立 deadline（同步到 `start()` 返回），客户端按普通请求处理；超时后**不得**自动重试，先刷新列表看是否已产生新 run。

### 4.5 `flow_node_reject`

入参：`{reason ≤2000 必填, findings? ≤50, rejectTarget? 必须是该节点出向 reject 边目标}`；成功 `{ok:true,accepted:true,runId,nodeId,attempt,sessionId,reason,rejectTarget|null,hint}`；失败 `{ok:false,error,hint,retryable:false}`；`timeoutMs:15000`（`src/node-tools.js:26-32`）。调用后本轮收口等价 `verdict=reject`；与当前 attempt 不匹配的登记被忽略。

### 4.6 skills

`GET /skills` → `{ok:true, skills:[{name, description, whenToUse}]}`（`src/index.js:1084-1097`；服务缺失返回 `[]`）。`SkillsPicker` props：`{value: string[], skills: Skill[], onChange: (next: string[]) => void, initialOpen?: boolean}`。输出：去重、保序、≤12（`src/model.js:74`）；chips 由外层渲染，形状不变。
