> 阶段：结构设计 · 目标版本 0.10 · 基线 0.9.4（HEAD `808f929`，2026-11-07）· 仓库 `/testbed/workspace/dsh-flow-studio`
> 上游：`docs/plan/0.10-需求.md`（R1–R9）、`docs/plan/0.10-方案.md`（D1–D9、§4 契约）
> 本文回答：每条需求落到哪个文件/函数/组件、新增哪些导出与测试、样式类名与 LOD 断点是什么、客户端 vdom 与既有 aria/键盘可达性怎么不被破坏、`docs/reference` 与 `docs/guide` 哪些段落必须同批改。本文不写实现，所有关键断言带源码/测试行号；基线实测见 §8。

## 0. 结论：结构可落地，但有 6 处必须先钉死

9 条需求都有文件级落点，没有一条需要改冻结的 `docs/design/`。方案层面的 9 个拍板（D1–D9）在结构上成立；结构阶段只做 6 个修正，都是「不修正就会返工」的点：

| # | 结构裁决 | 为什么必须现在定 |
|---|---|---|

### 1.3 依赖方向与环风险

既有方向（实测）：`engine → runstore → runlog`；`engine → node-tools → model`；`restart → engine`（唯一倒挂）；`runtime → restart → engine`；`page → logdrawer`（11 个符号）；`flowlist → logdrawer`（2 个符号）；客户端 → `../model.js`（6 处）。客户端不 import 任何服务端实现（grep 空）。

0.10 新增方向必须是：

```
engine.js ──→ runstore.js（归一化函数）
   │              ↑
   └──→ runlog.js（kind 常量）
plugin.js ──→ page.js ──→ logdrawer.js ──→ api.js
                  ↑            │
                  └── 回调 ────┘
```

六个环/倒挂点，开发时逐条守：

| # | 风险 | 触发条件 | 守则 |
|---|---|---|---|
| A | `engine ↔ restart` | 把路由或续跑模型写进 `restart.js` | `restart.js:22` 已 import engine；0.10 不改 `restart.js` |
| B | `engine ↔ node-tools` | R6 让 node-tools 反查「注册了没有」 | 用 `_syncNodeRejectTool` 的返回值（`:2750`），不让 `node-tools` import 引擎 |
| C | `runstore ↔ engine` | 在 runstore 里做「同源成对」语义校验 | runstore 只做字符串/长度/半对的**形状**校验；语义在 engine 的 `resolveModelRoute` |
| D | `page ↔ logdrawer` | R8 让抽屉自己调 `flushBeforeLeave` / `createSaveQueue` | 保存链留 page；抽屉只接 `onRestartRun` 回调 |
| E | `logdrawer → api → ?` 纯度 | 把 `restartFailureText` 放进 logdrawer 再被 api 使用 | 错误文案放 `api.js`（与 `runActionFailureText` 同家），logdrawer 只 import/复用 |
| F | `normalizeRun` 两份 | 新字段加在 `logdrawer.js:522` 的旧函数上，另写一份 | 0.10 只保留一份（logdrawer），不拆 `runmodel.js`；拆分条件见 §6 |

### 1.4 新增文件裁决：0.10 不新增

模块成员建议新增 `src/modelroute.js`、`src/client/runmodel.js`、`src/client/hostbridge.js`。三者技术上可行，但 0.10 的硬约束是「零依赖增量 + 构建/发布清单不动 + 测试全绿」，新增文件的收益在 0.10 不足以覆盖成本：

1. **`src/modelroute.js`**：Host 模块必须进 `HOST_MODULES`（`scripts/build.mjs:44`），且新文件未被 `git archive HEAD` 收录时 `test/build.test.mjs:150-175` 会假失败。route 规则只有一个消费者（engine）；runstore 不需要语义校验（见 C）。留在 engine.js，规则仍只有一份。
2. **`src/client/runmodel.js`**：`logdrawer.js` 的 `normalizeRun` / `mergeRunDetail` 被 23 个测试的 import 点引用；要拆必须再 `re-export` 一整套符号，并搬 `text` / `isObject` / `optionalNum` 等私有 helper（`logdrawer.js:151-230`）。0.10 四条需求（R4/R5/R6/R8）都落 logdrawer，先拆再改会把「行为改动」与「搬家」混在一个 diff 里，无法审计。留到 0.11 单独重构。
3. **`src/client/hostbridge.js`**：R4 的宿主适配只有约 20 行（懒取 + try/catch + 返回 boolean），放 `plugin.js` 足够；拆文件反而让「调用点是否懒取」更难用 grep 证明。

代价：`logdrawer.js` 继续变长（3743 → 约 3900 行），`engine.js` 继续持有路由规则。两项都记入 §6 的技术债，不阻塞 0.10。

**R1 的三个调用点**（必须同批改，否则「规则只有一份」是假的）：

1. `src/engine.js:3482`（`_createNodeSession`，默认 `agents.create`）；
2. `src/engine.js:2624-2666`（`_followupNodeSession`，冷会话 `agents.resume`）；
3. `src/engine.js:3705-3716`（`_legacyActivate`，旧宿主兼容 spawn；方案未提，容易漏）。

**R1 的 route 解析规则**（结构上钉死输入/输出，详细规则表见方案 §2.1）：

- 输入 `{node, host, session, origin}`：node 取 `node.provider` / `node.model` / `node.reasoningEffort`（空串=未配置）；host 取 `agentDefaultModel.currentSelection()`（可抛/可半对）；session 取 `sessions.json` 条目的 `agentOptions`；
- 输出 `{ok:true,provider,model,reasoningEffort?,source}` 或 `{ok:false,code,message}`；不抛异常；
- `reasoningEffort` 只来自 node；host 的 effort 永不返回；session 的 effort 只在创建时实际传过才存在；
- 半对（只有一个）+ 另一来源有整对 → `MODEL_ROUTE_CONFLICT`（禁止跨来源拼）；半对 + 另一来源也没有整对 → `MODEL_ROUTE_UNAVAILABLE`（文案含「宿主未提供 agentDefaultModel」）；host 只回一半 → `MODEL_ROUTE_PARTIAL_HOST`；三处都没有 → `MODEL_ROUTE_UNAVAILABLE`；
- engine 把 `ok:false` 转 `EngineError(503, message)`；`agents.create` / `agents.resume` 调用次数为 0。

**R6 采集点与时序**（结构上钉死）：

```
node/start（已落盘，:4427）
  → agents.create（:3498）| agents.resume（:2652）
  → _syncNodeRejectTool（:3537 / :2676）
  → 预热轮（仅新建，:3540）
  → _promptNodeSession 开头（:2471）← 采集 node/tools
  → 正式 followup
```

采集实现要点：

- `agent.ctx.tools.definitions(agent)` 返回数组 → 取 `definition.name`；
- `_syncNodeRejectTool` 返回 `true` 时，**合并** `flow_node_reject`（`:2750`），不依赖 `definitions` 是否立刻可见；
- 去重 → 字典序排序 → 截 64 → `Buffer.byteLength(JSON.stringify(event))` 兜底 → append；任何异常 `try/catch` + `warn`，不阻断节点（与预热失败同口径，`:3688-3692`）；
- `toolsSource`：拿到注册表视图 = `session`；没有 tools 服务 / `definitions` 抛错 / 返回非数组 = `unavailable`（此时若 `flow_node_reject` 已注册仍保留在 `tools` 里，UI 文案说明「清单不完整」）；
- 外部 executor 节点不经过 `_promptNodeSession`，不产生 `node/tools`；UI 显示「外部执行器没有节点会话，未记录工具清单」，不是「未检测」。
- 重试同一 attemptId 会多一条 `node/start` + 一条 `node/tools`（`_promptNodeSession` 每次重试都会走），时间线可读；不新增 `data.retry` 之外的语义。

**R9 旁路**（结构上钉死）：

- 现在 `node/end{status:'rejected'}` 在 `selectRejectTarget` **之前**写（`:4503-4526`）；要加 `extra.rejectBypass`，先把 `choice = selectRejectTarget(...)` 算出来，再写 `node/end`（`choice === null` → `extra.rejectBypass='no-edge'`），然后抛错；
- `reason` 在现有「没有任何 reject 边」后追加：「补一条从该节点出发的打回边后，用「修复后重启」在原会话续跑；或把结论改为 pass」；
- 不降级 pass；`run/end.data.reason` 仍包含完整原因（`this.failedNode.reason`）。
