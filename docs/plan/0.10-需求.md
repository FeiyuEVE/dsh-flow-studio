# 0.10 需求分析：9 条改进的裁决与验收

> 阶段：需求分析 · 目标版本 0.10 · 基线 0.9.4（2026-11-07）· 仓库 `/testbed/workspace/dsh-flow-studio`
> 本文回答三件事：9 条诉求各自「现在到哪、0.10 还差什么」；每条怎样判真假；哪些地方会冲突、会返工、必须先裁决。

## 0. 结论

- 9 条诉求全部保留为 0.10 需求（R1–R9），每条都有可判真假的验收条目；但它们的**性质不同**：①⑧⑨ 三条在 0.9.2 已交付引擎/服务端并有针对性用例，0.10 的增量主要是「界面入口、模型路由补强、回归锁定」；②③ 是实现缺陷；④⑤⑥⑦ 是真正的界面新功能。
- **两个 P0 残留**：节点冷会话 `resume` 只带宿主默认 selection，不带节点配置的 provider/model（`src/engine.js:2638-2640`），重启/打回后模型会漂移；`_resolveCreateAgentOptions` 允许「节点 provider + 宿主 model」跨来源拼成一对（`src/engine.js:2069-2074`，现有用例 `test/engine.test.mjs:2424-2438` 甚至把 `openai + deepseek-chat` 断言为合法）。这两条不处理，R1「成对」只是结构上成对。
- **三个会改变方案的点**：④ 的宿主导航能力已确认可用（`ctx.uiWorkspace.openSession(sessionId)`，见 `dsh-client-ui-workspace/lib/types/client/navigation.d.ts:22` 与 `dsh-client-ui-workflow-run/lib/client.js:791-792`），但本插件目前只 `inject:['slots']`（`src/client/plugin.js:29`），需要新增注入与降级路径；③ 加高指标条会挤压 200px 抽屉里的事件区，必须在「增高」与「两行化」之间裁决；⑨ 只拿掉工具、没拿掉结构化 `verdict=reject`，无出向打回边的节点若文本判打回，整条 run 仍会失败（`src/engine.js:4521-4527`）。
- 基线实测（本机，命令见 §8）：`npm test` **23 个 .test.mjs / 805 组全绿**，`npm run build` 通过。任务书写「22 个 .test.mjs」，仓库实际是 23 个（`package.json` 的 test 脚本列了 23 个）——验收以实际命令全绿为准，不以文件数为准。

## 4. 需求清单 R1–R9

> 每条给：用户故事、需求（必须/建议）、验收条目（A）、检查方式。验收条目均为「可判真假」；UI 项给了像素/可见性口径，引擎项给了可观测断言。
> 现状列见 §2；「0.10 动作」是需求边界，不是实现方案。

### R1 节点会话的模型路由必须同源成对（create + resume）

- 用户故事：US1、US2。
- 必须：
  1. `agents.create` 收到的 `agentOptions` 同时含非空 `provider` 与 `model`，且两者来自同一来源（节点显式对，或宿主默认对）；不允许「节点 provider + 宿主 model」跨来源拼接。
  2. 拿不到宿主默认且节点不成对时，**创建调用发生之前**失败；`agents.create` 调用次数为 0，run 失败原因可诊断。
  3. 冷会话 `agents.resume` 复用与创建时相同的模型对；不能因为 resume 丢掉节点自定义 model。
  4. 节点自定模型时不移植宿主的 `reasoningEffort`（不同模型档位不可移植）。
- 建议（P2）：检查器提供 provider 输入并与 model 成对保存/回填；`NODE_KNOWN_FIELDS` 增加 `provider`（或明确以 `extras.provider` 往返并回填）。
- 验收：
  - **A1.1** 宿主 `agentDefaultModel.currentSelection()` = `(p, m)`，节点无覆盖：`agents.create` 收到的 `agentOptions` 等于 `{provider:p, model:m}`，且不携带宿主 reasoningEffort。检查：`test/engine.test.mjs` 现有 `strictProviderHost` 捕获 `created[0].agentOptions`（参考 `:2317/2357`）。
  - **A1.2** 无宿主默认 + 节点只给 model：`agents.create` 调用 0 次，run 状态 `failed`，`run/end.reason` 含「宿主未提供 agentDefaultModel」；检查：`test/engine.test.mjs:2380-2404`。
  - **A1.3** 节点显式 `provider+model` 与宿主不同：create 收到节点对，不带宿主 `reasoningEffort`；检查：`:2406-2422`、`:2317-2333`。
  - **A1.4** 节点只给 provider（无 model）且宿主 selection 是另一 provider：**不得**返回 `{provider:节点, model:宿主}` 的跨来源组合；应 503 提示补 model，或解析为同一 provider 的模型并在事件里记录来源。检查：新增用例；现有 `:2424-2438` 的期望必须改（当前断言 `openai + deepseek-chat`，是本条的反例）。
  - **A1.5** 冷会话 resume：`agents.resume` 收到的 `agentOptions` 与创建时同一对；若宿主不支持 resume 时传 `agentOptions`，则本轮实际模型必须与节点配置一致并在 `node/start` 记录。检查：新增用例（现有 `:2560-2579` 只断言 `setup`，未断言 `agentOptions`）。
  - **A1.6**（P2）检查器 provider 输入：填 `openai` + `gpt-5` 保存后重载仍回填；只有 provider 或只有 model 时给出成对提示。检查：SSR + `model.js` 往返用例。
- 依赖：R8（续跑必须沿用同一模型对）、R5（显示实际路由）。

### R2 画布节点卡的三键必须完整可见、可点

- 用户故事：US3。
- 必须：
  1. 选中、hover、`:focus-within` 三种触发下，新增下游 / 删除 / 检查器三键都完整显示（END 节点不显示「新增下游」，只显示 2 键）。
  2. 每个按钮的可点区域（含 padding）不小于 20×20px（01 §3.7 热区口径）；按钮不得被任何 `overflow:hidden` 祖先裁剪。
  3. 点击行为不变：＋ 新建下游并选中；✕ 删除节点；⌕ 打开检查器。运行中锁定：＋/✕ disabled，⌕ 可用。
  4. 不改变 208×96（主从 116）卡片尺寸；far LOD 仍隐藏工具条（既有行为）。
- 验收：
  - **A2.1** SSR 渲染选中节点：存在 `button[aria-label="新增下游节点"]`、`[aria-label="删除节点"]`、`[aria-label="打开检查器"]`；END 节点只有后两个。检查：`test/render.test.mjs` 增加断言（现有 `renderToStaticMarkup` 能力足够）。
  - **A2.2** 静态几何：三键外框 = 3×22 + 2×2(gap) + 2×2(padding) + 2×1(border) = **76×28**（`src/client/styles.js:447-462`）；且不处于「父级 `overflow:hidden` + 工具栏负 top」的组合中；若保留负偏移，必须把工具条移出裁剪容器或改为不裁剪的包裹层。检查：`test/render.test.mjs` 已 import `CSS`，可正则取 `.fs-node/.fs-node-tools/.fs-node-tool` 的 `overflow/top/padding/border/width/height` 计算外框并断言（确定性回归，不依赖浏览器）。
  - **A2.3** 浏览器实测（1440×900、缩放 100%）：三键 `getBoundingClientRect()` 均与视口相交且宽高 ≥20；`document.elementFromPoint(center)` 命中对应按钮或其后代；三键各点击一次行为符合 3。检查：一次性浏览器脚本/人工记录 rect JSON + 截图，写入 0.10 测试报告（本仓无 Playwright/jsdom，见 RISK-4）。
  - **A2.4** 键盘：Tab 聚焦节点后工具条可见，三键可 Tab 到并 Enter 触发；far LOD 下仍 `display:none`。
- 依赖：无；冲突：208×96 冻结规格（不能在卡片内加高一行）。

### R3 指标横条必须完整展示每个指标的三行信息

- 用户故事：US4。
- 必须：
  1. 7 个指标块的 label / value / hint 三行都完整可见，不发生纵向裁剪；不得用省略号吞掉 hint（截断只允许在横向超宽时由 title 兜底）。

  3. 120px 最小高度、拉高、全屏三档不出现纵向裁字；横向滚动可接受。
- 验收：
  - **A3.1** 计算：`.fs-log-stats` 内容盒高度 ≥ 48px（三行 16+18+14），加上下 padding 4+4 后总高 ≥ **56px**；或改为两行后 hint 内容不丢失（「完整展示」口径以可见文本为准，只把 hint 塞进 `title` 不算通过）；`overflow-y` 不为 `hidden` 或内容 `scrollHeight <= clientHeight`。检查：`test/logdrawer.test.mjs` 已有 `CSS` 与 `baseDrawerProps`，解析 `height/padding` 与 `.fs-stat-label/value/hint` 行高求和断言；SSR 断言 `.fs-stat` 数=7 且三行文本齐。

### R4 节点与执行记录可跳到对应会话详情

- 用户故事：US5。
- 必须：
  1. 节点详情（事件详情里的节点面板）显示该节点的会话入口；执行记录（run 详情/节点行）也提供入口；run 级若有 `wakerSessionId`，提供发起会话入口。

### R9 打回工具按 reject 边门控，并在结构变化后重挂

- 用户故事：US10。
- 必须：
  1. 只有「阶段节点 + 当前流程存在出向 reject 边」才注册 `flow_node_reject`；开始/结束节点、无出向边的节点不注册。
  2. 每次 attempt 开始、复用冷会话、重启续跑时按当前结构重算：加边补挂、删边撤掉；旧注册先 dispose，注册失败要可见（warn + 不静默）。

  5. 旁路（需裁决，不默认改语义）：无出向边时模型仍可能输出 `verdict=reject`，当前会写 `node/end rejected` 后抛「没有任何 reject 边」判 run 失败；0.10 要么保留失败但文案更明确，要么降级为 pass + warn。方案阶段二选一并在方案文档记录（RISK-3）。
- 验收：
  - **A9.1** 无出向边的阶段节点：fake `agent.ctx.tools.register` 未收到 `flow_node_reject`；有边则收到 1 次；开始/结束节点 0 次。检查：`test/engine-restart.test.mjs:305-335` 已覆盖，沿用。
  - **A9.2** 加边后 restart：B 的新 attempt 注册表含 `flow_node_reject`，旧注册 disposer 被调用；删边后不注册。检查：`:422-524`。
  - **A9.3** 工具调用：fake agent 调用工具后 `node/end.status='rejected'`、`reject/trigger` 指向目标、目标 attempt+1；检查：`test/tools.test.mjs` 或 `engine.test.mjs` 新用例。
  - **A9.4** 收尾：run 结束后注册表为空（disposer 全调用），重复 run 不叠加。
  - **A9.5** 旁路：按 5 的选择锁定行为（若保留失败，断言中文原因；若降级，断言 warn 事件 + pass），并更新 `docs/plan/0.10-方案.md` 记录。
- 依赖：R8（重启重挂）。

- **业务分析师**（subagent，只读）：交付 S1–S10 场景、US1–US10、Q1–Q8；核心结论是「①⑧⑨ 已在 0.9.2 落地，别按新需求重写；②③ 是写死像素几何与新增内容打架；④ 风险最高；⑨ 有结构化 reject 旁路」。本稿采纳其对 ③ 设计口径、⑨ 旁路、① provider UI 缺口的判断；④ 的宿主能力由主管补充证据（`uiWorkspace.openSession` 可用，但仍需方案阶段在插件上下文实测）。
- **验收设计者**（subagent，只读）：交付 A1–A11 验收条目表（A1 create 成对、A2 resume 成对、A3 三键、A4 指标条、A5 跳会话、A6 preset/来源、A7 工具清单、A8 skills 下拉、A9 重启续跑、A10 打回门控、A11 全局门禁）与 9 条冲突/返工风险。三条被吸收进本稿的硬事实：
  1. `normalizeRun` 显式映射会丢弃 `sessions` 与 `agentPreset`（`src/client/logdrawer.js:522-556`），R4/R5 的第一道修复应发生在归一化层，不是 UI；
  2. 工具清单必须在 `_syncNodeRejectTool` **之后**采集（否则漏 `flow_node_reject`），且受单条事件 8KB 上限约束（`src/runlog.js:80`），故上限取 64 个而非 200 个；
  3. 重启前不 flush 保存是最大返工风险（A9+A10 会「假绿」）：`runtime.restart` 读的是磁盘上的流程，而客户端保存有 700ms 去抖与在途串行化。
- 两条独立复核结论一致：①⑧⑨ 引擎侧已完成、0.10 重心在 resume 成对、重启 UI 与界面可见性；②③ 是当前即 fail 的实现缺陷。
