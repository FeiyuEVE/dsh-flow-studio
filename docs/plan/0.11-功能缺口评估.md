# 0.11 功能缺口评估（四模型独立评审的合并结果）

> 日期：2026-11-07 · 基线：`@feiyueve/dsh-flow-studio` 0.10.0（`36c0297`）
> 方法：四个**只读**评审子 agent 并行跑，各看一个角度、各自限读 6–8 个文件、要求「证据 file:line + 验收判据 + P0/P1/P2」。
> 模型：`lucen-gpt/gpt-6.1-sol`（产品/交互）、`lucen-gpt/gpt-6-sol`（引擎/可靠性）、`lucen-gpt/gpt-6-astra`（复用/生态）、`lucen-gpt/gpt-5.6`（风险/边界）。
> 原计划的 `opencode-go` 非 DeepSeek 模型因**周额度 100%**（`/zen/go/v1/usage`：weekly rate-limited，2026-11-09T00:00Z 重置）全部 429，改用上面四个 GPT 模型。
> 本文只做汇总，**每条标注「已核」= 主线读过源码确认；「待核」= 模型报告、尚未逐行核对**。

## 0. 结论

- 四份评审去重后共 **19 条**，其中 **P0 6 条 / P1 10 条 / P2 3 条**。
- 6 条 P0 里，**4 条是「可信度」问题**（引擎租约失权仍写、外部事件可伪造质量结论、独立验证缺失、并发无上限导致资源洪泛），2 条是**资源/安全**（外部 executor 输出无界、run 无所有权）。
- 与 `docs/guide/overview.md` §路线图**重合**的有 3 条（独立证据源、worktree 管理入口、图中图/片段），本次给出的是「具体落点」，不是新需求。
- 建议 0.11 只做「正确性 + 可信度」六条；交互与复用类排到 0.12，避免再次出现「功能很多但结论不可信」。

## 1. 引擎正确性（4 条）

| # | 优先级 | 问题 | 证据 | 建议 |
|---|---|---|---|---|
| E1 | **P0** | **续租失权后旧实例继续跑**：`renewLease` 失败只 `warn`，而 runstore 允许过期租约被接管 → 两个实例同时写同一 run | 已核：`src/engine.js:5114-5121`（状态机循环）、`src/engine.js:4719-4726`（旧循环）；`src/runstore.js:1929-1938` 明确会 409 | 续租返回 409（确知被接管）时 **abort 整轮**并写 `run/end failed(lease-lost)`；I/O 类错误仍只 warn。红测：模拟续租 409 后旧实例不得再写任何事件 |
| E2 | P1 | **restart 跨进程无原子门**：进程内 `restarting` Set + 「查列表再创建」两步，两个进程可同时通过检查 | 已核：`src/runtime.js:1302-1310`、`src/runtime.js:1322-1334`、`:1380-1424` | 以「旧 runId」为键的跨进程锁（复用 `withLock`）包住「查子 run → createRun → 写 restart 元数据」整段；红测：双进程并发 restart，至多一个子 run |
| E3 | P1 | **续跑查重只看最近 100 个 run**：子 run 被挤出列表后可重复续跑 | 已核：`src/runtime.js:1323-1328`（`listRuns({limit:100})`）、`src/runstore.js:3640-3646` 按 startedAt 截断 | 建「fromRunId → childRunId」定向索引（或在 run 目录按前缀查），与 E2 共用同一把锁 |
| E4 | P1 | **模型自报证据可「数学自洽即通过」**：tests/checks/acceptance 的自报计数能推出 pass，sha256 只证明文件存在 | 待核（模型给的是 `src/engine.js:1476-1577`） | 无可验证 `reportRef` 的 pass 降级为 `claimed`，只有宿主工具事件/签名报告算 authoritative |

## 2. 资源与安全（5 条）

| # | 优先级 | 问题 | 证据 | 建议 |
|---|---|---|---|---|
| S1 | **P0** | **全局并发无上限**：一 run 一 Engine、不排队，每个 run 可再起 agent/外部进程/worktree；并发起 N 个 run 可耗尽 CPU/内存/会话槽/磁盘 | 已核：`src/engine.js:15` 注释明写「没有模块级锁 / 并发上限 / 排队」；`src/index.js:2159-2169` | `createRuntime` 加全局 + 每工作区配额与排队，超限 429（带预计等待）；红测：第 N+1 个 start 得 429/queued |
| S2 | **P0** | **外部 executor 输出无界**：`events` 数组与 `stdoutAll` 持续增长，非 0 退出时把 stderr/stdout 尾巴原样带回错误 | 已核：`src/executor.js:585/609/881/910` | 总字节 + 事件数硬上限（ring buffer），超限杀进程组；返回前复用 `redactArguments` 脱敏 |
| S3 | P1 | **外部 `POST /events` 可伪造质量结论**：白名单里有 `review/verdict`/`acceptance/verdict`/`test/report`/`check/form` | 已核：`src/index.js:715-732` | 外部事件强制 `source=external`，summary 默认排除其权威 verdict（只显示「外部未验证」） |
| S4 | P1 | **上游产物正文是活提示词**：正文缩进后就拼进下游提示词，没有「不可信数据」边界 | 已核：`src/engine.js:1123-1143` | 提示词加不可变 system 级声明 + 把上游内容包成结构化数据段；skill 只按注册 id 解析 |
| S5 | P2 | **run 无所有权**：任意已认证调用者凭 runId 可读/停/删/投消息/改 supervision | 待核（`docs/reference/host-api.md:5-9` 确为「宿主鉴权 + 全权 token」） | run.json 记 owner，路由统一 authorizeRun；单用户部署下先记为「威胁模型待确认」 |

## 6. 建议的落地顺序

1. **0.11.0「可信」**：E1 租约失权停跑、S1 并发配额、S2 executor 输出硬上限 + 脱敏、S3 外部事件标不可信、P1 独立验证执行器、E4 自报证据降级。
   —— 这六条的共同点是「让 run 的结论可信、让资源可预期」，都是能写成红测的。
2. **0.11.x「可干预」**：P2 人工放行、P4 开跑配置面板、E2/E3 restart 原子化。
3. **0.12「可复用」**：R1 入参、R2 导入导出、R3 版本 diff、C1 编辑历史、R4 片段。
