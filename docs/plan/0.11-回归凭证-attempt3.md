## R1/R5 测试覆盖审核

- **R1 正向覆盖**：[runstore 跨进程用例](../../test/runstore.test.mjs#L2504) 由父进程在 `appendEvents.guard` 中持住 `meta.lock`，另起子进程执行 claim；400 ms 后读到 epoch 仍为 1，释放 guard 后 child 退出 0 并报告 epoch 2。源码 [claimLease.markClaimed](../../src/runstore.js#L1940) 现确实在 `withMetaLock` 中读旧世代并写新世代，与 [appendEvents](../../src/runstore.js#L3698) 共用持久锁。旧 epoch 带 fence 写入在 [runstore 测试](../../test/runstore.test.mjs#L2462) 获 409 `LEASE_FENCED`、零事件；这比前轮顺序单进程反例强。
- **R1 边界**：该可控交错夹具只断言 execution 更新受 `meta.lock` 阻塞与最终 child 成功，未在锁持有期间验证子进程已拿到新 `lock.json` 或证明“新租约文件建立后、世代更新前”绝无旧 epoch 提交。因此它不等于对所有 claim/append 时序的穷尽证明；本节点没有另行复现此窄窗口，不能写成实测失败。
- **R5 HTTP 跨读端**：[host 测试](../../test/host.test.mjs#L2194) 对同一有哈希的宿主报告，先确认 summary 检查 pass 且 export 文本 pass，删除报告副本后确认 summary 缓存失效、权威通过数归零、export unknown；前轮的 export 漏参反例已进入用例。源码 [summary 与 export](../../src/index.js#L2184) 两路均传事件和 run 目录给共享验证器；[共享验证器](../../src/runstore.js#L2165) 重新读取报告并比对 sha256，[runstore 测试](../../test/runstore.test.mjs#L2566) 对副本删除撤销授信有独立断言。[runtime 自审](../../src/runtime.js#L879) 也调用该共享验证器，但本节点没有找到“报告损坏后触发真实自审并核对裁决”的端到端用例；源码核对成立，不把它冒充真实调度链取证。
