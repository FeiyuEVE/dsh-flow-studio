## 新断言静态复核

- R1：[runstore 双进程交错测试](../../test/runstore.test.mjs#L2504) 在父进程 append guard 持 `meta.lock` 时启动子进程 claim，400ms 后断言 `execution.epoch === 1` 且 `lock.json.ownerId` 仍为旧 owner；释放后子进程 claim epoch2，旧身份带 fence 再写返回 `LEASE_FENCED` 且无事件。当前[claimLease](../../src/runstore.js#L1922) 将读取世代、写 execution、替换 lease 文件置于同一 `withMetaLock`，顺序为先 execution 后 lock.json。该测试确实锁定前轮的“新租约先可见”窗口，但没有在此用例中主动模拟旧 owner `renewLease` 的 409 时序；后者应由故障注入同事独立复核。测试绿不是遍历所有可能竞态的数学证明。
- R5：[host HTTP 用例](../../test/host.test.mjs#L2138) 用真实 route 对同一已登记报告验证 summary/export 正常 pass；以同长度内容覆盖现有副本后断言 summary 缓存失效、权威通过归零、export unknown；恢复原文后重新授信，删除副本后再次撤权。该正式用例已包括前轮缺失的“内容篡改”断言，对取消 sha256 字节比较应可红，但本节点**未执行反向 mutation**，红色退出码由故障注入成员核验。[runstore 的独立验证器用例](../../test/runstore.test.mjs#L2579) 仍只测试删除副本，不能单独证明哈希比较可红。runtime 自审接共享验证器的源码链可核，但尚无真实 supervision 报告损坏端到端测试，不写为完整 E2E 通过。
- R3 资源用例参与本轮全量测试：96 MiB heap 隔离 runner、20 轮 OUTPUT_LIMIT、进程组终止与逐轮孙进程退出。本轮日志记录 982 个外部采样点，峰值相对基线 +28.9 MiB、首末五轮结束点中位差 +7.6 MiB。采样器只断言基线 ≥5 个样本、未量测定时器实际 10ms 间隔，结果只代表本机 POSIX 执行。
