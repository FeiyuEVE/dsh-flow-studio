## R1/R5 测试覆盖

- R1： [runstore 测试](../../test/runstore.test.mjs#L2504) 的父进程 `appendEvents.guard` 先持 `meta.lock`，子进程尝试 claim；400ms 后断言 execution 仍 epoch1，释放 guard 后子进程成功得 epoch2。另有接管完成后带旧 fence 的写返回 409、零事件。该夹具**未**断言新 `lock.json` 在 epoch 更新前已可见，也未尝试在旧 owner 续租返回 409 后再放行旧 append。因此它只覆盖世代写入被锁阻塞，不覆盖已知 409 后零旧写的完整交错；本轮质量工程师未执行额外三进程故障注入，不能从 944 组推断该问题已解决。
- R5：[host HTTP 用例](../../test/host.test.mjs#L2138) 对同一登记报告的 summary 与 export 检查 pass；删除副本后 summary 缓存失效、两端降 unknown。[runstore 用例](../../test/runstore.test.mjs#L2566) 测报告存在通过、删除后不授信；**未测试同路径内容被篡改**，所以把验证器中 `digest !== record.reportSha256` 比较去掉时，该删除用例仍可能绿，不能把删除测试当哈希比较的可红凭证。[runtime 自审](../../src/runtime.js#L879) 静态接共享验证器，但真实 supervision 发现损坏报告并降权的端到端用例尚未查到。
- R3 资源用例仍在本次 `npm test` 中执行：96MiB heap 隔离 runner、20 轮 `OUTPUT_LIMIT`/组杀与逐轮孙进程检查；原始日志第 1198 行记录 **985 样本，RSS 首末五轮中位差 +8.5MiB，外部峰值增量 +30.3MiB**。此处只是门禁复核，不独立做 mutation 或跨平台声明。
