## 2. 每条实现

### R1/E1：续租失权后旧实例立即停跑（持久 fence + 原子收口）

- 续租统一走 `engine._renewLeaseOnce(runId)`（single-flight，可注入）：`409` 走 `_handleLeaseLost`，其它 I/O 只 `warn`。
- 租约随机 `ownerId`；`claimLease` 整体在 `withMetaLock`（跨进程 `meta.lock`，与 append fence 同一把锁）内完成：先递增 `run.json.execution.epoch` 并绑定 `{epoch, ownerId, state:'active'}`，再发布 `lock.json`。因此「新租约可见」与「旧 owner fence 失效」同临界区，旧 owner 续租 409 后在飞写会被 fence 拒绝；`renew/release` 按 ownerId 精确校验（不带 ownerId 的旧调用保持 pid/host 兼容）。
- **持久 fence**：`appendEvents` / `writeRunMeta` 接受 `{ownerId, leaseEpoch}`，在各自存储锁内复核 `meta.execution`；不符抛 409 `LEASE_FENCED` 且整批不写。引擎 `_append`、`_persistLive`、`_patchRunBinding` 全部带 fence；fence 拒绝等价于失权，立即收口。
- `_handleLeaseLost`：置 `leaseLost`、停 timer、封会话观察、abort；旧实例 `_append` 直接丢弃。
- **原子 finalizer**：`finalizeEpoch` 构造 run 范围 end 后用 `appendEvents.guard` 在 append 锁内复核 epoch/owner；不匹配则 `LEASE_FENCED` 整批不写，再追加 `terminalScope='instance'` 事实，不改 `run.status` / `endedAt` / 接管者 `execution`。幂等键 `loss:<epoch>`。
- 读端统一忽略 instance：`appendEvents` meta reducer、`repairRunStates`、`runlog` 时间线、`audit` 的 status/failure/aborted、`restart` 的 `run/end` 选择。
- 宿主检查执行中失权：runHostCheck 收 abort 取消，落地前复查 `leaseLost`，不补 `check/form` / 宿主产物。

### R2/S1：全局并发配额 + 每工作区配额 + 有限 FIFO + restart 可重试

- 默认 `global=4` / `perWorkspace=2` / `queueMax=8` / `queueTimeoutMs=15000`；env 完整数字校验，非法回默认并写 warnings；工作区满立即 429，全局满严格 FIFO，队满/超时/断连 429；进程单例挂在 `globalThis[Symbol.for(...)]`。
- `runtime.start` 未启用准入时保持 0.10 行为；启用时先登记再 acquire，排队期间不建 Engine、不写 run/start；入队前冻结 `flowSnapshot`，排队期间保存流程不改变执行命令。
- restart 在准入 429 时保留 pending 子 run（`restart.startRejected`、`started=false`），错误带 `childRunId`；下一次 restart 复用同一 child 与 resumePlan。
- `index` 生产 runtime 启用 env 配额；429 序列化带 `code/scope/reason/active/max/limits/retryAfterMs` 与 `Retry-After`；详情动态合并 `admission`；`tools.failureOf` 识别 429。

### R3/S2：外部 executor 输出有界 + 脱敏

- `process-output.js` 在 decode 前按 Buffer 原始字节累计；保留文本 ≤ maxBytes；事件额度 maxEvents。
- 超限先置 `OUTPUT_LIMIT` 再杀进程组；唯一 settle 返回 `reason/code='OUTPUT_LIMIT'`、`truncated`、`receivedBytes/retainedBytes/eventCount/killScope`；迟到 close/error 不改判。
- 所有可见文本先 `redactText`，事件对象 `redactDeep`；默认 8 MiB / 5000 条，env 可覆盖。
- **A3.2 取证**：隔离 runner（96MiB heap）+ 外部 10ms RSS 采样（500ms 基线）+ 20 轮无限输出；逐轮输出上限、5s 内终止、`killScope=group`、孙进程退出（僵尸态算退出）；末 5 轮 RSS 中位差 ≤32MiB、外部峰值增量 ≤128MiB。

### R4/S3：外部事件不能伪造质量结论

- 外部 POST 事件强制 `source=external / producer=external / authority=unverified`，剥离受保护元数据；聚合前分区 external，不覆盖内部证据 / 冲突 / 宿主失败。
- summary 增加 `externalCount` 与有界 `externalObservations`；导出与客户端标「外部未验证」，权威计数排除 external。

### R5/P1：宿主独立检查（私有登记 + 防伪凭证 + 报告完整性）

- `node.check` 配置归一化 / 校验（command / expectExitCode / timeoutMs / reportPath），旧 `extras.check` 不升级。
- `host-check.js` 固定 `sh -c` 单 argv，真实 spawn + close + 退出码匹配，报告前后 fingerprint / 安全打开 / 有界读 / sha256，进程组终止。
- 引擎在节点收口后执行检查，创建一次性凭证登记 `verification/<executionId>/record.json`；结果写 `check/form` + `producer=host` 记录 / 报告副本。为适配 `extra` 有界化，可信元数据同时写扁平键 `verificationId / verificationKind / reportSha256`。
- **共享验证器**：`runstore.buildHostExecutionVerifier` 同时供 HTTP summary/export 与 runtime 自审使用；核对 runId / 节点 / attempt，并在记录有 `reportSha256` 时**重读持久化报告副本字节**比对，副本缺失 / 内容篡改 / 损坏即不授信（内容篡改用同长度字节覆盖验证）。`hostEvidenceDigest`（记录 + 副本哈希）参与 summary 缓存比较，报告变化使缓存失效。
- 启动前门禁：check 开关未开 400 `HOST_CHECKS_DISABLED`，非法配置 400 `HOST_CHECK_INVALID`；检查器新增 h() 表单。

### R6/E4：自报证据降级为 claimed（tests / checks / acceptance）

- 引擎回退到自写报告时对 tests / checks / acceptance 打 `extra.generatedReport=true`。
- 聚合把 `model-claim + generatedReport` 只计 claimed，指标 unknown；三项指标带 `claimedPassed / authoritativePassed / authoritativeTotal / coverageRatio`，quality 带汇总与 `authorityCoverage`；三项全 claimed → 至少 unknown。
- **无验证器默认不信任**：`classifyEvidenceAuthority` 在没有 `verifyHostExecution` 时把 producer/authority host 视为 claimed（避免离线/审计入口被伪 host 洗白）；宿主失败与更高 seq 的自报仍不能洗绿。
- 客户端展示「权威通过 / 自报通过 / 权威覆盖」，缺字段显示 unknown。

## 6. 剩余偏差与已知边界

1. **fence 覆盖边界**：引擎事件 / live / 绑定写已带 fence；`runstore` 对不带 fence 的调用（HTTP 外部观察、启动恢复、测试夹具）保持允许，这是「宿主/运维通道」与「旧执行实例」的边界。检测旧实例依赖其写路径经过引擎并带 fence；同进程直接调用 `runstore.appendEvents` 的伪造者不在本期威胁模型内。
2. **finalizeEpoch 的幂等扫描在 guard 事务外**：重复收口仍可能并行进入 append，但 guard 保证只有持有当前 epoch 的一方能写 run 范围；重复 run 范围 end 由幂等键与终态检查兜底。极端窗口（guard 通过后、写盘前被接管）依赖 append 同一锁内的 claim 串行化，仍有毫秒级理论窗口。
3. **未新增 `evidence.js` / `run-projection.js` 独立模块**：instance 投影与验证分别落在 `runlog` / `runstore` / `index` 的复用函数中；没有签名报告 / 公钥验证。
4. **R5 凭证是进程内 capability（WeakSet）**：防模型 / HTTP / 普通 artifact writer 伪造；同 uid 恶意进程篡改不在本期隔离范围。报告副本在节点 `artifacts/` 下，以 `producer=host` + 私有登记双重标记。
5. **外部事件仍计入 token / skill / agent activity 统计**（只从权威证据、冲突、findings、进度、质量中排除）；`externalObservations` 只保留最近 50 条。
6. **S2 内存有界**：结果文本 / 事件 / tail 有硬上限；`custom` 最终 text 是前 maxBytes 的保留文本，没有独立原始 ring 回放。规则 4 额外放行路径形态长串，与 `engine.redactArguments` 存在有意差异。
7. 客户端只用既有 `h()`，无 JSX、无新增运行时依赖；`docs/design/`、`docs/DESIGN*.md` 未改；未 `git push` / `npm publish`，未重启任何服务。
