## 2. 每条实现

### R1/E1：续租失权后旧实例立即停跑

- 续租统一走 `engine._renewLeaseOnce(runId)`（single-flight，可注入 `renewLease` / `leaseRenewMs`）：`409` 走 `_handleLeaseLost`，其它 I/O 错误只 `warn` 并保留下一次续租机会。
- `_handleLeaseLost`：置 `leaseLost`、停续租 timer、封会话观察入口、`abort(code='LEASE_LOST')`；不在这里写 `run/end`。
- 旧实例写门：`_append` 在 `leaseLost` 时丢弃业务事件并返回 `dropped`；`_persistLive` / `_patchRunBinding` 在失权后不再改写接管者的 `live` / 绑定。
- 唯一收口：双循环 finally 在失权时跳过旧的 `run/end`、`live:null`、绑定回写与 `releaseLease`，只调 `runstore.finalizeEpoch`——按 `extra.idempotencyKey='loss:<epoch>'` 幂等追加**一条** `run/end failed`（`reason` 含 `lease-lost`、`extra.code='LEASE_LOST'`、`terminalScope='run'`）；run 已是终态时不覆盖。
- 租约对象保留 `acquiredAt` 作为本次执行的 epoch 身份（不再只存 `true`）。

### R2/S1：全局并发配额 + 每工作区配额 + 有限 FIFO

- `createAdmission`：默认 `global=4` / `perWorkspace=2` / `queueMax=8` / `queueTimeoutMs=15000`；env 完整字符串数字校验，非法回默认并写 `warnings`（不回显原值）；`perWorkspace` 有效值取 `min(value, global)`。
- 工作区满立即 429 `workspace-full`（不排队）；全局满进严格 FIFO（只看队头，不越过被工作区挡住的队头）；队满 / `queueMax=0` / 超时 / abort 分别 429 `queue-full` / `queue-timeout` / `cancelled`；重复 runId 409。
- 进程单例挂在 `globalThis[Symbol.for('dsh-flow-studio.admission.v1')]`；已有 controller 与不同 limits 同时存在 → 抛可读错误，不悄悄开第二本账。
- `runtime.start`：未传 `admission` / `admissionLimits` 时保持 0.10 旧路径；启用时先同步登记再 `acquire`，**排队期间不创建 Engine、不写 `run/start`**，grant 后 `markRunning` + `engine.start`；`settleInstance` / start 抛错 / dispose 各释放一次（一次性包装）。
- `index` 生产 runtime 传 `admissionLimits: {}` 启用 env 配额；429 序列化保留 `code/scope/reason/active/max/limits/retryAfterMs` 并带 `Retry-After`；`GET /runs/<id>` 动态合并 `admission`（不落盘，run.json 仍 pending）；`tools.failureOf` 识别 429 并标明可重试。

### R3/S2：外部 executor 输出有界 + 脱敏

- `process-output.js` 在 decode 前按 Buffer 原始字节累计 `receivedBytes`（单调、不因淘汰回退）；保留文本取前 `maxBytes` 个 UTF-8 字节；事件额度 `maxEvents`。
- `runExternalExecutor` 超限：先置 `interruptReason='OUTPUT_LIMIT'`，再杀进程组，唯一 settle 返回 `reason/code='OUTPUT_LIMIT'`、`truncated=true`、`receivedBytes/retainedBytes/eventCount/killScope`；迟到 close/error 不再成功、不再 `onEvent`。
- 所有进入 `events/tail/text/message` 的文本先 `redactText`，事件对象 `redactDeep`；tail 上限 `min(maxTail, maxBytes)`。
- 默认上限 `8 MiB / 5000 条`，env `FLOW_STUDIO_EXECUTOR_MAX_OUTPUT_BYTES` / `_MAX_EVENTS`（完整字符串校验）。
- 脱敏规则 1–3 与 `engine.redactArguments` 一致；规则 4（≥32 连续可疑串）收紧为「同时含至少两类字符」，避免把既有夹具的纯小写长串误伤，差异在模块注释里写明。

### R4/S3：外部事件不能伪造质量结论

- `POST /runs/<id>/events` 仍整批白名单校验；落盘前服务端强制盖 `extra.source='external'`、`producer='external'`、`authority='unverified'`，并剥离来客自带的 `source/producer/authority/verification/executionId/trustedExecution/terminalScope/leaseEpoch/epoch/idempotencyKey/generatedReport`。
- `runlog` 在任何权威索引（artifact/hash/owner、conflict、current attempt、stale、findings、review、progress）之前先分区 external；外部同 path / 同 itemId / 同 ruleSetId 的 pass/fail 不覆盖内部证据、不制造冲突、不清宿主失败。
- `summary` 新增 `externalCount` 与有界 `externalObservations`（最近 50 条）；时间线与 markdown 导出带「外部未验证」附录，权威通过计数排除 external。
- 客户端事件行加「外部未验证」徽标，不再只按裸 `verdict` 渲染绿色。

### R5/P1：保存的检查命令由宿主独立执行

- `model.js`：`NODE_KNOWN_FIELDS` 增加 `check`；`normalizeNodeCheck` / `validateNodeCheck` 覆盖 command（必填 ≤2000、拒 NUL）、`expectExitCode`（0–255，默认 0）、`timeoutMs`（1000–1800000，默认 600000）、安全相对 `reportPath`（拒绝绝对路径 / 盘符 / UNC / 反斜杠 / `..` / 空段）；非法配置保留可诊断，不静默丢成未配置；旧 `extras.check` 不升级为可执行配置。
- `host-check.js`：`sh -c <完整命令>` 单 argv、`shell:false`、不 split / 不插值 / 不读 stdin；真实 spawn + close + 退出码匹配才可能 pass；报告执行前后 fingerprint（inode/mtimeNs/ctimeNs/size/sha256）、`O_NOFOLLOW|O_NONBLOCK`、有界读（limit+1）、前后 fstat 一致；缺失 / 陈旧 / 软链 / 超 1 MiB → fail；进程组终止，输出脱敏后有界。
- `engine`：节点结构化结果写完、`node/end` 之前执行 `_runHostCheckOnce`，按 `(runId,nodeId,attempt,command)` 去重；结果写 `check/form`（`ruleSetId='host:<nodeId>'`、`executor='host'`、pass/fail/skipped 与 1/0 计数）与 `producer=host` 的执行记录 / 报告副本产物。宿主结果只影响 quality，不改 agent verdict 与 next/reject。
- `index` 启动前拦截：配了 check 但 `FLOW_STUDIO_ALLOW_HOST_CHECKS !== '1'` → 400 `HOST_CHECKS_DISABLED`；配置非法 → 400 `HOST_CHECK_INVALID`。
- 检查器新增「宿主检查（可选）」表单（命令 / 期望退出码 / 报告路径 / 超时 / 清除），沿用既有保存链，不新增旁路。

### R6/E4：自报证据降级为 claimed

- 引擎写 `tests` / `checks` 事件时，若 `reportRef` 退回**引擎自己刚生成的**报告（没有独立可复核引用），打 `extra.generatedReport=true`。
- `runlog`：`model-claim + generatedReport` 只计 `claimed`，指标 state 降 `unknown`（reason 含「自报报告 / 缺独立证据」）；三项指标新增 `claimedPassed / authoritativePassed / authoritativeTotal / coverageRatio`，`quality` 汇总带 `claimedPassed / authoritativePassed / authoritativeTotal / authorityCoverage`；三项全部只有 claimed 覆盖时 quality 至少 unknown。
- 宿主检查失败优先：同一 ruleSetId 的最后一条宿主执行是 fail 时，更大 seq / 更高 attempt 的模型自报 pass 不能解除，只能由更晚的宿主 pass 解除。
- 客户端 40px 条展示「权威通过 / 自报通过 / 权威覆盖」，字段缺省显示 unknown。

## 6. 偏差与已知边界（相对 0.11 方案）

1. **未实现完整 epoch/owner 条件写与 instance 终态投影**：租约身份用 `acquiredAt`，`finalizeEpoch` 用幂等键保证「一个失权 epoch 一条 run/end」，但接管者已持新租约时仍会落下 run 范围 failed（没有 `run-projection.js` 的 `terminalScope='instance'` 读端统一投影）。跨进程 takeover 的「不覆盖接管者 status/live/lease」只做到跳过 live / 绑定 / release 与终态覆盖。
2. **未新增 `evidence.js` / `run-projection.js`**：R6 的验证与汇总落在 `runlog.js` 纯函数 + 引擎的 `generatedReport` 标记；没有独立验证服务，也没有签名报告 / 私有 `verification/` 目录。
3. **R6 只对 tests / checks 打 `generatedReport`，acceptance 仍保留历史的兜底通过**：G1-c 既有用例依赖「模型不写 evidenceRef 时 acceptance 仍可 pass」；acceptance 的 claimed 降级留到后续（runlog 侧的 `generatedReport` 分支已存在，接上即可）。
4. **R2 队列快照未冻结 `check` 命令**：engine 在出队后的 `start` 里读当前保存的流程；排队期间保存流程会改变实际执行命令。restart 在准入 429 时仍可能留下一个 pending 子 run（既有 restart 流程未回滚）。
5. **R5 执行记录 / 报告副本放在节点 `artifacts/` 下**，用 `extra.producer='host'` 与 engine-only 写路径区分，而不是私有 `verification/<executionId>/`；同 OS 用户的敌对文件篡改不在本期隔离范围（方案 §7.3 已声明）。
6. **外部事件仍计入 token / skill / agent activity 统计**（只从权威证据、冲突、findings、进度、质量中排除）；`externalObservations` 只保留最近 50 条。
7. **S2 的内存有界**：结果文本 / 事件 / tail 都有硬上限；但 `custom` 的最终 text 仍是前 `maxBytes` 的保留文本，解析对象与事件对象按额度共同受控，没有实现独立的原始 ring 回放。为不误伤既有「长路径必须原样回显」的 RCE 夹具，规则 4 额外放行了路径形态长串（含 `/` 且每段为安全字符）；规则 1–3 不受影响，这是与 `engine.redactArguments` 的已知差异（`process-output.js` 注释写明）。
8. 客户端只用既有 `h()`，无 JSX、无新增运行时依赖；`docs/design/`、`docs/DESIGN*.md` 未改；未 `git commit` / `push` / `npm publish`，未重启任何服务。
