## 旧反例重放与资源取证

运行 `node /tmp/fi3-replay.mjs` 实际 exit 0：创建 old epoch1 过期租约，new epoch2 接管后以旧 `{ownerId,leaseEpoch}` 调用 `appendEvents` 被 409 `LEASE_FENCED` 拒绝；日志输出 `staleRejected:true,oldEvents:0,metaEpoch:2`，夹具 `/tmp/fi3-takeover-EMH7if`。同脚本对没有登记的伪 `producer=host` check/form 调 `summarize([spoof],{})` 得 `spoofState:'unknown',spoofAuthoritativePassed:0`。两条前轮**带旧身份的业务写**与**无 verifier 自报 host**反例均已转绿。未传 fence 的裸存储 API 仍属于宿主/运维通道，不能把裸 append 当旧引擎路径。

主树 `node test/process-output.test.mjs` exit 0，`/tmp/fi3-logs/process-output.green.log:21-22` 报告隔离 96MiB runner 的 20 轮 `OUTPUT_LIMIT`、外部 10ms 采样共 987 个样本、末五与首五轮 RSS 中位增长 8.8MiB、外部峰值相对基线 29.2MiB；真实子进程和孙进程每轮按 group 收口。测试源码 [A3.2](../../test/process-output.test.mjs#L668) 有 500ms 启动基线与 10ms `/proc/<pid>/status` 采样，已独立跑过；本节点未单独对采样器本身做 mutation。

## 新发现：同一宿主报告的导出错误降级

只在隔离副本 [host 测试](../../test/host.test.mjs#L2138) 已有真实 route/run 夹具中加一条断言：保存有 `reportSha256` 的登记与报告副本后，原断言先确认 `GET /summary` 的 `checks.state='pass', authoritativePassed=1`；随后 `GET /export` 必须显示同一条 `| 规范 | 0 | 1 | 1 | 100.0% |`。`node test/host.test.mjs > /tmp/fi3-logs/export-compare.red.log 2>&1` **exit 1**，失败断言 `export must preserve authoritative host pass shown by summary`；原始导出实际上写 `| 规范 | unknown | 1 个规范检查声称来自宿主，但没有可验证的宿主执行登记... |` 与 `| 规范 | 0 | 0 | 1 | 0.0% |`（日志 77、135–145 行）。去掉新增断言后副本 host 复绿 exit 0。根因 [export 路由](../../src/index.js#L2272) 调 `makeHostExecutionVerifier(runId,hostExecutions)` 未传 `events,runDir`，而 [验证器](../../src/index.js#L367) 对含 reportSha256 的报告要求这两个参数才能读副本；相同 run 的 [summary 路由](../../src/index.js#L2245) 传齐。**这是已实测的跨读端不一致，不是伪 host 获权威；导出错降为 unknown。** 建议 P1 打回 R5/R6：统一装配验证器，补 summary/export 同源断言及反向 mutation。
