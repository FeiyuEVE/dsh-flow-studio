## 1. 结构裁决与上游衔接

已读取全部 [0.10 需求](0.10-需求.md)、[方案](0.10-方案.md)、[结构](0.10-结构.md)、[开发记录](0.10-开发记录.md)、[测试报告](0.10-测试报告.md)、[审查报告](0.10-审查报告.md)。0.10 的会话路由、保存队列、节点工具门控与 restart 会话继承继续遵守；“无全局上限”和“跨节点文件即独立证据”由本轮需求覆盖。历史结构中 240/120 的抽屉高度已被开发/测试修为 340/200，本期不借可信改造重排几何，也不顺带处理其余 0.10 UI 技术债。

本阶段保留上游 C0–C6 顺序，新增两项必要拆分：`src/run-projection.js` 负责无 Node 依赖的生命周期投影；`src/evidence.js` 负责宿主证据验证与摘要装配。加上方案已有的 `src/admission.js`、`src/process-output.js`、`src/host-check.js`，共五个新增 Host 源模块。拆分的原因是 [存储](../../src/runstore.js) 已依赖 [runlog](../../src/runlog.js)，而浏览器不能加载带 `node:buffer` 的 runlog；验证器也不能仅存在 [HTTP 入口](../../src/index.js)，否则 [runtime](../../src/runtime.js) 自审与 [工具](../../src/tools.js) 的 flow_watch 会得到不同质量结论。

以下结构补充关闭实现缺口，无需打回上游：受保护 extra 字段预留预算；fence 拒绝不得触发存储故障降级写；新客户端对旧 Host 的检查能力握手；私有检查命令的公共序列化；摘要文件完整性不按事件 seq 永久缓存。这些补充不更改上游六项业务裁决。

## 2. 模块与调用方向

箭头表示 import/调用依赖。组合层可以装配下层服务；下层不读组合层全局变量，不反调路由。注入的回调仅承载窄接口，不能传入整个 Engine 或 HTTP env 供下层任意调用。

```text
index（鉴权/HTTP装配） ──→ runtime ──→ engine
         │                    │          ├─→ host-check ─→ process-output
         │                    │          ├─→ executor ───→ process-output
         │                    │          ├─→ runstore ───→ runlog
         │                    │          └─→ flowmachine
         │                    └─→ admission
         ├─→ evidence ──→ runstore / runlog / run-projection
         └─→ tools（注入同一 evidence 服务）
runtime / tools ──→ evidence ──→ 只读验证快照
runtime / tools ──→ audit（注入已算 summary / projection）
runstore / runlog / flowmachine / restart / audit ──→ run-projection
client：page → inspector / logdrawer → api；logdrawer → run-projection
model：Host / client 共用纯配置归一化
```

既有 `restart → engine`（选首节点/next 的 helper）是 0.10 已存在的倒挂，本轮不扩大；新增终态投影直接依赖底层 run-projection，禁止新增 `engine → restart`。inbox 的现有 pending 分支只记录启动输入并返回 `mode:'started'`，不调用 start；本文启动图中的 inbox 箭头仅指后续显式启动或调用方已触发的 runtime 路径，不新增自动启动语义。需要启动的消息入口只接受 runtime 启动回调注入，不为消息新建 Engine，也不 import runtime。supervise 只消费投影后的状态/事件，不自行启动检查或授信报告。

## 3. 数据流：执行、事件与摘要

### 3.1 启动与 run.json

```text
HTTP / flow_start / restart / inbox
 → runtime.start 同步登记 resolving ticket（root+runId去重）
 → 只读 preflight：流程合法性、来源workspace realpath、检查能力与开关、固定flow/check快照
 → admission reserve 或有限FIFO（不建Engine/worktree/session，不写run/start）
 → grant后再次核 ticket generation → Engine.start(私有快照, signal)
 → runstore claim(epoch,ownerId) → capability → fenced 绑定/快照/run/start
 → 正常/失败/stop finalizer → 资源确认退出 → settleInstance → release一次
```

来源工作区取原绑定 realpath；worktree 只改变执行 cwd，不改变工作区计量。`reserved/starting/running/terminating` 占槽；queued/resolving 不计 active，resolving 有界时限与取消。队头再次核两级额度，严格 FIFO；工作区满立即429。start promise 获 Engine.start 成功才成功；GET详情动态合并 admission，run.json 仍 pending，不新增持久 queued 状态。参数/429 默认值引用 [方案参数与错误表](0.11-方案.md#9-新增契约表默认与边界)，不复制另一套。

run.json 是执行投影与私有检查快照载体，JSONL 是事件事实。`execution` 保存当前世代；`checks` 保存本 run 固定命令和 digest，内部读取与公开 serializer 分开。公共 GET/list/light/start/restart/append 返回的 run 对象都经过同一公开投影；tools jsonSafe 也不能直接透传私有 meta。公开 checks 只含 node/check标识、脱敏摘要、digest与状态，不含 command/env/实际私有cwd。保存流程的全权编辑接口可回填 command；它与公共运行详情权限面不能混为一谈。

restart 沿 0.10 新 run/继承会话语义；准入失败保留 childRunId、resumePlan 和 startRejected 可重试标识，不删除审计目录；未写 run/start 的同 child 重试再准入。已经运行过的 child 按既有世代规则续跑，不能重建第二份。restart 读取当前已保存 check，新 run 不继承旧 verification 权威，也不把历史跳过节点强行执行一遍检查；对应缺少本 run 有效证据的项保持 unknown。跨进程 restart 原子索引仍为后续范围。

### 3.2 租约失权与全部写入口

```text
renewLease single-flight → 409
 → 同一回调 writeClosed/leaseLost + 停timer + detach观察 + abort(LEASE_LOST)
 → 停host-check/external进程组、封迟到回调、有限dispose
 → 存储中已进入提交的事务完成；未提交旧队列逐个fence拒绝
 → 唯一 _finalizeRunOnce → runstore.finalizeEpoch(loss:<epoch>)
 → 相同epoch：run/end failed、清本epoch投影；新epoch：仅instance end
 → runtime摘本实例、清本地调度、幂等归还配额；不清接管者持久supervision
```

非409 I/O只 warn。失权旧实例仅允许专用 finalizer 写一次失权事实；reason含 lease-lost，code为LEASE_LOST。runstore 核 ownerId+epoch并持同一跨进程 mutation 锁，再提交事件/meta/业务文件。锁不能持有着 await agent/进程/dispose；内部 unlocked helper只允许锁内调用，不嵌套锁。

必须覆盖 `_append/_persistLive/_persistMachine/_persistNodeSessions/_patchRunBinding/_writeArtifactFile/_writeExecutorSchema`、inbox执行状态、runtime.patchRunJson/saveSupervision/settledHook、session/member/tool观察、产物最终rename及repair。只挡 append 不挡文件写不合格；临时文件使用epoch隔离且条件发布。外部 observation 使用受控 external capability，仅追加观察与安全计数，不获 engine meta/lease写权。

**条件拒写与真实磁盘故障必须分流**：[存储](../../src/runstore.js) 的 appendEvents catch 当前会 markStorageFailure/writeMetaUnlocked。新增 LEASE_LOST/FENCE_REJECTED 必须在进入该 catch 前拒绝，或 catch 首先原样抛出，绝不把预期失权当存储故障再写 failed 覆盖接管者。真正 I/O失败写.error/meta也要核对应epoch；无法核权只记当前实例诊断，不越权修新owner。

投影不简单过滤 `event.epoch !== currentEpoch`：接管前已提交的合法节点passed/进度仍是历史事实。run-projection仅将 instance end 排除于run终态、拒绝不适用的世代生命周期覆盖；保留已提交业务事实供现有attempt失效规则处理。旧无epoch事件按历史语义，若带新受保护字段却不完整/不合法则不退回legacy，不得把损坏instance end误当run级终态。当前世代与run级终态由持久metadata及合法日志恢复联合裁决，repair不能任取最后end。

全读端同批适配：runstore reducer/repair/list/detail、runlog progress/quality/export、engine恢复、flowmachine重放、restart失败节点推导、audit终态、supervise/run及node调度、logdrawer状态回退。审计时间线仍显示旧实例失权失败；接管者可能done且最后一条日志是旧instance失败，主状态仍done。

### 3.3 宿主检查与可信质量

```text
正式agent结论 → engine._writeStructured（model/engine来源）
 → _runHostCheckOnce(run,node,attempt,checkId) 缓存Promise
 → host-check静态argv/env/cwd + executor.runBoundedProcess
 → process-output累计限额/脱敏；报告普通文件/新鲜性/有界读取
 → engine调用runstore专用commitVerification(fence,执行事实,脱敏报告)
 → 私有报告+记录先持久化 → artifact/write + check/form受保护引用
 → node/end（保留agent verdict） → next/reject
```

command来自preflight固定的保存流程，不能从prompt/input/start body或模型结果覆盖。POSIX静态 `sh -c savedCommand` 是一个完整argv元素，Node spawn shell:false；具体参数/报告规则沿 [方案宿主检查](0.11-方案.md#7-r5保存的检查命令与宿主执行报告)。失权优先于取消记录：检查在跑时409先杀组，其close/onEvent不能追加check/artifact/node/end。检查自身超时必须HOST_CHECK_TIMEOUT并记fail；仅用户stop或上层run/node取消且仍持权时可记skipped/派生unknown，不能把检查自身超时降级为skipped。host失败只影响quality；不改agent verdict，不新增自动reject，允许run done与quality fail并列。

```text
HTTP summary/export、runtime evaluateRun、tools auditRunContext
 → 同一 evidence.summarizeRun({run,events,now})
 → 按run当前元数据/有效attempt建立候选集合
 → runstore只读校验私有登记+完整副本（有界，错误转unknown）
 → 不可变verificationSnapshot（opaque lookup，不接收事件自带authority）
 → runlog.summarize(events,{projection,verifyEvidence:同步lookup,engine,now})
 → summary/quality + audit结果 + UI/markdown
```

evidence 服务的输入 events 与run采用同次读取上下文；验证后如世代/seq变化，重取一次或返回明示unknown，不能合并不同attempt的证据。调用次数/候选规模服从既有读取上限，截断时标truncated并禁止据不完整覆盖判pass。纯runlog同步查快照，不在循环里开文件；runstore不反向依赖evidence。auditWorkflow优先使用注入summary/projection，独立调用缺服务时只可保守unknown，不能默认“报告存在即执行”。renderRunMarkdown已有第三个summary参数，必须传同一服务摘要。

summaryCache当前按lastSeq/eventCount/engine复用，报告删除/损坏不会改变seq。本期禁用带权威结论的跨请求缓存，每次重新验证报告；以后若优化需验证文件身份/内容失效链，不能只加TTL并继续对已损坏报告绿灯。runtime/flow_watch与HTTP使用同一adapter，不能留HTTP专属makeEvidenceVerifier作为第二真相。

聚合先分 external，再建artifact/hash/owner/latest/conflict/current attempt/stale fail/findings索引。外部只进入观察分区。宿主失败事实优先；缺报告/纯计数/跨节点自写文件/无验证器仅claimed/unknown；同一检查有效新attempt真实通过才解除旧host fail。真实host check只覆盖其绑定项目，不把命令exit0外推为所有tests/acceptance通过。保留声明与已验证指标，主绿灯依据权威覆盖与既有未解决发现规则，完整判定引用 [方案判定表](0.11-方案.md#8-r6权威规则和-quality-判定表)。

| admission详情 | admissionOf→index public run projector→client.normalizeRun/mergeRunDetail | 非持久；state仅queued、合法时间/正position/timeoutMs；缺失null | HTTP或start body自带admission忽略，不能伪造获准 |
| 保护extra | runlog新增normalizeProtectedExtra；store的受控event提交context；index.stampExternalEvents | 来源/producer/authority枚举；leaseEpoch正整数；terminalScope枚举；executionId/checkId/lossKey扁平受限标量 | 仅内部context赋值；来客同名键剥离覆盖；nested verification不进入extra，完整记录私有存储 |
| verification记录/报告 | runstore.commitVerification/readVerifiedExecution；evidence快照 | run/node/attempt/check/digest/exit/times/hash绑定；缺失/不完整不pass；报告≤1MiB安全读副本 | 路径namespace与普通artifact写隔离；producer=host仅标签不授信；同uid任意篡改不是本期隔离保证 |
| summary质量 | runlog.computeQuality/summarize；client归一化消费 | claimedPassed/authoritativePassed/authoritativeTotal/authoritativePassRate/coverageRatio；非负整数、分母清晰，缺失null/unknown；新增evidenceAuthorityVersion=1 | 摘要是派生结果不写回冒充事件事实；旧passed仅标自报；客户端不得凭字段存在授予权威 |
| health.capabilities | index health→api.health→page→inspector/logdrawer | 增hostChecks={supported:true,enabled:boolean,configVersion:1}、evidenceAuthorityVersion=1、leaseEpochVersion=1；缺失即不支持 | supported与enabled不同；UI握手不能替代Host开关/鉴权，API调用仍由preflight拒绝 |

受保护extra必须在普通boundExtra**之前预留**并在最终8KiB检查中验证完整性。当前boundExtra仅收有限键与标量，后加stamp或嵌套verification会被裁没。实现顺序固定为：从顶层未知字段和raw.extra中剥离保护键 → 对剩余用户extra按剩余键数/字节预算归一化 → 由受控context注入保护字段 → normalizeEvent最终字节校验 → 确认必需字段原样存留。不得依赖对象插入顺序；攻击者先塞16个键或同名键不能挤掉source/terminalScope。放不下整条拒绝，不能删除scope后“兼容写入”。internal legacy不自动贴host来源；external必须source/producer=external且authority=unverified。

新字段往返测试必须穿过“写入→读回→不相关meta patch→再读→GET→normalizeRun→mergeRunDetail”。flow需穿过保存队列和重新载入。check只读取节点own顶层属性；旧extras的存在性必须在collectExtras按known跳过之前捕获供惰性提示。单独验证2000字符command（含超过256字符与多字节）保存/回填/快照/精确digest/argv不变，2001字符报400且spawn零次；另有仅extras.check、顶层与extras冲突、无check三组fixture，锁住不自动迁移语义。schema仍用既有v:1，新增可选字段与能力版本区分语义，不提升基础EVENT_KINDS数量、不为检查增加新kind；check/form仍使用合法state(pass/fail/skipped/na)，unknown仅在派生摘要。

## 5. 资源与进程边界

process-output收到Buffer先按stdout+stderr原始字节计量，再解码/复制；累计计数不因ring淘汰减少。恰等上限合法，超一个字节即OUTPUT_LIMIT。events数、半行、finalText/structured/JSON膨胀与onEvent待提交队列共同受留存预算，tail有独立小上限。合法限内结果完整；不能默默淘汰正文后仍成功。executor拥有子进程和杀组计时器；host-check只持窄取消句柄，Engine只触发AbortSignal。

所有可见边界先脱敏后clip；完整记录或状态化敏感段解析解决跨chunk/跨行凭据。raw buffer不可挂在error/cause/onEvent对象中。可信结构化digest/id字段按受控schema序列化，脱敏针对command摘要、消息、输出、错误和报告内容；不能把合法sha256当长token抹掉导致核验链失效，也不能让未知JSON键值绕过脱敏。报告sha256绑定最终脱敏副本精确字节。

OUTPUT_LIMIT/timeout/stop/lease-lost均先固定原因，再TERM/KILL进程组，关闭管道、断回调、确认退出后唯一settle。清理失败保持terminating占位并公开故障，不能提前还配额遗留无限进程。POSIX测试验证孙进程；其它平台killScope=process并提示能力局限，stub/缺shell不产生权威成功。
