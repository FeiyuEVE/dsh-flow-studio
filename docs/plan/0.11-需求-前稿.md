# 0.11 需求分析：六条「可信」的裁决与验收

> 阶段：需求分析 · 目标版本 0.11「可信」 · 基线 `@feiyueve/dsh-flow-studio` 0.10.0（HEAD `345d3d6`，2026-11-07）· 仓库 `/testbed/workspace/dsh-flow-studio`
> 上游：[0.11 功能缺口评估](0.11-功能缺口评估.md)（下称「评估」）。本文的 file:line 以评估为准，评估标「待核」的条目本节点已逐条核对并改正。
> 本文回答：六条各自「现在到哪、0.11 做到什么算过、怎么写成会红的测试」，以及必须先裁决的冲突点。**不写实现方案**（实现归方案/开发阶段）。

## 0. 结论

- 六条全部保留，编号 **R1=E1、R2=S1、R3=S2、R4=S3、R5=P1、R6=E4**；每条给出「必须 / 可降级」「可判真假的验收标准」「红→绿双向验证设计」。
- **基线实测**（本机，命令见 §8）：`npm test` → EXIT 0，**23 个 `.test.mjs` / 855 组全绿**；`npm run build` → EXIT 0；`node scripts/verify-build.mjs` → EXIT 0（17 个 Host 模块、`lib/` 18 个 `.js`）；`git diff --stat -- docs/design` 为空。任务书写的「855 组」与实测一致。
- **三处需求范围修正（相对评估）**：
  1. **E4 不是空白**：0.10 已有 `provenance='model-claim'`、`verifyClaimRef`（path+sha256）、`selfCertified/selfOnly` 与「全自证 → warn」。真实缺口是三条：① 引擎自己转写的 `test-report.json` / `acceptance.json` / `summary.json` 没打 `producer` 标记，**别的节点引用它会被判成 peer（独立）**；② `check/form` 只要带 `executedAt` 就能 pass，`reportRef` 可缺（`src/runlog.js:1830-1841`），外部可刷绿；③ 没有 `claimed` 一等标签，`summarizeAcceptance` 与 run 终态仍显示「通过」。需求按这三条收窄，不许「重写整个证据层」。
  2. **S3 有一个评估没写的旁路**：外部 `POST /events` 可追加 `artifact/write` 并自带 `extra.producer='host'`（`src/runlog.js:1418` 只读 `event.extra.producer`），凭空造出宿主级证据。S3 修复必须同时**强制改写外部事件的 `producer`**，不能只过滤 verdict 类事件。
  3. **P1 的检查命令与 custom executor 同级**：都是「流程 JSON 里的任意 shell + 全权 token → 宿主 RCE」。必须复用同一道默认关闭的开关，不能因为「只是检查」就默认放行。
- **三个特别裁决**见 §5：检查配置用 `node.check`（命令 + 期望退出码 + 可选报告路径），在**节点收口后、`node/end` 前**由宿主执行，**失败不改节点 verdict、只把 quality 打成 fail**；并发默认 **全局 4 / 每工作区 2 / 队列 8 / 等待 15s**（env 见 §5.2）；E4 权威分级为 **host / peer（非引擎转写）/ claimed（self、转写、无 ref）**。

## 1. 范围与硬约束

**范围**：把「让 run 的结论可信、让资源可预期」的六条做到可验收；不碰 0.12 的交互/复用项（人工放行、开跑面板、restart 原子化、undo 等）。

**硬约束（违反即验收失败）**：

1. 不改 `docs/design/` 下任何文件（冻结）；新文档只写 `docs/plan/0.11-*.md`。事件契约的真相仍是 `docs/design/05-run-log.md`，**新字段只进 `extra`，不改 kind 与必填字段**。
2. 不 `git push`、不 `npm publish`、不重启任何服务。
3. 客户端一律自研 `h()` vdom，不用 JSX、不新增运行时依赖。
4. `npm test`（23 文件 / 855 组基线）+ `npm run build` + `node scripts/verify-build.mjs` 必须全绿；`lib/` 与 `src/` 逐字节一致由既有门禁保证。
5. 每条新增用例必须做**红→绿双向验证**：把修复改回旧行为，对应用例必须红；只加绿用例不算过。
6. 不新增 Host 模块（避免 `scripts/build.mjs` 清单、`test/build.test.mjs` 的「18 个 `.js`」断言连锁返工）：脱敏与宿主检查放进 `src/executor.js`，引擎侧只调用。

## 3. 用户场景

| 场景 | 触发 | 期望 | 当前实际 | 「可信」的判据 |
|---|---|---|---|---|
| S-A 长跑被接管 | 2 小时 run 到 90 分钟，进程休眠后又被另一个实例接手 | 旧实例立刻停，`run/end failed` 的 reason 含 `lease-lost` | 旧实例只 warn 继续写，与新实例事件交错 | reason 含 `lease-lost`，且旧实例不再产生任何新事件 |
| S-B 连点 / 洪泛 | 同工作区连点两次运行；或 5 人各起 3 个 run | 超限排队或 429 并说明等多久 | 全部起跑，worktree 互相覆盖 | 第 N+1 个有明确位次或 429，且能说清等多久 |
| S-C 输出爆炸 | codex/custom 吐 4GB，或回显继承的 `TOKEN` | 硬上限、超限杀进程组、返回 `OUTPUT_LIMIT`、日志只见 `[REDACTED]` | 内存无界增长，tail 原样进错误与导出 | 结果标 `OUTPUT_LIMIT`；落盘与响应无凭据原文 |
| S-D 真跑过吗 | 运营追问「这次测试真的跑过了吗」 | 没有宿主/独立报告的自报只能是 `claimed` | 自报计数 + 自写文件 sha256 对得上就算通过 | 结论能指出「谁执行的」：host / peer / claimed |
| S-E 外部事件伪造 | CI 用 `POST /events` 补结论，或被恶意调用 | 一律标「外部未验证」，不进 quality/终态 | 白名单放行，直接把结论刷绿 | POST 前后 quality/status 一个字不变 |
| S-F 检查失败但 agent 说 pass | 节点配了检查命令，宿主跑出退出码 1，agent 报 pass | 宿主失败压过自报 pass，质量不得为 pass | 宿主根本不会跑检查 | 质量结论为 fail，且能看到命令、退出码、耗时 |

## 4. 需求清单

> 每条给：必须 / 可降级、验收标准（A，全部可判真假）、红测设计、测试落点。`file:line` 是现状；验收不给「更稳」「更可信」这类词（黑名单见 §7）。

### R1（E1）续租失权必须停跑

- **必须**：
  1. 续租返回 `RunError.status===409`（含被接管、缺失、损坏——都意味着「本实例已无权写」）→ 立即记 `leaseLost`、停续租定时器、`active.controller.abort(LeaseLostError)`；此后**除收尾 `run/end` 外不再落任何事件**。
  2. `run/end` 必须是 `status:'failed'`，`reason` 以 `lease-lost:` 开头并带 409 的中文原因，`extra:{error:'LeaseLost', code:'LEASE_LOST'}`；不得落成 `aborted`/`done`（收尾分支要排在 `aborted` 判断之前）。
  3. 非 409（EIO/ENOSPC/超时等）仍只 warn 并继续跑；**不得因为 I/O 抖动误杀长跑**。
  4. 状态机循环与旧循环两处都改，共用同一段判定；漏一处由 A1.4 抓。
  5. `_append` 增加闸门：`leaseLost` 且非终态事件 → 拒绝写入（抛 `LeaseLostError` 或丢弃并计数），保证「不再写任何事件」可被断言。
  6. 可测性：`createEngine({ leaseRenewIntervalMs, renewLease })` 可注入（默认 30000 / `runstore.renewLease`），runtime 已透传未知 options（`src/runtime.js:706-710`）。
- **可降级（P2）**：fencing token、跨进程写入带租约校验（`appendEvents` 侧）、续租指数退避。
- **验收**：
  - A1.1 注入 `renewLease` 首次即 reject `RunError(409)`，interval 10ms：≤200ms 内收口；`run.json.status==='failed'`；`run/end.data.reason` 匹配 `/^lease-lost/`；`extra.code==='LEASE_LOST'`。
  - A1.2 收口后 1s 内 `seq` 不再增长，且 `run.jsonl` 最后一条是这条 `run/end`。
  - A1.3 注入「前两次 EIO、第三次成功」：run 继续到 `done`，日志有 warn，无 failed 收口（防过度 abort 的反向守护）。
  - A1.4 走 `_loopLegacy`（`resumePlan` 路径）重复 A1.1。
  - A1.5 409 后 200ms 内不得出现任何 `node/*` / `agent/*` 新事件（只允许终态 `run/end`）。
- **红测**：把 409 分支改回 `log('warn')` → A1.1/A1.2/A1.5 红（run 仍是 running/done、seq 继续涨）；把「所有错误都 abort」写进实现 → A1.3 红。
- **落点**：`test/engine.test.mjs` 新组（复用 `createEngine` + `runsRoot` 夹具；注入 `leaseRenewIntervalMs: 10`）。

### R2（S1）全局 + 每工作区并发配额与排队

- **计量与路径**：单位为「runtime 里活跃的 Engine 实例」（一 run 一实例）。在 `runtime.start()` 内、`runs.set` 之前 acquire；`settleInstance`、`start` 抛错、`dispose()` 三处 release（幂等）。HTTP `POST /runs/<id>/start`（`src/index.js:1918`）与 `flow_start`（`src/tools.js:1701`）、`restart`（`src/runtime.js:1424`）都走这一个入口，无需分别改。
- **必须**：
  1. 全局配额 + 每工作区配额；工作区键优先 `startOptions.workspace`，其次 `run.json.workspace.realpath/path`，都没有（stub）归 `'<none>'`。
  2. 超限：全局可排队（FIFO，队列上限与等待超时见 §5.2）；每工作区超限**立即 429、不排队**（防单工作区占满队列把全局饿死）。
  3. 429 契约：HTTP **429** + `Retry-After`（秒，5–60）+ body `{ok:false, error:<中文>、code:'RUN_CONCURRENCY_LIMIT', retryAfterMs, limit:{scope:'global'|'workspace', active, max, workspaceActive, workspaceMax}}`；文案必须含「当前 N/M 个 run 在运行」与「怎么调」（env 名）。
  4. 同一 runId 仍 **409**，且判定在配额之前（先有语义不变的双跑保护，再谈资源）。
  5. 排队中的 run 不写 `run/start`、不建 worktree；拿到槽位后正常启动，`run/start.extra.queueWaitMs` 记等待毫秒。
  6. 排队中可被 `stop` 取消：`stop(runId)` 命中队列 → 移除等待者，start 以 409「该 run 在排队中被停止」结束（不得等 15s 后照样起跑）。
  7. env：`FLOW_STUDIO_MAX_CONCURRENT_RUNS`、`FLOW_STUDIO_MAX_CONCURRENT_RUNS_PER_WORKSPACE`、`FLOW_STUDIO_RUN_QUEUE_MAX`、`FLOW_STUDIO_RUN_QUEUE_TIMEOUT_MS`；默认与 0 的语义见 §5.2。
- **可降级（P2）**：精确 ETA、跨进程/多 Host 配额、持久队列、按令牌配额。
- **验收**：
  - A2.1 注入 `maxConcurrentRuns: 2, runQueueMax: 0`：并发 3 个 start，前两个成功，第三个 ≤200ms 内得到 `EngineError.status===429`、`code==='RUN_CONCURRENCY_LIMIT'`、`limit.scope==='global'`、`retryAfterMs>0`；该 run 的 `run.json.status==='pending'` 且无 `run/start`。
  - A2.2 释放（引擎收口或 stop）后 3s 内重试第三个 → 202（槽位真的释放，且不泄漏）。
  - A2.3 两个不同工作区各 1 个、全局 2 已满：第三个同工作区 → `scope==='workspace'`；第三个换工作区 → `scope==='global'`（顺序断言）。
  - A2.4 排队：`runQueueMax:2, runQueueTimeoutMs:1000`（全局 1）：第二个 start 挂起，释放第一个后其返回 202 且 `run/start.extra.queueWaitMs>=0`；第四个（队列满）立即 429；把超时调 50ms 的用例 → 50ms 后 429。
  - A2.5 同 runId 并发 start 仍 409（不是 429），文案不变。
  - A2.6 HTTP 层：`POST /runs/<id>/start` 超限 → 状态 429、`Retry-After` 头存在、body 字段齐全。
  - A2.7 排队中 `stop` → start 以 409 结束，run 保持 pending，`run/start` 不出现。
- **红测**：删掉 acquire/limit → A2.1 第三个直接 202 并 running（红）；只判全局不判工作区 → A2.3 红；429 写成 500 / 不带 `retryAfterMs` → A2.1/A2.6 红；release 写在 `settleInstance` 之外 → A2.2 红（槽位泄漏）。
- **落点**：`test/runtime.test.mjs` 新组（`createEngine` 桩已存在，`src/runtime.js:656`）；HTTP 层落 `test/host.test.mjs`（注入假 runtime）。

### R3（S2）外部 executor 输出硬上限与脱敏

- **必须**：
  1. 硬上限：输出总字节默认 **8 MiB**、事件数默认 **5000**（模块常量 + 可注入 options + 部署 env `FLOW_STUDIO_EXECUTOR_MAX_OUTPUT_BYTES` / `FLOW_STUDIO_EXECUTOR_MAX_EVENTS`）。
  2. 流式 ring buffer：`events` 只保留尾部 N 条、`stdoutAll` 只保留尾部 N 字节；`stderrTail` 沿用 2000。
  3. 超限**立即** `interrupt('OUTPUT_LIMIT')` → `killChild()`（已有进程组优先逻辑）→ `finish({ok:false, reason:'OUTPUT_LIMIT', truncated:true, ...})`；不得走 `exit` 分支、不得静默截断后 `ok:true`（custom 的长答案是结果本体）。
  4. 脱敏：`redactArguments` 实现移到 `src/executor.js`，`src/engine.js` 原样 re-export（`test/runlog.test.mjs:153` 与公共 API 不能断）；对 `stderr/log` 事件的文本、`result.tail`、错误 message 在**落盘/返回前**脱敏。
  5. JSONL 解析输入**不脱敏**（脱敏可能破坏 JSON），只脱敏输出面。
  6. 引擎：`result.reason==='OUTPUT_LIMIT'` → 抛 `OutputLimitError`（`name/code='OUTPUT_LIMIT'`），节点失败 reason 含 `OUTPUT_LIMIT`，`node/end.data.outputLimit=true`；不得混成「非 0 退出（未知）」。
- **可降级（P2）**：头尾双 ring（保留前 N 字节）、按事件类型分级（诊断日志单独上限）、把完整输出落临时文件。
- **验收**：
  - A3.1 注入 spawn 桩持续 emit 总计 10MiB：`result.ok===false`、`reason==='OUTPUT_LIMIT'`、`events.length<=5000`、保留字节 `<=8MiB`、`child.kill` 被调用（桩记录）且 `killScope` 有值。
  - A3.2 事件数 6000 条（小上限注入 100）：`reason==='OUTPUT_LIMIT'`，`events.length<=100`。
  - A3.3 stderr 含 `sk-abcdef1234` 与 `Authorization: Bearer abc.def.ghi`：`result.tail` 与落盘 `run.jsonl` 中匹配 `/sk-[A-Za-z0-9]{4,}/`、`/Bearer\s+[A-Za-z0-9]/` 的行数为 0，且出现 `[REDACTED]`。
  - A3.4 真进程 `sh -c 'yes'`：≤5s 返回 `OUTPUT_LIMIT`；RSS 增量 < 50MiB（此条标记非门禁 / 可 flaky，只做观测，不当红绿判据）。
  - A3.5 正常 1MiB 输出：`ok:true` 且 `text` 完整（回归，防误杀）。
- **红测**：把上限改回无界累积 → A3.1/A3.2 红（不再杀、`ok` 变 true）；去掉脱敏 → A3.3 红。
- **落点**：`test/executor.test.mjs` 新组（`fakeSpawn` 已有，`src/executor.js:562` 可注入 `spawn/onEvent`）。

### R4（S3）外部事件一律「外部未验证」

- **必须**：
  1. `POST /runs/<id>/events`（`src/index.js:1723-1741`）服务端强制改写：`extra.source='external'`、`extra.authority='unverified'`、`extra.producer='external'`（**覆盖**客户端自带的同名值，尤其是 `producer`）；客户端不能通过任何字段把自己标成 host/内部。
  2. 聚合层（`src/runlog.js`）先过滤再计算：`computeQuality` / `computeAcceptance` / `computeTests` / `checkEvidence` / `computeFindings` / `computeConflicts` / `computeStaleFails` / `summarizeAcceptance` / `collectArtifactOwners` / `collectArtifactIndex` 一律忽略 `extra.source==='external'` 的事件；事件时间线与导出保留它们并标注。
  3. summary/export 增加外部事件计数与「外部未验证（N 条，未计入结论）」段落；客户端事件行显示「外部未验证」徽标。
  4. run 终态不由外部事件推动（生命周期白名单现状已保证，作为回归锁定）。
- **可降级（P2）**：签名/allowlist 的可信外部源开关（`FLOW_STUDIO_TRUST_EXTERNAL_EVENTS=1`）、按调用方身份分级。
- **验收**：

- **必须**：

## 5. 三个特别裁决

### 5.1 P1 检查命令：字段、时机、失败影响

- **字段**：`node.check = {command, expectExitCode=0, reportPath?, timeoutMs?}`。不放 `extras`——`extras` 是无 schema 的未知字段兜底（`src/model.js:288-292`），不能承载要门禁的安全配置。不支持 `{prompt}` 之类占位符（命令是静态配置，避免把不可信文本拼进 shell）。
- **来源**：只能来自流程 JSON（画布检查器 / 保存接口，需全权 token）；不接受 run 输入、消息、上游产物注入。配置不合法允许保存（与 executor 同口径），但 **start 400**，不静默忽略。
- **时机**：**节点收口后、`node/end` 前**。理由：此时 `node/end` 尚未写，质量证据（`check/form`）与产物（`verification.json`）都在同一 attempt 内；且严格保证「下一个节点开始前执行完」。节点执行失败则不执行（记 skipped）。
- **失败影响**：**只压 quality，不改节点 verdict**。理由：`node/end` 是「agent 干得怎么样」，`quality` 是「这次交付可不可信」；把检查失败改判成节点失败会破坏打回语义、且让 agent 的自报与宿主结论无法对照。质量 fail 已满足「自报 pass 不得顶掉 host 失败」。若后续要「检查失败即阻断/打回」，归 0.12 与人工放行一起设计。
- **平台**：仅 POSIX `sh`；Windows/无 shell → `skipped` + reason，不算 pass。

### 5.2 并发配额的默认值与 env

| env | 默认 | 语义 |
|---|---|---|
| `FLOW_STUDIO_MAX_CONCURRENT_RUNS` | `4` | 全局活跃 run 上限；`0` = 不限（启动 warn）；非法/负数 → 用默认 + warn |
| `FLOW_STUDIO_MAX_CONCURRENT_RUNS_PER_WORKSPACE` | `2` | 每工作区上限；`0` = 跟随全局；同样只认非负整数 |
| `FLOW_STUDIO_RUN_QUEUE_MAX` | `8` | 全局满时最多排队的 start 数；`0` = 不排队、直接 429 |
| `FLOW_STUDIO_RUN_QUEUE_TIMEOUT_MS` | `15000` | 排队最长等待；超时 429；范围 0–600000 |

- 为什么是 4/2：一个 run 可再起 1 主管 + N 成员会话与 worktree；默认 2h 墙钟意味着槽位会被长时间占用。4 全局能容纳一条流水线 + 一次重跑；每工作区 2 防止同一目录两个 worktree 互踩。现有用例最大并发是 2（`test/runtime.test.mjs:231/304/426/475/1277`），4/2 不会把既有套件打成 429。
- 429 的 `retryAfterMs`：取 5–60s 的保守值（默认 30s），不承诺精确 ETA（精确 ETA 列 P2）；`Retry-After` 头取同一值向上取整秒。
- 排队只对全局生效；每工作区超限立即 429，避免单工作区把队列占满。

### 5.3 E4 权威分级

| 级别 | 判定条件 | 是否 authoritative |
|---|---|---|
| host | `artifact/write.extra.producer==='host'`（宿主检查/宿主落盘） | 是 |
| peer | 其它节点写的产物，且该 `artifact/write` 没有 `producer==='engine'` | 是（保持 0.10 的跨节点复核语义） |
| self | 本节点写的产物 | 否（claimed） |
| transcript | 引擎根据模型结构化输出转写的文件（`producer==='engine'`） | 否（claimed，**新增**） |
| none | 没有 ref / ref 不可解析 | 否（claimed，**新增**） |

- 不把「peer 一律降级」写进 0.11：0.10 的跨节点复核是真实在用的路径，一律降级会误杀（A6.5 守护）；只把「引擎转写」和「无 ref」这两类假独立证据降级。
- 签名报告：0.11 只预留 `reportRef` 旁的 `signature` 字段与「不采信」注释，不实现验签。
