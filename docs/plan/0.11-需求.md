## 4. R1（E1，P0）：失权续租必须停跑

现状证据：[评估第 20 行](0.11-功能缺口评估.md#L20) 的 [状态机循环](../../src/engine.js#L5114)、[旧循环](../../src/engine.js#L4719) 均只 warn；[renewLease](../../src/runstore.js#L1924) 对缺失、损坏、owner 不符和接管均 409。此处将这些明确无权续租的 409 全部视作 lease-lost；非 409 I/O 不混入失权分支。

必须：在续租 409 被处理的同一异步回调内触发整轮 abort、关闭续租入口、封锁旧实例新业务写入；当前节点、外部子进程和迟到会话回调都服从封口。唯一允许的后续事件是一次 `run/end failed`，reason 含 `lease-lost`、可机器识别 `LEASE_LOST`。不得写 done/aborted。终态异常重试不得制造重复 end；不得释放新 owner 的租约。失权时间点前已经提交的事件不追溯删除。

可降级：指数退避、普遍跨进程 fencing 优化；**失权后零业务写入和接管者状态不被迟到旧写破坏不能降级**。若现有写入协议不能同时满足，方案必须增加条件写入或接管协调，不能只补一行 abort。

验收与测试设计（均未执行）：

- A1.1 用可注入续租/时钟在状态机执行悬挂节点时抛 409；同 tick 观察 signal.aborted，虚拟时钟推进 200ms 后恰有一次 failed end，reason/code 正确。迟到节点完成、成员、tool、artifact 回调全部触发后，旧实例 append 记录中除 end 外零新增；再推进 1s seq 不变。
- A1.2 对 resumePlan/legacy 重复 A1.1，两个循环都须覆盖。记录实际命中路径，不能仅更换用例名称。
- A1.3 前两次 EIO、第三次成功：不中止，仍能正常 done，warn 两次；不得把所有异常都当 409。
- A1.4 模拟接管者已写事件，旧实例续租 409；其清理不得删接管租约或写迟到 node/end。记录双方 owner 与失权终态协调结果，只有一条失权失败事件，事件顺序可复核。
- 红→绿：原代码只 warn，A1.1/A1.2 的取消和 append 断言失败；修复后绿；仅恢复 warn 必红。反向“所有错误 abort”使 A1.3 红。测试进入现有 engine/engine-machine/engine-restart 夹具，取证不能只检查最终状态。

## 5. R2（S1，P0）：全局与工作区并发配额、有限排队

现状证据：[评估第 29 行](0.11-功能缺口评估.md#L29)，[engine 注释](../../src/engine.js#L15)、[启动路径](../../src/index.js#L2159)；[runtime.start](../../src/runtime.js#L1225) 只有 runId 重复 409，然后创建实例，没有容量闸门。

必须：宿主进程级全局额度覆盖所有 runtime 创建入口；每个 realpath 工作区单独计量，不能用 worktree 子目录绕过来源工作区额度。计数包含已占位启动中与运行中，排队不计活跃。HTTP、flow_start、restart、消息触发启动共用同一准入；异步路径先原子占位后创建资源。同 runId 已启动或在队列中仍 409，不重复占槽。

| 新增配置（0.11 需求值） | 默认与合法范围 |
|---|---|
| `FLOW_STUDIO_MAX_CONCURRENT_RUNS` | 4，正整数；0/负数/非整数回默认并 warn |
| `FLOW_STUDIO_MAX_CONCURRENT_RUNS_PER_WORKSPACE` | 2，正整数；0/非法回默认并 warn；大于全局时有效值钳到全局并提示 |
| `FLOW_STUDIO_RUN_QUEUE_MAX` | 8，非负整数；0 禁止排队 |
| `FLOW_STUDIO_RUN_QUEUE_TIMEOUT_MS` | 15000，正整数且不超过 600000；非法回默认并 warn |

这些数字是需求默认策略，不声称来自性能测量。全局满且该工作区未满可进入进程级有限 FIFO 队列；每工作区满直接 429，防单工作区占满等待位。出队必须重新核对两级额度。队满、超时、工作区满均返回 HTTP 429、`RUN_CONCURRENCY_LIMIT`、`Retry-After` 与一致的 retryAfterMs（默认建议 30000ms）、scope/active/max、可读容量和 env 调整说明；不伪造精确 ETA。等待期间 start 仍未成功，返回或查询应可观测 queued、入队时间和位置；不能以 pending 偷偷等同已启动。HTTP 最长等待 15s 后必须明确失败；取消后不得后台启动。

必须在正常完成、failed、stop、启动抛错、dispose 各路径幂等释放。排队 stop/dispose 取消 start，返回可识别取消原因并保留 pending，不写 run/start。restart 准入失败不能留下永久阻断旧 run 的孤儿 pending 子 run，必须可重试/可继续启动。

可降级：跨进程集群总配额、持久化队列、公平调度优化、精确 ETA；进程重启丢队列应有明确说明，不伪装恢复。

- A2.1 配全局 2/工作区 2/queue 0，三个不同 run（分配不同工作区）同时 start：仅前两个创建 Engine，第三个 429，零 worktree/会话/run/start；释放一个后第三个成功。
- A2.2 全局 4、工作区 1，同目录及 symlink 别名启动两个 run：第二个 workspace 429；另一工作区可启动。两个 createRuntime 实例也共享总上限。
- A2.3 全局 1、queue 2：第二/第三个明确 queued，第四个 429；释放后 FIFO，任意时刻 active≤1；排队期间资源创建计数为零。超时、stop、dispose 后再释放槽，已取消请求均不启动。
- A2.4 并发相同 runId 仅一份启动/排队，另一份 409；启动失败、执行失败、stop、dispose 后分别验证额度归还且不重复释放；restart 429 后重试能成功。
- A2.5 真 HTTP 路由断言 429、Retry-After/body；模型工具输出保留相同 code 与可读原因，不得变 500。
- 红→绿：恢复无限准入 A2.1 红；去工作区规范化 A2.2 红；漏 release/取消 A2.3/A2.4 红。落点 runtime/host/tools/engine-restart 既有测试。每个新增用例对应的 mutation 单独记录。

## 6. R3（S2，P0）：外部输出有界与脱敏

现状证据：[评估第 30 行](0.11-功能缺口评估.md#L30)；精确纠偏为 [executor 第 584 行](../../src/executor.js#L584) 是 events 数组，585 是 stdoutAll；609 无界 push，881 无界拼接，882 的半行缓冲同样危险，910 直接回 tail。stderr 已在 [第 887 行](../../src/executor.js#L887) 做尾部裁剪，不能说 stderrTail 本身无界。[脱敏函数](../../src/engine.js#L415) 已有 Bearer/sk-/键值规则，[错误拼接](../../src/engine.js#L6060) 会继续把日志尾部带进节点错误。

必须：stdout+stderr 累计接收字节（UTF-8 原始字节，不是字符数）默认 8 MiB、总规范化事件数默认 5000；新增 `FLOW_STUDIO_EXECUTOR_MAX_OUTPUT_BYTES` / `FLOW_STUDIO_EXECUTOR_MAX_EVENTS` 均为正整数，非法/0 回默认并 warn，可用构造选项注入小值测试。累计输入超额不能因 ring 淘汰重置计数；最多处理限额内数据，单个超大 chunk 也不能先全量复制。所有滞留输出（含半行、finalText、诊断、事件队列）有明确字节和条数上界，不能只对返回 events.slice 限制。

越界立即进入唯一 OUTPUT_LIMIT 失败通道，终止进程组、阻止后续 onEvent 和迟到 close/error 改写成功，返回 code/reason=OUTPUT_LIMIT 与 truncated=true，节点/运行错误保留该 code。POSIX 须确认孙进程也终止；不支持进程组的环境明确报告降级，不声称杀组成功。脱敏必须在所有日志、错误、onEvent、响应及可导出产物可见前执行；解析器可保留未脱敏的有界输入，但不得将它落盘。跨 chunk/行 token 不能因切片绕过脱敏；复用 redactArguments 或等价共享规则，避免循环 import。

可降级：头尾双缓冲、原始大输出另存、诊断分类配额；RSS 有界、杀组和脱敏不可降级。

- A3.1 桩分别输出大量短行、单个超长无换行 chunk、只 stderr、UTF-8 多字节和超量事件；小阈值注入。每种都断言累计限额触发 OUTPUT_LIMIT、保留字节/事件数不超过配置、有界半行、只 settle 一次、迟到事件不继续落盘。
- A3.2 隔离 Node runner（固定 heap 上限 96 MiB）启动会持续写且派生孙进程的真实脚本，注入 256 KiB 限额，采样 runner RSS 峰值相对稳定基线增量≤128 MiB，5s 内 OUTPUT_LIMIT，父子进程均退出；超时/OOM也判 fail。重复 20 次，末 5 次与首 5 次中位 RSS 差≤32 MiB。记录平台、采样值和 kill 证据，此项是 POSIX CI 门禁；非 POSIX 不可用结果标 skip，不能全平台宣称通过。
- A3.3 stderr/stdout/JSON log 含唯一 canary token、Bearer、sk-key、token=值，并把值切在相邻 chunk 边界：响应、onEvent、run.jsonl、报告、导出零原值命中且有 `[REDACTED]`；不对“Bearer”字样本身判泄密。

## 8. R5（P1，P0）：宿主独立检查

现状证据：[评估第 39 行](0.11-功能缺口评估.md#L39) 与 [路线图](../guide/overview.md#L58)；[NODE_KNOWN_FIELDS](../../src/model.js#L288) 无 check；[engine 产物注释](../../src/engine.js#L6587) 明确当前是模型转写，未生成独立 host 证据。

特别裁决：检查命令只来自已保存流程节点的显式 `node.check={command,expectExitCode,reportPath?,timeoutMs?}`。command 必填非空≤2000 字符；expectExitCode 默认 0、整数 0–255；timeoutMs 默认 600000、范围 1000–1800000；reportPath 是相对于实际节点 cwd 的安全相对普通文件路径，禁止绝对路径、穿越和软链逃逸。不允许模型消息、run input 或上游产物覆盖命令，也不将 prompt 插入静态命令。检查器用既有 h() 表单保存/回填；非法配置启动前 400，不静默丢为“未配置”。

必须：独立开关 `FLOW_STUDIO_ALLOW_HOST_CHECKS=1` 默认关；节点配 check 而关闭时启动前返回 400/HOST_CHECKS_DISABLED，不假装检查过。与 custom executor 使用同等级全权操作控制，不能经只读令牌配置/执行。命令在节点业务收口、结构化产物已写之后执行，在该 attempt 的 node/end 以及下一节点 start/打回调度之前完成。配置快照固定到本次 run；相同 attempt 因订阅重复回调不能重复执行。

宿主在节点实际 cwd（worktree 生效则使用该目录）真正启动检查进程；记录命令摘要、cwd、实际/期望退出码、开始结束时间、超时/取消原因、输出限额和报告摘要。采用 R3 的有界缓冲、脱敏和进程组终止；检查默认输出上限 1 MiB，事件上限沿用 R3。不要无依据删除所有 DSH/FLOW_STUDIO 环境变量使项目测试无法工作；只剔除认证凭据和明确敏感变量，并测试 PATH 等必要环境仍可用，不宣称沙箱隔离任意 shell。

结果由宿主代码写受保护 `producer=host` 的 verification 产物及检查事件；agent 提供同名文件或 producer 字段不能复用为该结果。无 reportPath 时宿主执行记录本身就是可验证报告；有 reportPath 时要求本次执行生成/更新、内容未变更且有界读取复制，旧文件不能冒充新报告。报告丢失、过大导致无法完整验证、退出码不符、spawn 失败、超时均为 host fail/unknown（不能 pass），具体失败原因可区分。判 pass 必须退出码等于期望值且报告条件满足。

**失败对 verdict 的裁决**：保留 agent 原 verdict 和原 next/reject 行为；host fail 优先把 quality 判 fail，agent 的任何 claimed pass 和后续其它规则 pass 都不能覆盖。同一检查的新有效 attempt 重新执行成功后，才能按当前 attempt 解除旧 fail；不能拿旧 host pass 给新 attempt 复用。执行流程可以 done 而 quality fail，客户端和导出必须并排显示“执行完成 / 宿主检查失败”。本期不新增“检查失败自动打回”。节点本身失败、run stop 或失权时不再启动新 check；已配置检查写 skipped/取消原因，lease-lost 后不得违反 R1 再追加检查事件。

可降级：JUnit/业务报告语义解析、自动打回、并行/重试、多 shell 适配、签名外部报告；无 shell/无 cwd/stub 显示 skipped/unknown，不能替代真执行通过。

- A5.1 流程节点配置 `exit 1`（期望 0），agent 报 pass/29 全过；真实子进程记录退出 1，host report/check 为 fail，quality fail，原 agent verdict 保留。捕获顺序：结构化产物→宿主执行→host 结果→node/end→后继 start；只检查“出现 check 事件”不足以证明执行。

- A5.3 report 缺失、旧文件未更新、越界/软链、超过报告限额、超时、spawn 失败、输出爆炸、token 回显分别不得假 pass，迟到 agent pass 不覆盖 host fail。正常相对路径报告完整复制且来源/attempt 可核对。
- A5.4 配置开关、command 空、expectExitCode/timeout 越界、只读令牌各在启动前拒绝且 spawn 0 次；UI 保存重载配置一致。节点先失败则 skipped 有原因，stop/失权不再起检查。
