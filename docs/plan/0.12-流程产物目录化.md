# 0.12 流程产物目录化：把「一份大 JSON」拆成「一个目录」

> 阶段：需求 + 结构（0.12 第一批）· 基线 0.11.2（HEAD `e0f5e08`，2026-11-08）
> 本文回答：为什么现在这份产物是错的、改成什么形状、怎么判它改对了、存量怎么办。

## 1. 问题：让模型一次手写整份大 JSON

实测数字（2026-11-08，本机）：

| 对象 | 实测 |
|---|---|
| 元流程自身 flow JSON（9 节点 / 13 边） | **44,947 B**，其中 `task` 正文合计 **13,633 字** |
| 设计 run 节点⑦产出的 `07-落地规格.md` | **63,568 B**（单个节点） |
| 同目录 `07-members/` 两份分册 | 49,228 B + 42,120 B |
| 同一次 run 实际产出的 `flow-*.json` | **0 个**（要求了，没产出来） |

三个具体失效模式，不是理论：

1. **评审过的不是交付的那份。** ⑤ 多视角评审、⑥ 抗打演练审的都是 Markdown；⑦ 再用同一个模型把 1.3 万字 `task` 重新编码进 JSON。无机械校验的重述必然漂移：id 改名、措辞被压缩、成员被合并。
2. **错误暴露在最贵的位置。** 结构校验（单出边 / 打回只回上游 / 无出向边的节点必须写「不得 reject」/ ≤12 节点 / team 2–6 / model+provider 真组合）只在**导入时**跑。跑了两小时、`maxRounds` 可能已经用尽，最后一个逗号或一条漏写的打回边就让整条 run 的交付物作废。
3. **不可 diff、不可局部重试。** 4.5 万字节单文件，人审不了，`git diff` 也读不出重点；改一个节点要整份重来。

要分开两件事：**产物是结构化数据**是对的（导入、校验、执行都要结构）；**让模型一次手写整份大结构**是错的。

## 2. 决策：目录化，而非 Markdown DSL

两条候选：

- **A. 自定义 Markdown 方言**（front-matter + 标题层级 + 表格表达节点与边），模型只写 Markdown，宿主解析成 JSON。
- **B. 目录化 + JSON 侧车**：结构留在小 JSON 文件里，只有 `task` 正文是 Markdown。

**选 B。** 理由：

1. **不引入第二套方言。** 本仓零运行时依赖（`dependencies: {}`），YAML 都不装；自写 Markdown 方言意味着一个新的解析器 + 一套新的错误语义，而它解析出来的东西还要再过一遍 `normalizeFlow` / `validateFlow`。两套判据必然漂移。
2. **结构性错误的归口只有一个。** B 的编译产物直接进既有 `validateFlow`，校验规则永远只有一份。
3. **文本化的实质目标已经达到**：一份流程 = 一个目录，最大的那块（`task` 正文）是独立 Markdown，每个节点单独一个文件，可 diff、可局部重写、可单独评审。
4. **解析风险最低**：JSON 解析是标准库，不需要为「引号里带冒号的 role」这类边界写解析器。

代价：读者看到的是「一堆小文件」而不是「一份纯文本」。接受。

## 3. 契约

### 3.1 布局

```
<dir>/flow.json                 # { schemaVersion, name, description, nodeOrder: [id...], edges: [...] }
<dir>/nodes/<id>.json           # 该节点除 task 外的全部字段
<dir>/nodes/<id>.task.md        # 该节点的 task 正文（Markdown）
```

- `relPath` 一律 `/` 分隔；`nodeOrder` 决定节点顺序（不靠文件名排序碰运气）。
- `nodes/<id>.json` **不得**含 `task` —— 两个真相源是 `task-duplicated`。
- 布局之外的任何文件 → `unknown-file`，不静默忽略。

### 3.2 模块与 API（`src/flowdir.js`）

```js
export const FLOWDIR_MANIFEST = 'flow.json'
export const FLOWDIR_NODES_DIR = 'nodes'
export const FLOWDIR_TASK_SUFFIX = '.task.md'
export const FLOWDIR_FILE_MAX_BYTES = 65536

export function decompileFlow(flow) -> { files: Map<string,string> }
export function compileFlowFiles(files) -> { flow, errors }
export async function readFlowDir(dir) -> { files, errors }
export async function writeFlowDir(dir, flow) -> { dir, files: string[], bytes }
```

约束：

- 两个纯函数都**不改输入**；同样输入两次调用**逐字节相同**（键顺序固定）。
- `compileFlowFiles` 组装后**必须**走 `normalizeFlow` + `validateFlow`（`src/model.js`），不另写结构校验。
- `validateFlow` 的 `errors[]` 带 `nodeId` / `edgeId`，据此映射回 `nodes/<id>.json` 或 `flow.json`。
- `readFlowDir` 拒绝符号链接逃逸（`realpath` 必须在目标目录内），单文件上限 64 KiB。
- `writeFlowDir` 先写同级临时目录再 `rename` 原子替换；目录 `0700`、文件 `0600`（与 `src/runstore.js` 一致）；目标已存在且非空且不是本模块产物时拒绝覆盖。

### 3.3 错误码

| code | 触发 |
|---|---|
| `missing-manifest` | 没有 `flow.json` |
| `bad-manifest-json` / `bad-node-json` | 不是合法 JSON |
| `missing-node` | `nodeOrder` 列了但文件不存在 |
| `unlisted-node` | 有节点文件但 `nodeOrder` 没列 |
| `missing-task` | 缺 `nodes/<id>.task.md` |
| `task-duplicated` | 节点 `.json` 里出现 `task` |
| `unknown-file` | 布局之外的文件 |
| `unsafe-path` | 路径穿越 / symlink 越界 / 绝对路径 |
| `invalid-flow` | `validateFlow` 判出的结构错误（映射回文件） |

每条错误带 `{ code, path, field?, message }`，`message` 中文并说清怎么改。

## 4. 验收（硬门禁）

1. **round-trip 深等**：`defaultFlow()` 与一个含 team / skills / maxRounds / check / 中文 task 的流程，`compile(decompile(flow))` 与原 flow `deepEqual`。
2. **逐字节确定性**：同一 flow 两次反编译，每个文件内容完全相等。
3. **不 mutate**：往返前后输入 flow 深比较不变。
4. **错误表 10 类各一条**，断言 `code` 与 `path` 都对。
5. **路径安全**：`..` / 绝对路径 / symlink 越界都拒。
6. **IO 往返**：`writeFlowDir` → `readFlowDir` → `compileFlowFiles` 深等；目录权限 `0700`。
7. **全量门禁**：`npm run build` / `node scripts/verify-build.mjs` / `npm test` 三者 EXIT 0。

## 5. 兼容性（存量一个字节不动）

- 现有的 `POST /flows` / `PUT /flows/<id>`（整份 JSON）**语义与校验不变**，目录化是**附加路径**。
- 存量 `~/.dsh/flow-studio/flows/*.json` 不迁移、不改写；需要时用 `export-dir` 导出一份目录，改完再 `import-dir` 生成**新 id**。
- 不做自动双向同步：目录是**编辑期真源**，JSON 是**运行期真源**，谁写谁负责，靠「导入生成新 id」避免两个真相源打架。

## 6. 明确不做

- **不拿 git hook 驱动 run 生命周期。** run 事件有自己的 JSONL 契约；hook 是同步阻塞、且在没有仓库 / `custom` executor 的场景直接失效。git 只用于两件事：产物仓库、设计期门禁。
- 不做 Markdown DSL（见 §2）。
- 不改 `docs/design/` 冻结分册。

## 7. 后续（0.12 第二批，Git 化）

1. 设计 run 默认开 worktree（引擎已支持 `startOptions.worktree`，当前设计 run 都是 `disabled-by-initiator`）。
2. `pre-commit` 跑同一个 `flow_compile` → 结构炸弹在**提交时**被拦住，而不是导入时。
3. `post-merge` / tag → 导入 `~/.dsh/flow-studio/flows/` 生成流程。
